# 本系列单篇契约（v2）

> validator 子 agent 的判定依据。本契约**以 `00-生成提示词.md` 为准**，
> 不采用 `tutorial-series-gen` skill 的通用 6 节契约（那套要求每篇 ≥3 个可运行练习 +
> 强制术语表 + 「全文完」页脚，与本系列「动手实践按需、纯理论篇不配代码」冲突）。

## 硬性结构

| 位置 | 要求 |
|---|---|
| H1 | `# 第 N 篇：{标题}`，紧跟一行 `> **知识地图【{分支}】· Part {P}**` 引言块（可再补一两句本篇定位） |
| 篇头 | `## 本篇要回答的问题` + 3-5 条编号问题（来自 `00-生成提示词.md` 该篇知识点清单，一条不漏） |
| 正文 | `## 1｜{小标题}`、`## 2｜…` 分节（`｜` 全角分隔）；子节 `### 1.1`、`### 1.2` |
| 动手实践 | `## 动手实践：{名}`，**按需**——仅「不亲手做就学不会 / 做了能验证某个设计决策」时加；纯概念篇（第 2、21 篇）改为不配代码的「动脑练习」 |
| 结尾 | `## 本篇结论`（≤3 行，不写标语） |
| 文末 | `## 参考资料`（≥3 条：官方文档 / 规范编号 / 论文，真实链接，禁止编造） |

## 内容规范（来自 `00-生成提示词.md` 写作规范）

1. **先概念后代码**：每个新名词先一句话大白话 + ASCII 图，再给准确定义和官方出处。
2. **每步可运行**：完整文件 + 依赖安装命令 + 运行命令 + 预期输出；不给「只贴关键片段」。
3. **对比优先**：凡有多种方案，给场景化对比表 + 选型建议 + 「什么时候不选它」。
4. **设计要有「为什么」**：从「解决什么问题 / 不解决会出什么事故」讲起。
5. **脚手架 ≤10%**：目录树、术语速查表、分隔线、重复小结等装饰性内容占比不超 10%。
   不强制术语表（提示词未要求）；若确有价值可加，但不为凑数。
6. **准确性硬要求**：版本号 / 协议行为 / API 签名 / star 数 / 规范 tag 必须先 WebSearch
   官方源确认再写；拿不准一律写 `<以官方 docs 为准>`；**严禁编造 URL / 版本 / 参数**。
7. **代码真实性**：未经实测的代码必须在注释里标 `<未实测，以官方文档为准>`；
   禁止把「想当然」写得像跑过一样。
8. **国内可跑**：模型 API 给国产替代（DeepSeek / 通义 / 智谱，OpenAI 兼容），
   安装给国内源（清华 / 阿里 PyPI），不依赖需科学上网的服务。
9. **不涉敏感**：示例用户 / 角色用通用名（张三 / 管理员），不出现公司名、真实域名、真实密钥。
10. **知识不重复**：每篇只讲自己的主题，引用前序用链接；关键概念（agent loop、PMTA）
    复用可一句话回顾。
11. **Part 内收口**：Part 最后一篇复验里程碑吸收本 Part 增量后仍可跑通，末尾给
    「下一 Part 会暴露什么问题」一句预告。

## 交稿前自检四问（不满足不许交）

1. 该篇清单里每个问题都有实质内容了吗？
2. 所有带引用的论断都有出处了吗？
3. 若本篇含动手实践：真能跑通吗？（含依赖安装、运行命令、预期输出）
4. 有没有任何 URL / 版本 / 参数 / 事实是「编」的？——有则改掉或标 `<以官方 docs 为准>`。

## validator 检查清单（可执行）

```bash
f="$1"
echo "篇头问题: $(grep -cE '^## 本篇要回答的问题' "$f")"        # 必须 1
echo "正文分节: $(grep -cE '^## [0-9]+｜' "$f")"               # 必须 ≥3
echo "本篇结论: $(grep -cE '^## 本篇结论' "$f")"               # 必须 1
echo "参考资料: $(grep -cE '^## 参考资料' "$f")"               # 必须 1
echo "参考条数: $(sed -n '/^## 参考资料/,$p' "$f" | grep -cE '^\s*[-0-9]')"  # 必须 ≥3
echo "残留标记: $(grep -c 'CONTINUATION_MARKER' "$f")"          # 必须 0
```
