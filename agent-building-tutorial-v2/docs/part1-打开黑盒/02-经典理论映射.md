# 第 2 篇：经典智能体理论 → 现代 LLM Agent 映射

> **知识地图【A0/PMTA 坐标系】· Part 1**
> 本篇是 Part 1 的收口篇，也是全系列的理论地基。第 1 篇给的是"能力阶梯与路线图"——workflow 与 agent 的分界线、一次 tool call 的全流程；本篇给的是另一件工具：**一套分析任何 agent 的坐标系（PMTA）**。读完它，你看到任何 agent 产品都能立刻拆出"它有哪些部件、缺哪些部件"。第 1 篇埋下的 PMTA 在本篇正式定义；agent loop 仍只预告一句，第 3 篇展开。

## 本篇要回答的问题

1. 三十年前教材里那五类智能体——simple reflex / model-based reflex / goal-based / utility-based / learning——分别是什么？每类怎么判定？
2. 这五类怎么一一映射到 2026 年 LLM agent 的具体构件？
3. PMTA（Planning / Memory / Tool use / Action）四要素是什么？为什么它能当全系列的坐标系？
4. 都 2026 年了，讲 agent 为什么还要回到这套"老"理论？
5. 拿一个现成的 agent（你正在用的 Claude Code）对照 PMTA，怎么逐个指认它的构件？

## 1｜五类经典智能体：一份用了三十年还没过时的分类

读完本节你能理解：经典教材怎么给"智能体"分类，每类的一句话定义、一个后端工程师能共鸣的类比、和一条可操作的判定标准。

### 1.1 出处先说清楚

这套分类的权威出处是 Stuart Russell 与 Peter Norvig 的教材《Artificial Intelligence: A Modern Approach》（下称 AIMA；Pearson，1995 年首版，2020 年第 4 版，ISBN 978-0134610993——版本信息见官网 translations 页）。第 4 版第 2 章 "Intelligent Agents" 的 §2.4 "The Structure of Agents" 依次讲五类：simple reflex agents（§2.4.2）、model-based reflex agents（§2.4.3）、goal-based agents（§2.4.4）、utility-based agents（§2.4.5）、learning agents（§2.4.6）。

AIMA 的"智能体"框架一句话：智能体是**感知环境并作用于环境的任何东西**，内部跑的是一个"感知序列 → 动作"的映射。先建立一个关键认知：**这五类不是"从笨到聪明"的进化树，而是"用什么决定动作"的五个维度**。真实系统往往同时落在多个维度上——第 4 节和动脑练习会回到这一点。

### 1.2 simple reflex：纯刺激-反应

一句话：不看历史、不看目标，"一有刺激就按规则出招"。

日常类比：**无状态 HTTP handler**。请求进来，按路由和参数返回响应，处理完什么都不记——同一个请求永远得到同一种处理，它不关心你上一秒发过什么。

判定标准：动作只由**当前这次输入**决定。实现上就是一张 `条件 → 动作` 的规则表（AIMA 称 condition-action rule）。它没有内部状态可"记"，也没有目标可"想"。局限也和无状态服务一样：一旦任务需要"记得上下文才能做对"，它就抓瞎。

### 1.3 model-based reflex：有内部状态

一句话：维护一份"世界现在长什么样"的内部模型，动作由"当前输入 + 内部模型"共同决定。

日常类比：**带会话（session）的服务**。登录态、购物车、多步表单的中间态——服务在请求之间"记住"了什么，行为就不再只取决于这一次请求。

判定标准：比 simple reflex 多两样东西——(a) **内部状态**，(b) 一套"世界怎么变、我的动作怎么影响世界"的**模型**，用来在两次输入之间维持状态（AIMA 强调模型正是为了处理"当前感知不到的部分"）。注意：这里的 model 指"世界模型"，**不是**大语言模型。

### 1.4 goal-based：目标导向，会规划

一句话：不只是"遇到 X 就做 Y"，而是先问"做了 Y 之后，离目标更近了吗"——会模拟后果、会规划步骤。

日常类比：**编排器（orchestrator）**。你说"把这个服务发上线"，它自己排出"构建 → 测试 → 灰度 → 全量"——目标定了，路径要它自己找。

判定标准：存在**显式目标**；选动作的依据从"当前刺激匹配哪条规则"变成"哪个动作的**后果**能达成目标"。后果在动作之前看不见，所以要**搜索 / 规划**——AIMA 里这正是第二部分"问题求解"各章的起点。

### 1.5 utility-based：效用权衡

一句话：目标只回答"到没到"，utility（效用函数）回答"有多好"——在都能达成目标的几条路里挑综合最优。

日常类比：**网关的评分路由**。目标都是"把请求处理成功"，但你在成本、延迟、质量之间打分权衡：贵但快、便宜但慢、还是均衡？光"能到"不够，还要"划算"。

判定标准：有**显式的效用函数**给候选方案打分，在"多个都能达成目标的方案"之间比较。它内含 goal-based（首先能到目标），只是在"到"之上多了一层"值不值"。

### 1.6 learning：从经验改进

一句话：用"表现如何"的反馈改自己——规则、状态、知识，跑得越久越顺手。

日常类比：**线上系统自调优**。根据错误率、延迟自动调整缓存策略或限流阈值——系统行为随运行经验变化。

判定标准：部件里多了 **learning element（学习元件）** 和 **critic（评价器）**——critic 用相对固定的性能标准衡量 agent 的表现，learning element 据此修改决策部分（AIMA §2.4.6）。可操作的判定一句话：**换一批输入、多跑一段时间，它的表现是否变好。**

> 五个维度可以叠加：learning agent 的内部可以是 utility-based 的，utility-based agent 也可能同时维护内部状态（model-based）。分类是坐标系，不是单选标签。

## 2｜核心映射：五档理论 ↔ 2026 年的 LLM Agent

读完本节你能理解：五档分类在 LLM agent 里各对应什么构件——这是"这理论没白学"的兑现环节。先给映射总表，再逐档展开：

| 经典类型 | LLM agent 里的对应物 | 一句话对应关系 |
|---|---|---|
| simple reflex | 无记忆的单次 tool call | 只看当前消息选工具，不看历史 |
| model-based reflex | 有状态 / 有记忆的循环 | 把历史回填进上下文 = 维护内部状态 |
| goal-based | 把目标拆成计划的 agent | plan mode / plan-and-execute |
| utility-based | 多目标权衡 / 守卫 / 评测打分 | 模型路由、护栏、LLM judge |
| learning | eval 闭环与自改进 | 失败案例沉淀进评测集、改进 prompt |

### 2.1 simple reflex ≈ 无记忆的单次 tool call

第 1 篇那张[时序图](01-全景与学习路线地图.md)的单圈，就是 simple reflex：模型收到 messages + 工具清单，只根据"这轮对话里现在有什么"决定调不调工具、调哪个、参数填什么。不回填历史、不做目标推理——标准的 condition-action：条件（用户消息 + 工具 schema）→ 动作（tool call）。

判定也问同一个问题：**它的动作是不是只由当前输入决定？** 是，它就停在这一档。

### 2.2 model-based reflex ≈ 有状态 / 有记忆的循环

把工具结果与模型回复**回填进 messages 再问一次**（第 1 篇时序图第 (6) 步），你就迈进了 model-based 档：messages 列表就是 agent 的内部状态，"对话历史会增长"就是最朴素的世界模型。第 3 篇的 agent loop 会把这个循环写成代码，第 11 篇的三层记忆则把它工程化——上下文窗口装不下怎么办、哪些该记哪些该忘。

用后端味儿串起来：simple reflex 是无状态 handler；从这一档起，你开始给服务引入 session。

### 2.3 goal-based ≈ 把目标拆成计划的 agent

用户给的是一个**目标**（"把张三的角色换成 admin"），达成路径有多步、且没法预先写死——agent 得自己想"先查 → 再改 → 再验证"。这正是 goal-based 的定义：**依据动作的预期后果选动作**。第 12 篇的 Plan-and-Execute（先出一份可执行计划再逐步执行、结果推翻计划时重规划）是它的现代实现；你正在用的 Claude Code 的 plan mode 也是（第 4 节动脑练习里亲手指认）。

### 2.4 utility-based ≈ 多目标权衡 / 守卫 / 评测打分

这一档在 2026 年的 agent 工程里至少有三种现成形态：

- **模型路由**：简单任务走便宜模型、复杂任务走强模型——成本 vs 质量的效用权衡（第 20 篇）。
- **护栏（guardrail）**：危险操作按风险等级打分，决定"放行 / 停下来问人 / 拒绝"（第 9、19 篇）。
- **LLM judge / 评测打分**：给 agent 输出按维度打分再跑回归（第 18 篇）。

共同点：都引入了**显式打分**环节，在"能完成"之上问"好不好"——这就是效用函数的现代形态。

### 2.5 learning ≈ eval 闭环与自改进

先说一句诚实声明：LLM agent 的"学习"**大多不改模型权重**（微调是另一回事，第 18 篇会讲为什么新手别碰），改的是**权重之外的部分**——把失败案例沉淀进评测集、改 prompt、改工具描述、把经验写进记忆。判定精神不变：**同一个 agent，跑过一段时间后表现是否变好。** 本系列的落地在第 18 篇：reflection → 失败案例进测试集 → 改进 prompt → 回归验证，这是经典 learning 闭环（critic + learning element）的当代对应。

还有一个经典理论没预料到的差别值得点出：AIMA 的 learning 改的是 agent program 内部（权重 / 规则）；LLM 时代的 learning 改的是**环绕模型的外围资产**（评测集、prompt、记忆、工具描述）——因为模型本体是"租来的"，你改不了。

## 3｜PMTA：给任何 agent 画像的四要素坐标系

读完本节你能拿到全系列的主坐标系：此后每一篇都在这四个字母上展开。

### 3.1 一句话与出处

**PMTA** 大白话：描述任何 agent 只需要回答四个问题——**会不会先想（Planning）、记不记得住（Memory）、有没有手（Tool use）、动没动真格（Action）**。

定义：四个要素取首字母，即 **P**lanning（规划）/ **M**emory（记忆）/ **T**ool use（工具使用）/ **A**ction（行动）。这是本系列采用的工程坐标系；它的学术根基是 CoALA（**Co**gnitive **A**rchitectures for **L**anguage Agents，Sumers、Yao、Narasimhan、Griffiths，arXiv 2309.02427，2023 年提交、2024 年更新至 v3）。

### 3.2 ASCII 图

```
                    目标（用户的一句话）
                        |
             ┌──────────▼──────────┐
             │   P: Planning       │  先想：把目标拆成步骤（简单任务可以没有，见第 12 篇）
             └──────────┬──────────┘
                        ▼
  M: Memory  <────►  决策（LLM） ────►  T: Tool use
  记什么 / 忘什么       挑工具、填参数       （点菜，不做饭）
                        │
                        ▼
             ┌─────────────────────┐
             │   A: Action         │  真执行：发 HTTP / 写文件 / 查库
             └──────────┬──────────┘
                        │  结果回填 → 回到决策（这个循环 = agent loop，第 3 篇展开）
                        ▼
                 世界（你的后台系统）
```

### 3.3 准确定义与经典理论对应

- **Planning（规划）**：动手前把目标转成行动序列，执行中还能改计划。经典对应：goal-based（"按后果选动作"落到工程上就是规划），utility-based（多个可行方案间的权衡）。
- **Memory（记忆）**：保存并复用过去的感知、决策与结果——从"这轮对话历史"到"跨会话长期记忆"。经典对应：model-based reflex 的内部状态；learning 的经验沉淀。
- **Tool use（工具使用）**：从"只会说"到"能点菜"——把能力注册成模型可调用的清单，模型输出调用意图、你的代码执行（第 1 篇的三方分工）。经典对应：AIMA 里没有直接对应物，角色最接近的是 actuator（执行器，智能体作用于环境的机构）——这是本系列的理解性映射，非教材原义。
- **Action（行动）**：真正改变世界的一步——真发 HTTP、真写文件、真改数据。经典对应：五类共同的底座，即"感知 → 动作环"的动作端；simple reflex 当下就动，goal-based 把它作为计划中的一步。

### 3.4 核心交付物：要素 × 经典类型 × 你在哪篇学它

这张表是本篇的核心交付物，也是全系列坐标系——后面每篇引用它时一句话回顾即可：

| PMTA 要素 | 大白话 | 经典理论对应（AIMA） | 现代 agent 里长什么样 | 你在哪篇亲手做 |
|---|---|---|---|---|
| **P**lanning | 动手前先想路径 | goal-based（按后果选动作）、utility-based（多方案权衡） | plan mode、Plan-and-Execute、执行中重规划 | P4·12（反思与验证在 P2·4 埋点） |
| **M**emory | 记得住、忘得掉 | model-based reflex（内部状态）、learning（经验沉淀） | 上下文窗口、会话记忆、长期记忆、自动压缩 | P2·3（上下文管理）、P4·11（三层记忆） |
| **T**ool use | 能伸出去的手 | （无直接对应；最接近 actuator） | function calling、工具注册、MCP | P2·6（三种姿势）、P3·8-10（工具工程）、P5·13-15（MCP） |
| **A**ction | 真正改变世界 | 五类共同底座（感知 → 动作环的动作端） | 工具真执行：HTTP、SQL、写文件 | P3·8（第一个闭环）、P7·20（治理） |
| learning（横跨四要素） | 从经验变好 | learning agent（critic + learning element） | eval 闭环、trace 驱动改进 | P7·18 |

（learning 不是 PMTA 的第五个字母，但经典第五类必须落在坐标系里——它描述的是"这套坐标怎么随时间变优"，故以横行存在，落点在第 18 篇。）

### 3.5 怎么用：见到任何 agent 问四个问题

1. **它记什么？**（M）只看当前消息 = reflex 档；回填历史 = model-based 档；跨会话还记得 = 长期记忆。
2. **它想吗？**（P）拿到目标就闷头一步步干，还是先出计划、执行中还改计划？
3. **它的手多长？**（T + A）只有嘴（纯聊天）→ 能读（搜索）→ 能写（改数据、调接口）；真动手前有没有打分护栏（utility 成分）？
4. **它会变好吗？**（learning）失败案例去哪了——蒸发，还是沉淀进评测集 / 记忆？

## 4｜为什么 2026 年讲 agent 还要回到这套模型

读完本节你能理解：这套理论没过时的原因——它定义的是"智能体要有哪些部件"，而这个部件清单没有被 LLM 改变。

**一、LLM 改变的是"决策程序怎么实现"，没有改变"要有哪些部件"。** AIMA 的五类回答的是"用什么决定动作"：当前规则（simple reflex）、内部状态（model-based）、后果模拟（goal-based）、效用打分（utility-based）、经验修正（learning）。LLM 只是把"决定"这个环节的实现，从规则引擎 / 搜索算法换成了"读上下文、写文本的巨型函数"。2026 年你造一个 agent，仍然在回答 1995 年教材里的同一组问题：记忆放哪（M）、要不要规划（P）、工具怎么给（T）、动作怎么执行（A）。

**二、五个维度就是五条现成的"成熟度提问"。** 评价任何 agent——开源的、商业的、你们公司自研的——问的还是 §3.5 那四个问题。你会发现 2026 年的 agent 架构评审、评测报告，做的仍是 AIMA 第 2 章的事：给部件清单打勾。

**三、它是"防玄学"的理论。** 第 1 篇的立场是 agent 不是玄学、是一层编排代码；本篇补上另一半：经典理论把"智能体"还原成一份**工程构件清单**（PMTA），你按清单造零件、按维度判成熟度，不需要任何"涌现""意识"式的解释。CoALA 的作者们在 2023 年分析语言 agent 时，选择的框架正是"认知科学与符号 AI 的悠久历史"（论文摘要原话：draw on the rich history of cognitive science and symbolic artificial intelligence）——新物种，老骨骼，这是对"老理论没过时"最有力的背书。

一句话收束：**经典理论告诉你"造哪几个零件"，PMTA 把零件清单压缩成四个字母；本系列之后每一篇，都在这四个字母上施工。**

## 动脑练习：拿 Claude Code 对照 PMTA 逐个指认构件

本篇是纯概念篇，不配代码；练习是"指认"——照着步骤读官方文档，把一个真实 agent 的部件逐个填进 PMTA。做完它，你就通过了第 1 篇路线图里 P1 的自测门槛（"能指认一个现成 agent 的构件"），也是本 Part 的验收动作。

### 参考答案（填完再看）

- **Planning**：plan mode（先出计划、批准后执行）+ 模型把复杂任务拆成多步、按每步结果调整（官方 Models 一节："For complex tasks, it breaks work into steps, executes them, and adjusts based on what it learns"）。经典对应：goal-based。
- **Memory**：CLAUDE.md + auto memory + 会话上下文（JSONL 持久化、可 resume）+ 自动压缩 / `/compact`。经典对应：model-based（内部状态），同时是 learning 的素材来源。
- **Tool use**：五大类内置工具 + subagent / 提问等编排类工具。经典对应：actuator 的现代形态（模型点菜，工具真做）。
- **Action**：Bash 真跑命令、Edit 真改文件；checkpoints 提供动作级回滚。经典对应：动作端。
- **追加判定题**：Claude Code 属于经典分类的哪一档？——**不是哪一档，是哪几档的叠加**：维护内部状态（model-based）、会规划（goal-based）、有模型路由等成本权衡（utility-based 成分）、auto memory 从经验沉淀（learning 成分）。这正是 §1.1 说的"分类是维度，不是标签"。

一个诚实的边界说明：以上指认全部基于官方文档的公开描述（出处见参考资料 4-7）；Claude Code 本体闭源，harness 内部实现细节（如循环的确切代码路径）官方未公开，不在本练习指认范围内——第 16 篇拆解成熟 agent 时同样以公开文档与行为观察为准。

## 本篇结论

经典五类智能体定义的是"智能体用哪些部件决定动作"，LLM 只换了决策程序的实现、没换部件清单：reflex≈无记忆单次 tool call、model-based≈有状态循环、goal-based≈会拆计划的 agent、utility-based≈打分与权衡、learning≈eval 闭环。
PMTA（Planning / Memory / Tool use / Action）是这副骨架的四字母速记（学术根基 CoALA，arXiv 2309.02427），是全系列坐标系；动脑练习用它指认 Claude Code 构件，即 Part 1 的自测门槛。
**下一 Part 会暴露什么问题**：Part 1 只看了理论没写代码，PMTA 每个字母还都是纸上谈兵——Part 2 从第 3 篇起亲手把 M 与 A 写成代码（agent loop 与上下文管理），你会第一次看见自己造的 agent 在循环里跑起来。
