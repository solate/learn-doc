# 电力行业视频协议与国网标准

> **适合读者**：参与国家电网/南方电网视频监控系统项目的后端开发者  
> **核心内容**：电力视频为什么特殊（安全分区）→ 一堆标准到底谁管什么（GB28181 / DL/T 283 / Q/GDW 1517）→ 变电站视频接入网关怎么工作 → 国网扩展点（入网检测 / 国密 / 巡检机器人）→ 配网边缘的轻量视频怎么做  
> **本篇主线**：先记住一句话——电力视频不是"另一个物联网视频"，而是"被安全分区和合规标准框死的国标视频"。所有技术细节（接入网关、国密、级联）都是在回答同一个问题：**视频怎么在不违反安全隔离的前提下，从边缘变电站送进平台，交给符合标准的上游系统。**

读完本篇，你能做到：

1. **理清标准层级**：说出 GB28181、DL/T 283、Q/GDW 1517、DL/T 2866 各自是谁发的、管什么、怎么配合
2. **看懂安全分区**：画出四区模型，说清视频在哪个区、正向/反向隔离装置允许什么方向的流量，为什么变电站摄像头不"直接进平台"
3. **说清视频接入网关**：讲明白"站端网关"在电力链路里夹在摄像头与主站中间干什么、对应开源世界里的哪个角色（ZLMediaKit 类的黑盒）
4. **说出国网对 GB28181 扩展了什么**：入网检测、国密算法、级联/联动、机器人当特殊设备——而不是"和安防国标完全一样"
5. **选对传输方式**：区分"光纤/专网的站端实时流"和"配网无线的边缘轻量视频"该用什么（实时流 vs 事件抓拍图片）
6. **走通一次合规接入**：拿到一个变电站项目，知道要先查什么、先验什么、按什么顺序把摄像头接进平台

## 一、电力视频的三个特殊点：先立起"为什么"

电力视频和普通安防（第 24、25 篇）用的协议栈几乎一样，但多了三道锁，这三道锁决定了整个工程做法：

| 特殊点 | 后果 | 体现 |
|--------|------|------|
| **网络被分区隔离** | 视频不能随便连公网、不能直连业务网 | 安全区 I/II/III/IV + 隔离装置（第三节） |
| **必须过标准合规** | 采购、接入、验收都看检测报告 | 入网检测、"全网一套标准"（第二节） |
| **传输要国密加密** | 链路加密用 SM4/SM2/SM3 不用 AES/RSA | 平台间传输、录像加密（第六节） |

**为什么普通安防的方法论不能直接搬**：公安视频专网只要解决"跨品牌互联"（GB28181），电力视频在此基础上多了一道"**决不能让控制区被视频链路攻破**"的底线。视频链路是攻击面——一个被黑的摄像头等于给电网控制网开了一扇后门，所以一切的方案设计都先回答"这条链路会不会污染更安全的区"。

读完本章你能理解：电力视频的协议栈并不新奇，新奇的是它被"安全分区 + 标准合规 + 国密"三道锁框住，所有工程决策都从这三道锁出发。

## 二、标准全景：四类标准到底谁管什么

电力项目最劝退新人的是标准一堆：GB28181、DL/T 283、Q/GDW 1517、DL/T 2866……其实它们分属三层，不用全背：

```
第 1 层  安全红线（国家法规）        《电力监控系统安全防护规定》
          └ 规定分区、隔离装置 —— 谁都不能违反的物理边界
第 2 层  联网信令国标（通用）        GB/T 28181
          └ 设备/平台怎么注册、级联、点播 —— 第 25 篇刚讲过
第 3 层  电力专用（行业 + 企业）     DL/T 283、Q/GDW 1517、DL/T 2866
          └ 在统一信令之上，追加电力场景的技术与安全要求
```

| 标准号 | 发布方 | 管什么 | 重要性 |
|--------|--------|--------|--------|
| **GB/T 28181** | 国标（公安部）| 视频监控联网的 SIP 信令与媒体（注册/级联/点播）| 一切的"底层信令" |
| **DL/T 283**《电力视频监控系统接口规范》 | 行业标准（中电联）| 电力视频的**接口划分**：前端怎么接入、平台间怎么互联、编码与图像质量要求 | 电力项目必备 |
| **Q/GDW 1517-2015**《变电站视频监控系统技术规范》 | 国网企业标准 | **变电站**场景的专属要求：前端设备选型、图像指标（主码流 ≥ 2Mbps、≥ 720P）、联网方式 | 国网项目必备 |
| **DL/T 2866-2024**《配电网物联网平台接入技术规范》 | 行业标准（中电联）| **配电网边缘终端**（传感器/智能开关/带视频能力的边缘设备）接入物联平台 | 配网/边缘项目必备 |
| 南网对应企标 | 南方电网 | 与 Q/GDW 1517 同位，南网各省有自己的补充规范 | 南网项目按所属省查 |

**三条工程结论，比背标准号有用**：

1. **先问"这是哪家电网、哪个省"再找标准**。国网看 Q/GDW 系列，南网看南网企标，而且**各省电网公司经常有自己的补充细则**（接口、入网名录制式的差别）。开工前第一件事就是找项目所在省的《视频监控接入实施细则》。
2. **DL/T 283 是"全域接口分法"，Q/GDW 1517 是"变电站落地细则"**。前者规定接口框架（你能想象成"电力版的数据字典 + 接口规范"），后者细化到"变电站里一台枪机要满足什么指标"。界别：接口/互联问题查 283，变电站前端问题查 1517。
3. **调度/生产系统的标准不在视频里**。视频系统要跟电力业务系统（PMS 生产管理、EMS 调度、OMS 运维）联动，联动的"谁给谁数据、怎么认证"遵循各自系统的规定——视频平台只是其中一环。

读完本章你能理解：标准是三层结构——安全红线是底线、GB28181 是通用信令、DL/T 283 与 Q/GDW/Q 系列是电力落地约束。做项目先定位"哪个省、哪家电网上网公司"，别对着全国标准猜。

## 三、安全分区：视频放在哪、怎么进出

### 3.1 四区模型

电力监控网络被强制划分为两大区四个安全区：

```
生产控制大区（高安全）                 管理信息大区（低安全）
 ├─ 安全区 I  控制区                    ├─ 安全区 III  生产管理区
 │   调度自动化 SCADA                   │   视频监控系统 ← 视频在这里
 │   继电保护                           └─ 安全区 IV   企业管理区
 └─ 安全区 II 非控制区                       OA/办公/财务
     电量采集 / 自动装置
```

- **越靠上越安全、越敏感**：I 区是控制电网的命根子，一旦被攻破后果最严重。
- **视频在安全区 III**（管理信息大区）：因为视频属于"生产监视"而非"控制"，放 III 区既够用又不污染控制区。

### 3.2 隔离装置：只能单向走

大区之间的数据传输**不允许直连**，必须通过专用硬件装置，而且方向被锁死：

| 装置 | 允许方向 | 用途 |
|------|---------|------|
| **正向隔离装置** | 安全区 I/II → III/IV（高→低）| 定时/准实时把数据单向送出来 |
| **反向隔离装置** | 安全区 III/IV → I/II（低→高）| 极少量受控数据回送，**必须人工审核** |

```
       ┌────────── 正向隔离装置 ──────────┐
安全区I/II                              安全区III/IV
（调度/采集）   ──只出单向──►              （视频/生产管理）
              ◄──仅受控少量（审核）──────  反向隔离装置
```

**记忆锚点**："正出去、反射回"。正向隔离装置把生产数据单向带出，反向隔离装置只放行经过审核的极少量数据回伸。**反向方向永远不是"平等的双向"**，这是电力网络安全的地基。

### 3.3 变电站的现实：摄像头在站内，但"归属"在 III 区

最绕的是这一点：摄像头物理上就装在被监视的变电站里，而变电站里同时有 I/II 区的自动化设备——**摄像头不能直接插到主站视频平台**，中间必须隔一道"站端接入"：

```
变电站站内
  IPC×N / NVR / 巡检机器人(WiFi)
        │  站内网（和自动化设备隔离的独立 VLAN/网段）
        ▼
  视频接入网关（站端）          ← 第四节主角
        │  电力综合数据网 / 专用通道
        ▼
  [隔离装置/安全接入区]  —— 符合分区要求后才允许出
        │
        ▼
  省/市/县 统一视频监控平台（安全区 III）
        │ 级联（GB28181）
        ▼
  上级平台 / 调度中心侧查看
```

**理解要点**：视频数据在站内就被"圈"进一个独立网段，由站端网关统一收口，再按安全分区要求单向送向主站。**你写的代码几乎总是在"网关之后"——对着统一的平台 API，而不是直接戳摄像头的 IP。**

读完本章你能理解：安全分区是物理级的约束——视频在 III 区，进出靠单向隔离装置，站端摄像头由网关收口而非直连主站。项目里任何"要不要开放端口、能不能直连"的争论，都回到这张图上回答。

## 四、视频接入网关：电力特有的中间层

### 4.1 它是什么

在公安视频里，设备大体"自分级联"接平台；在电力里，**几乎每个站点都有一层"视频接入网关"**垫在摄像头与主站之间。它是硬件盒子或站内软网关，本质是——

> **一台微型的 GB28181 平台 + 本地视频管理器**：向下用 ONVIF/RTSP/私有 SDK 吃各路摄像头，向上用一个统一身份向主站注册，把"一堆厂商的摄像机"翻译成"一路符合规范的标准通道"。

```
     向上：一个身份，GB28181 REGISTER → 主站
                      同目录/心跳/点播
 视频接入网关
     向下：ONVIF(发现/配置) + RTSP(取流) + 私有SDK(NVR等)
                 │
            IPC / NVR / 球机 / 巡检机器人
```

### 4.2 它替你挡掉的问题（这也是它的存在理由）

| 问题 | 网关怎么解决 |
|------|-------------|
| 站内摄像头品牌杂、协议私有 | 网关内置 ONVIF/RTSP/主流厂商 SDK，统一成标准通道 |
| 到主站的连接不能被每个摄像头直连 | 只有网关一个 身份、一条电路进主站，主站对接面收敛 |
| 站端断网/延时 | 网关本地录像，网络恢复后补传（主站无感） |
| 安全要求 | 网关做白名单、限流、国密隧道，是站与网之间的"安全关闸" |
| 联动（告警抓拍/录像） | 网关在站内就近完成，不占主站资源 |

### 4.3 对应到开源 / 工程选型

- **不想自研**：国网/南网有**入网检测名录**，项目直接采购名录里的站端网关产品（集成了上述能力）。
- **想先跑通概念**：开源里最接近的就是 ZLMediaKit（[第 16.5 篇](../02-工程实践优化/16.5-ZLMediaKit实战.md)）——它内置 GB28181 的 SIP 接入 + RTP/PS 解封装 + 转出 RTSP/HTTP-FLV/HLS，你拿它当"模拟站端网关/主站"都行，反正要透的过程（注册、目录、点播、把 28181 转 HTTP-FLV 给前端播放）一应俱全。
- **你（后端）真正要写的**：不是信令，而是**级联状态管理**——维护"站端网关 ⇄ 通道 ⇄ 录像 ⇄ 权限"，以及"收到某路由注册 → 上报目录 → 允许/拒绝点播"的业务判断。

读完本章你能理解：视频接入网关是电力链路里"向下收多品牌、向上露单一身份"的翻译层+安全关闸，类比开源世界就是一台独立运行的 ZLMediaKit。后端代码工作在其上的 API 层，不做底层信令。

## 五、电力对 GB28181 的扩展：同信令，多几道规矩

GB28181 的信令骨架（REGISTER 摘要认证 → Keepalive 心跳 → CATALOG 目录 → INVITE 点播）在第 25 篇已完整讲透，电力这里**一条不换**。变的是加在骨架上的四道"电力规矩"：

### 1. 入网检测（型检）——接入的前置门槛

电力项目里的摄像头/网关/平台**必须持有效检测报告**（国网/南网或认可的检测机构出具）才能接入，招标和验收都会检查。试剂上这叫"入网许可/型检"：

- 设备没检测报告 → 平台直接拒绝注册或不予验收；
- 同一型号、不同批次是否免检，以当年细则为准——开工前把"设备入网名录"问进项目初期的风险清单。

### 2. 国密算法——链路加密不许用 RSA/AES

电力平台间、平台与重要站端之间的传输，要求用国密算法（第六节展开）。信令走国密 TLS（TLCP），媒体流按需加密。

### 3. 级联与联动——不是单单看视频

- **级联**：站端网关 → 县/市 → 省，逐级注册、目录同步（第 25 篇的级联流程图原样适用，只是纵向多了一层站端）；
- **联动**：视频与业务系统（PMS/EMS）联动——越限告警 → 弹对应摄像头画面、自动录像；周界入侵 → 联动球机转向 + 抓拍。**联动接口是电力项目真正的"业务量"所在**，视频本身反而按标准走完就行。

### 4. 巡检机器人/无人机 = 特殊"摄像头"

机器人（变电站内）和无人机（输电线路）被平台当作**特殊前端设备**注册入网（第七节展开）。它们比其他 IPC 多两类数据：**云台控制**和**AI/仪表读数上报**——这走的是 GB28181 的 `DeviceControl`（PTZ）与国标消息（数据/告警上报），不是视频之外的私货。

### 快速回顾：一条注册链条长什么样（对照第 25 篇 3.5）

```
站端网关(SIP UA)                       省统一视频平台(SIP @5060)
   │  REGISTER（不带认证）                     │
   ├──────────────────────────────────→│
   │←──────────────────────────────────│  401 Unauthorized（Digest 挑战）
   │  REGISTER（带 Authorization + Expires）   │
   ├──────────────────────────────────→│
   │←──────────────────────────────────│  200 OK
   │  MESSAGE Keepalive（每 ~60s）            │
   ├──────────────────────────────────→│   注册期间持续保活
   │  MESSAGE Catalog（上报通道目录）           │
   ├──────────────────────────────────→│   平台建通道资源
```

差异点就是：**注册方的设备 ID 要符合电力编码规则（通常沿用 GB28181 的 20 位编码，行业位/序号按各省规定）、必须已在名录、信令加密用国密**。报文构成不变。

读完本章你能理解：电力没有发明新信令，GB28181 怎么做它怎么做——只是加了四道规矩：入网检测、国密加密、多级级联+业务联动、机器人当特殊设备。排障时仍按第 25 篇的时序表查"注册失败/点播无流/PS 不解封装"。

## 六、国密加密：SM4 / SM2 / SM3

### 6.1 谁对应谁

| 国际算法 | 国密对应 | 用途 |
|---------|---------|------|
| AES-128 | **SM4** | 对称加密：媒体/录像加密 |
| RSA-2048 | **SM2** | 非对称：身份认证、密钥协商、签名 |
| SHA-256 | **SM3** | 摘要/校验 |
| TLS 1.3 | **TLCP**（国密 TLS）| 传输层握手，证书链用 SM2/SM3 |

**工程现实**：链路层由"国密 VPN/平台内建国密模块"整体承担，业务代码通常见不到裸算法；但验收会抓包验证是否走国密。下面代码用于**理解与自测**，不用于生产链路实现。

### 6.2 SM4 代码示例（Go）

```go
// 依赖：github.com/tjfoc/gmsm（国密 Go 库）
// SM4 是 16 字节块密码，CBC 模式需要 16 字节 IV
import (
    "bytes"
    "crypto/cipher"
    "fmt"
    "github.com/tjfoc/gmsm/sm4"
)

// 加密一段视频数据（演示：真实链路由平台内建国密模块完成）
func sm4EncryptGOP(key, iv, plaintext []byte) ([]byte, error) {
    if len(key) != 16 || len(iv) != 16 {
        return nil, fmt.Errorf("SM4 密钥与 IV 必须为 16 字节")
    }
    block, err := sm4.NewCipher(key)
    if err != nil {
        return nil, err
    }
    // CBC 要求输入是 16 字节的整数倍，先做 PKCS#7 填充再用 SM4 加密
    padded := pkcs7Pad(plaintext, block.BlockSize())
    out := make([]byte, len(padded))
    cipher.NewCBCEncrypter(block, iv).CryptBlocks(out, padded)
    return out, nil
}

// PKCS#7 填充：末尾补 N 个字节，每个字节的值都是 N（补齐到块大小整数倍）
func pkcs7Pad(data []byte, blockSize int) []byte {
    padLen := blockSize - len(data)%blockSize
    return append(data, bytes.Repeat([]byte{byte(padLen)}, padLen)...)
}
```

**要点**：SM4 用法和 AES-CBC 完全同构，只是块大小与算法不同——这解释了为什么"国密改造"往往是"换库 + 换证书体系"，不是重写加密逻辑。

读完本章你能理解：国密不是新体系而是"换算法 + 换证书体系"：SM4/AES 同构、SM2/RSA 同构、SM3/SHA 同构。验收时的判断手段是抓包看握手证书是否为国密根 CA 签发。

## 七、巡检机器人 / 无人机：移动的"摄像头"

### 7.1 两类场景

```
变电站巡检机器人（站内）
  ├── 局域网 WiFi：RTSP/RTMP 推流（实时，站内带宽够）
  ├── 视频 + 仪表读数/AI 结果同步上报（国标消息）
  └── 异常时触发云台转向 + 高清抓拍

输电线路巡检无人机（线路，无固定网络）
  ├── 4G/5G 弱网推流：SRT（第 9 篇主角，抗丢包）
  ├── 飞行过程本地存储，降落后断点/全量回传
  └── 热红外/可见光双光数据，回传后拼图分析
```

### 7.2 接入要点

| 问题 | 做法 |
|------|------|
| 机器人算什么设备 | 作为一个特殊通道注册入网，额外带设备控制（PTZ）和状态上报 |
| 无人机视频延迟/卡顿 | 弱网走 **SRT**（抗丢包），或 4G 绑定性推流 + 本地回补 |
| 数据怎么进平台 | 无人机回传视频 → 站端/线路侧接入点 → 再按 GB28181 上送；与实时 IPC 同一套主站 |
| 与主站联动 | 机器人识别的异常（表计读数超限、油位异常）触发平台侧告警 + 联动录像 |

`ffmpeg` 推 SRT 的示例（线路巡检场景）与第 9 篇一致，只是更多用到 `-re`（按实时速率推）和弱网参数：

```bash
# 无人机端：SRT 推流（latency 调大容忍抖动，caller 主动连接收端）
ffmpeg -re -i /dev/video0 \
  -c:v libx264 -preset veryfast -b:v 2M \
  -f mpegts "srt://inspection-server:9000?streamid=uav001&latency=400&mode=caller"
```

读完本章你能理解：机器人和无人机只是"能动的摄像头"，进平台的路径机制不变——实时流走流媒体协议、弱网用 SRT、数据/告警走国标消息；真正的新东西是"AI 结果 + PTZ"这两类与视频并列的数据。

## 八、配网边缘的轻量视频：没有光纤怎么办

站内视频走光纤/专网，**配电网没有**：配变台区、智能开关、电缆井在路边/野外，往往只有 2G/4G/5G 无线，带宽小、时好时坏。这里的主线不是"实时高清"，而是"**够用的画面 + 事件触发**"：

### 8.1 三种逐级升配的方案

| 需求强度 | 方案 | 数据量 | 适配 |
|---------|------|--------|------|
| 平时不用看，出事要证据 | **事件触发抓拍**（图片）| 单张几 KB ~ 几十 KB | 告警联动抓图 → 压缩 → MQTT/HTTP 上报物联平台 |
| 偶发要看实时 | **极低码率流**（H.265 + 低分辨）| 100–300 Kbps | 需要时再拉，平时不推 |
| 有带宽余量 | 全量实时流（同站端方案）| ≥ 1 Mbit | 有光纤/专网的台区 |

### 8.2 配网场景怎么落地

```
配变/智能开关的边缘终端（带摄像头）
  ├─ 事件触发 → 抓拍 JPEG（H.264/H.265 压缩，缩略图）→ MQTT QoS1/HTTP 上报
  │        → 接入电力物联管理平台（按 DL/T 2866 规范）
  └─ 需要实时时 → 边缘盒拉 RTSP → H.265 降码率 → 4G 上行（SRT/WebRTC 弱网）
```

**为什么以图片为主**：实时流 1 秒的数据量抵几百张抓拍图，无线链路扛不住也不必要——配网的刚需是"它有没有异常、异常长什么样"，图片正好满足，还能长期低成本留存。

**接入对象的分界线**：站端实时视频归**视频监控平台**（GB28181 体系），配网边缘终端归**物联管理平台**（DL/T 2866 / MQTT 体系）。两套是不同系统，别混着做——这也是第 33 篇"消息通道 vs 视频通道"在电力侧的落地。

读完本章你能理解：配网没有光纤，就别硬上实时高清——按"事件抓拍图片为主、低码率流按需、专网台区才全量实时"逐级升配，且配网设备走物联平台、站端视频走视频平台，两条体系各归各的。

## 本篇小结

1. **三道锁定义电力视频**：安全分区（网络边界）、标准合规（采购与验收门槛）、国密加密（链路传输要求）——所有架构决策都从这三条出发。
2. **标准三层结构**：安全法规管分区 → GB28181 管信令 → DL/T 283（接口）/ Q/GDW 1517（变电站细则）/ DL/T 2866（配网接入）做电力落地；动手前先确认"哪个省、哪家电网"。
3. **视频在安全区 III，进出靠单向隔离装置**：正向出、反向射回（受控+审核），物理上摄像头由站端网关收口，不直连主站。
4. **视频接入网关是电力特有的中间层**：向下吃多品牌、向上露单一 GB28181 身份，兼做本地录像与安全关闸；开源类比 = 一台独立 ZLMediaKit。
5. **电力没发明新信令**：GB28181 原样用，只是叠加入网检测、国密、多级级联 + 业务联动、机器人当特殊设备。
6. **国密是换算法不是换思路**：SM4≈AES、SM2≈RSA、SM3≈SHA、TLCP≈TLS；验收靠抓包看国密证书。
7. **边缘求"够用"不求"高清"**：配网无光纤 → 事件抓拍图片为主、低码率按需；实时视频进视频平台、边缘终端进物联平台，各归各。

## 动手实践

### 练习1：本机搭"站端→主站"的 GB28181 注册链（模拟接入）

用 ZLMediaKit 当"省统一平台"，一个 GB28181 设备/模拟器当"站端摄像头"，把探电注册过程走一遍（详细 ZLMediaKit 部署见 [第 16.5 篇](../02-工程实践优化/16.5-ZLMediaKit实战.md)）：

```bash
# 1. 起平台（SIP 5060 + HTTP API 8000）
docker run -d --name zlm -p 8000:8000 -p 554:554 -p 5060:5060/udp \
  zlmediakit/zlmediakit:master

# 2. 在 GB28181 设备/摄像头模拟器里配置：
#    SIP 域/端口 = 本机 5060；设备 ID = 34020000001320000001
#    通道 ID = 34020000001320000002（尾号 +1，规则见第 25 篇 3.4）

# 3. 查平台已注册设备与可播流（等价于电力平台的“设备列表”）
curl "http://127.0.0.1:8000/index/api/getMediaList?app=rtp"
```

**预期输出**：平台媒体列表出现 `rtp/34020000001320000002`，Web 界面有该设备且"在线"。此时把日志级别调成 debug，能看到 **REGISTER → 401 → REGISTER → 200** 的完整会话——这正是第五节回顾的注册链。你在电力项目里排查"摄像头怎么没上来"，看的就是同一段日志。

### 练习2：验证"安全分区单向性"的抽象实验

不是真隔离装置（那要电力专用硬件），而是验证你对该约束的心智模型——把隔离装置当作"只能单向走的路由器"来排查：

```bash
# 在一台机器上开 5080 收流（模拟管理区平台），试试从"生产区"侧 netcat 主动连它
# 预期：如果按电力单向隔离，这个方向根本不通——把"端口不通"当作设计，而不是故障

# 现实对照：真正做跨区传输时，永远先问“这是正向还是反向？”
# 正向（高→低）：走正向隔离装置，数据格式受装置限制（如规定报文头）
# 反向（低→高）：必须人工审核，一定不是实时双向通道
```

**预期输出**：你写下一张清单："给平台的每个数据需求标注方向（正/反）"，凡标"反"的先问审核流程——这就是电力项目里"视频能不能调出某个业务系统的报警数据"这类问题的答案来源。

### 练习3：SM4 国密加解密自测（验收口径）

电力项目验收会问"链路是否国密"，设备端可用下面代码自证算法管线通：

```go
// 依赖：github.com/tjfoc/gmsm
import (
    "bytes"
    "crypto/cipher"
    "fmt"
    "github.com/tjfoc/gmsm/sm4"
)

func sm4RoundTrip(key, iv, data []byte) (bool, error) {
    if len(key) != 16 || len(iv) != 16 {
        return false, fmt.Errorf("SM4 密钥/IV 必须为 16 字节")
    }
    block, err := sm4.NewCipher(key)
    if err != nil {
        return false, err
    }
    // CBC 要求输入是 16 字节的整数倍，这里用测试数据（已对齐）演示来回转换
    enc := make([]byte, len(data))
    cipher.NewCBCEncrypter(block, iv).CryptBlocks(enc, data)

    dec := make([]byte, len(enc))
    cipher.NewCBCDecrypter(block, iv).CryptBlocks(dec, enc)
    return bytes.Equal(dec, data), nil
}
```

**预期输出**：返回 `true`。再用 Wireshark 抓包：观察链路握手使用的证书链是否为国密根 CA 签发（数字证书上 sm2 签名的天文特征），确认"国密链路"而非"只是用 SM4 把某段数据加密"——两者在验收里含义完全不同。

## 常见问题排查

| 现象 | 可能原因 | 解决方法 |
|------|---------|---------|
| 摄像头能本地看、平台里"离线" | 站端网关未注册成功或心跳（~60s）丢失 | 先查网关与主站的网络打通；再看 debug 日志确认 REGISTER→200 完成；核对设备 ID 编码是否符合省电力规则 |
| GB28181 注册 401 后无 200 | 国标密码不一致 / 设备不在入网名录 | 核对设备国标密码；确认为入网检测名录内型号（否则平台侧按合规拒绝）|
| 跨区拉视频超时/黑屏 | 正向隔离装置带宽或白名单未配 | 联系安全团队给视频数据配隔离装置规则、协商上行带宽 |
| 点播 INVITE 后无媒体流 | 平台收流端口没对上 / 媒体端口被防火墙挡 | 按第 25 篇 3.7 核对 INVITE 的 `m=` 行端口，开放 RTP 端口段 |
| 机器人/无人机画面卡顿 | 站内 WiFi 干扰 / 4G 弱网丢包 | 换有线/调信道；无人机走 SRT（调大 latency 容忍抖动）|
| 机器人 AI 结果与画面对不上 | 时间戳漂移 | 统一 Unix 毫秒，设备端 NTP 同步 8 步 |
| 国密证书不被识别 | 系统未装国密根 CA / 应用未启用 GM TLS | 安装电网根 CA，配置 TLCP；确认应用支持 SM2/SM3 证书链 |
| 配网抓拍图片迟迟上不来 | 4G 链路抖动 / 图片过大 | 压缩分辨率/JPEG 质量；MQTT QoS1 + 断线缓存重发；或用"缩略图先传、原图按需"两段式 |
| 要 video 平台的流去物联平台 | 把两套体系搞混 | 站端视频进视频监控平台（GB28181），配网边缘终端进物联管理平台（DL/T 2866 / MQTT），互不替代 |

## 术语表

| 术语 | 英文/全称 | 说明 |
|------|-----------|------|
| 安全区 I/II/III/IV | Security Zone | 电力网络按安全级别划分：I 控制区、II 非控制区（生产控制大区）；III 生产管理区、IV 企业管理区（管理信息大区）。视频在 III 区 |
| 正向隔离装置 | Forward Isolation Device | 允许高安全区→低安全区单向传输的硬件装置 |
| 反向隔离装置 | Reverse Isolation Device | 允许低→高极少量受控传输，必须人工审核 |
| 视频接入网关 | Video Access Gateway | 站端统一收口设备：向下接多品牌摄像头，向上以单一身份走 GB28181 注册到主站 |
| 入网检测 / 型检 | Type Test | 电力设备接入前必须通过检测并列入名录，否则拒绝接入 |
| DL/T 283 | 电力视频监控系统接口规范 | 行业标准：电力视频的接口划分与平台互联要求 |
| Q/GDW 1517 | 变电站视频监控系统技术规范 | 国网企业标准：变电站视频的细则要求 |
| DL/T 2866 | 配电网物联网平台接入技术规范 | 行业标准：配网边缘终端接入物联平台 |
| 国密 | China National Cryptography | SM4/SM2/SM3/TLCP 等中国自主密码算法体系 |
| GB28181 | GB/T 28181 | 视频监控联网信令国标（详见第 25 篇）|
