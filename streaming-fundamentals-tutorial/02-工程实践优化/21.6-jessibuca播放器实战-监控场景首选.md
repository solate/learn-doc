## 一、jessibuca 简介与定位

### 1.1 jessibuca 是什么

**jessibuca** 是一个纯 H5 直播流播放器，基于 WebAssembly（WASM）实现，由国内开发者 langhuihui 开发并开源。

**核心特性**：
- 支持 HTTP-FLV、WebSocket-FLV、WebSocket-RAW（配合 Monibuca）
- **双解码模式**：MSE 硬解（H.264）+ WASM 软解（H.264/H.265）
- **监控场景优化**：低延迟缓冲、断线重连、水印叠加、PTZ 云台控件
- **跨平台**：PC、移动端、微信环境均可使用
- **商业友好**：MIT 协议，免费可商用

**GitHub 仓库**：[langhuihui/jessibuca](https://github.com/langhuihui/jessibuca)

### 1.2 与其他播放器对比

| 播放器 | H.265 支持 | 解码模式 | 延迟 | 监控场景优化 | 维护状态 |
|--------|-----------|---------|------|-------------|----------|
| **jessibuca** | ✅ WASM 软解 | MSE + WASM | 1-3s | ✅ 专门优化 | 活跃（2026 年仍在更新） |
| **flv.js** | ❌ | MSE 硬解 | 1-3s | ❌ 通用播放器 | 停止维护（2018 年后） |
| **mpegts.js** | ❌ | MSE 硬解 | 1-3s | ❌ 通用播放器 | 低频维护 |
| **EasyPlayer** | ✅ WASM 软解 | WASM | 1-3s | ✅ 监控优化 | 商业付费 |

**jessibuca 的差异化优势**：
1. **唯一免费开源且支持 H.265 的 WASM 播放器**（EasyPlayer 需付费）
2. **智能降级**：MSE 可用时用硬解（低 CPU），不可用或 H.265 时自动切 WASM 软解
3. **监控场景深度优化**：内置 PTZ 控件、水印、多实例管理、Canvas 坐标叠加

### 1.3 jessibuca 与 GB28181 的关系

**重要澄清：jessibuca 是通用的 FLV 播放器，不是专门为 GB28181 设计的。**

**支持的协议**：
- HTTP-FLV（HTTP 长连接传输 FLV）
- WebSocket-FLV（WebSocket 双向传输 FLV）
- WebSocket-RAW（配合 Monibuca 流媒体服务器）

**支持的编码格式**：
- H.264（AVC）
- H.265（HEVC）

**应用场景（覆盖多个行业）**：
- ✅ **GB28181 国标监控**：国标视频监控联网系统（信令用 SIP，媒体传输用 RTP）
- ✅ **普通安防监控**：海康/大华/宇视等摄像头（非国标，RTSP/RTMP 推流）
- ✅ **直播平台**：HTTP-FLV 低延迟直播
- ✅ **车载监控**：4G/5G 车载摄像头实时回传
- ✅ **智能家居摄像头**：家用 WiFi 摄像头

**GB28181 与 jessibuca 的关系**：
- **GB28181 是国标协议**：定义了监控设备与平台之间的通信规范（信令用 SIP，媒体传输用 RTP/RTSP/RTMP）
- **jessibuca 是浏览器播放器**：负责在前端播放 HTTP-FLV 流
- **完整链路**：GB28181 设备 → 流媒体服务器（SRS/ZLMediaKit）→ HTTP-FLV → 浏览器（jessibuca）

**结论**：GB28181 只是 jessibuca 的一个应用场景，不是唯一场景。jessibuca 可以播放任何来源的 HTTP-FLV/WebSocket-FLV 流，无论推流端是 GB28181 设备、普通摄像头、OBS 推流、还是 FFmpeg 转码。

## 二、为什么监控场景首选 jessibuca

### 2.1 国内监控行业的现实痛点

**痛点 1：H.265 编码普及**
- 国内摄像头厂商（海康/大华/宇视）2020 年后出厂设备大量采用 H.265 编码（体积减半，节省带宽）
- 浏览器 MSE **不支持 H.265**（Safari 部分支持，Chrome/Firefox 完全不支持）
- flv.js / mpegts.js 只能播 H.264，遇到 H.265 流直接黑屏

**痛点 2：多路并发播放**
- 监控中心常见 16/32/64 路分屏，MSE 硬解并发数有限（Chrome ≈ 8 个 video 实例）
- 超过并发数后新流无法打开，或旧流被浏览器强制回收

**痛点 3：低延迟要求**
- 实时监控延迟要求 < 2s（WebRTC 成本高，HTTP-FLV 是主流）
- 需要精细的缓冲区控制（`videoBuffer`、追帧策略）

**jessibuca 的解决方案**：
1. **H.265 软解**：WASM 解码器支持 H.265，覆盖所有浏览器
2. **智能降级**：H.264 用 MSE 硬解（低 CPU），H.265 自动切 WASM 软解
3. **低延迟优化**：`videoBuffer` 精细配置，支持追帧、丢帧策略
4. **多实例管理**：每路流独立 Worker 线程解码，互不干扰

### 2.2 典型应用场景详解

#### 场景 1：GB28181 国标监控平台

**技术特征**：
- **信令协议**：SIP（Session Initiation Protocol）
- **媒体传输**：RTP/RTSP/RTMP
- **编码格式**：H.265 为主（节省带宽，国标推荐）
- **分屏需求**：16-64 路同时监控

**完整链路**：
```
GB28181 摄像头 → SIP 注册到 GB28181 平台（如 ZLMediaKit）
                ↓
         平台转发媒体流（RTP → RTMP → HTTP-FLV）
                ↓
         浏览器（jessibuca 播放 HTTP-FLV）
```

**jessibuca 解决的问题**：
- ✅ **H.265 软解**：GB28181 设备大量采用 H.265 编码，flv.js/mpegts.js 无法播放
- ✅ **多路并发**：16 路以上分屏，WASM 软解不受 MSE 并发数限制
- ✅ **低延迟**：配合 `videoBuffer: 0.2`，延迟控制在 1-2 秒

**实际案例**：公安/交通/城管的视频监控平台，数百路摄像头接入，中心大屏 16-64 分屏实时监控。

- **设备协议**：RTSP（非国标）
- **编码格式**：H.264/H.265 混合
- **分屏需求**：4-16 路
- **特殊需求**：PTZ 云台控制、Canvas 画框叠加 AI 检测结果

**完整链路**：
```
海康/大华摄像头 → RTSP 推流到流媒体服务器（SRS/ZLMediaKit）
                ↓
```

**jessibuca 解决的问题**：

#### 场景 3：直播平台（HTTP-FLV 低延迟）

**技术特征**：
- **推流端**：OBS/FFmpeg/移动端 SDK
- **传输协议**：RTMP → HTTP-FLV
- **编码格式**：H.264（兼容性优先）

**完整链路**：
```

           ↓
    SRS 输出 HTTP-FLV
           ↓
    浏览器（jessibuca 播放）
```

**jessibuca 解决的问题**：
- ✅ **低延迟播放**：`videoBuffer: 0.2` + `videoBufferDelay: 1.0` 追帧策略
- ✅ **断线重连**：网络波动时自动重连（指数退避）
- ✅ **性能统计**：实时显示 FPS、码率、丢帧数

**实际案例**：电商直播、教育直播、企业内训直播，观众端延迟 1-2 秒，可实时互动。

#### 场景 4：车载监控（4G/5G 实时回传）

**技术特征**：
- **网络环境**：4G/5G 移动网络（带宽不稳定）
- **编码格式**：H.265（节省流量）
- **分屏需求**：4-6 路（车内多角度摄像头）

```

```

**jessibuca 解决的问题**：
- ✅ **H.265 软解**：车载设备为节省流量大量使用 H.265
- ✅ **弱网优化**：`videoBuffer` 可调，适应网络波动
- ✅ **水印叠加**：内置 `watermarkConfig`，显示车牌号、时间戳

**实际案例**：网约车监管、公交/出租车调度、物流车队管理，4 路车载摄像头（前后左右）实时回传。

#### 场景 5：智能家居摄像头

- **设备类型**：WiFi 摄像头（小米/萤石/360）

- **平台要求**：移动端/微信环境兼容

**完整链路**：
```

```

**jessibuca 解决的问题**：
- ✅ **移动端兼容**：支持 iOS/Android 浏览器、微信环境
- ✅ **低功耗**：H.264 用 MSE 硬解，手机不发烫
- ✅ **操作按钮**：内置全屏/截图/录制按钮

**实际案例**：家庭安防、宠物看护、老人看护，用户通过微信小程序/H5 随时查看家中摄像头。

## 三、架构原理：MSE 硬解 + WASM 软解双模式

### 3.1 工作流程

```
┌──────────────────────────────────────────────────────────────┐
│  jessibuca 播放器                                             │
├──────────────────────────────────────────────────────────────┤
│  1. 接收流（HTTP-FLV / WebSocket-FLV）                       │
│     ↓                                                         │
│  2. FLV 解复用（提取视频/音频帧）                             │
│     ↓                                                         │
│  3. 检测编码格式（H.264 / H.265）                            │
│     ├─ H.264 且 useMSE=true → MSE 硬解（GPU 加速，低 CPU）   │
│     └─ H.265 或 MSE 不可用 → WASM 软解（CPU 解码）           │
│     ↓                                                         │
│  4. 渲染到 <video> 或 <canvas>                               │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 MSE 硬解模式（H.264）

**触发条件**：
- 配置 `useMSE: true`（默认开启）
- 流编码为 H.264
- 浏览器支持 MSE API

**优势**：
- CPU 占用极低（GPU 硬件加速）
- 16 路 H.264 流同时播放，CPU 占用 < 30%

**限制**：
- 只支持 H.264，不支持 H.265
- 浏览器并发数限制（Chrome ≈ 8 个 video 实例）

### 3.3 WASM 软解模式（H.264/H.265）

**触发条件**：
- 配置 `useMSE: false`
- 或流编码为 H.265
- 或 MSE API 不可用

**优势**：
- **支持 H.265**（关键优势）
- 不受浏览器并发数限制
- 可渲染到 Canvas（方便叠加 AI 检测框）

**代价**：
- CPU 占用高（H.265 软解：单路 20-40% CPU）
- 4 路 H.265 软解即可能卡顿（取决于 CPU 性能）

### 3.4 自动降级策略

```javascript
// jessibuca 内部逻辑（简化）
if (useMSE && codec === 'h264' && isMSESupported()) {
  // 使用 MSE 硬解
  decoder = new MSEDecoder();
} else {
  // 降级到 WASM 软解
  decoder = new WASMDecoder();
}
```

**最佳实践**：
- **H.264 流**：开启 `useMSE: true`，优先使用硬解
- **H.265 流**：jessibuca 自动切换到 WASM 软解
- **混合场景**：前 8 路 H.264 用 MSE，后续路或 H.265 用 WASM

## 五、核心配置详解

### 5.1 容器与渲染配置

```javascript
{
  container: document.getElementById('video-container'),  // 必填：DOM 容器
  isResize: false,  // 是否自动缩放画面（false = 保持原始比例）
  isFullResize: false,  // 全屏时是否拉伸（false = 保持比例）
  isFlv: true,  // 是否为 FLV 流（自动检测，一般无需设置）
}
```

### 5.2 解码模式配置

```javascript
{
  useMSE: true,   // 优先使用 MSE 硬解（H.264）
  useWCS: true,   // 启用 WASM 软解（H.265 回退）
  useSIMD: true,  // 启用 SIMD 指令优化（WASM 性能提升 30%）
  useOffscreen: true,  // 使用 OffscreenCanvas（Worker 线程渲染）
  openWebglAlignment: false,  // WebGL 对齐优化（某些显卡需要开启）
}
```

**关键配置说明**：
- `useMSE: true` + `useWCS: true`：**推荐配置**，H.264 用硬解，H.265 自动降级软解
- `useSIMD: true`：**必须开启**，WASM 软解性能提升 30%（需要浏览器支持 SIMD）
- `useOffscreen: true`：解码在 Worker 线程，不阻塞主线程（推荐开启）

### 5.3 低延迟配置（核心）

```javascript
{
  videoBuffer: 0.2,  // 视频缓冲时长（秒），越小延迟越低，但可能卡顿
  videoBufferDelay: 1.0,  // 缓冲超过此值时触发追帧（丢弃旧帧）
  
  // 追帧策略（重要）
  hasAudio: false,  // 是否有音频（监控流通常无音频，设为 false 可降低延迟）
  autoPlay: true,   // 自动播放（绕过浏览器自动播放策略，需用户交互）
  
  // 网络配置
  timeout: 10,  // 连接超时（秒）
  heartTimeout: 10,  // 心跳超时（秒）
  loadingTimeout: 10,  // 加载超时（秒）
}
```

**延迟优化建议**：
- **实时监控**：`videoBuffer: 0.2`，`videoBufferDelay: 1.0`（延迟 1-2s）
- **普通直播**：`videoBuffer: 0.5`，`videoBufferDelay: 2.0`（延迟 2-3s）
- **无音频流**：`hasAudio: false`（监控流大多无音频，必须设为 false）

## 六、生产级播放器封装

### 6.1 StreamPlayer 类（完整封装）

```javascript
class JessibucaPlayer {
  constructor(container, url, options = {}) {
    this.container = container;
    this.url = url;
    this.player = null;
    this.reconnectAttempts = 0;
    this.maxReconnectAttempts = options.maxReconnectAttempts || 5;
    this.destroyed = false;
    this.options = options;
  }

  init() {
    // 创建播放器实例
    this.player = new Jessibuca({
      container: this.container,
      
      // 解码配置
      useMSE: true,
      useWCS: true,
      useSIMD: true,
      useOffscreen: true,
      
      // 低延迟配置
      videoBuffer: this.options.videoBuffer || 0.2,
      videoBufferDelay: this.options.videoBufferDelay || 1.0,
      hasAudio: this.options.hasAudio || false,
      
      // 渲染配置
      isResize: false,
      isFullResize: false,
      
      // 网络配置
      timeout: 10,
      heartTimeout: 10,
      loadingTimeout: 10,
      
      // UI 配置
      loadingText: '加载中...',
      showBandwidth: true,
      operateBtns: {
        fullscreen: true,
        screenshot: true,
        play: true,
        audio: false,  // 监控流通常无音频
      },
      
      // 调试
      debug: false,
    });

    // 绑定事件
    this.bindEvents();

    // 开始播放
    this.player.play(this.url);
  }

  bindEvents() {
    // 播放成功
    this.player.on('play', () => {
      console.log('播放成功');
      this.reconnectAttempts = 0;  // 重置重连计数
    });

    // 播放暂停
    this.player.on('pause', () => {
      console.log('播放暂停');
    });

    // 流信息
    this.player.on('streamInfo', (info) => {
      console.log('流信息:', info);
      // info = { width, height, encType: 'h264' or 'h265' }
    });

    // 性能统计
    this.player.on('performance', (stats) => {
      // stats = { fps, bitrate, packetLoss, decodeType: 'mse' or 'wasm' }
      if (this.options.onPerformance) {
        this.options.onPerformance(stats);
      }
    });

    // 错误处理
    this.player.on('error', (error) => {
      console.error('播放错误:', error);
      this.handleError(error);
    });

    // 超时
    this.player.on('timeout', () => {
      console.warn('连接超时');
      this.reconnect();
    });

    // kBps（实时码率）
    this.player.on('kBps', (kbps) => {
      // console.debug('码率:', kbps, 'kB/s');
    });
  }

  handleError(error) {
    if (this.destroyed) return;

    // 解析错误类型
    const errorMessage = error.message || error;
    
    if (errorMessage.includes('fetch') || errorMessage.includes('network')) {
      // 网络错误，尝试重连
      this.reconnect();
    } else if (errorMessage.includes('decode')) {
      // 解码错误，可能是编码格式不支持
      console.error('解码失败，请检查流编码格式');
      if (this.options.onError) {
        this.options.onError('DECODE_ERROR', error);
      }
    } else {
      // 其他错误
      console.error('未知错误:', error);
      if (this.options.onError) {
        this.options.onError('UNKNOWN_ERROR', error);
      }
    }
  }

  reconnect() {
    if (this.destroyed) return;

    if (this.reconnectAttempts >= this.maxReconnectAttempts) {
      console.error('达到最大重连次数');
      if (this.options.onReconnectFailed) {
        this.options.onReconnectFailed();
      }
      return;
    }

    this.destroy();

    // 指数退避
    const delay = Math.min(1000 * Math.pow(2, this.reconnectAttempts), 30000);
    console.log(`${delay}ms 后重连（第 ${this.reconnectAttempts + 1} 次）`);

    setTimeout(() => {
      this.reconnectAttempts++;
      this.init();
    }, delay);
  }

  destroy() {
    if (this.player) {
      try {
        this.player.pause();
        this.player.destroy();
      } catch (e) {
        console.warn('销毁播放器失败:', e);
      }
      this.player = null;
    }
  }

  dispose() {
    this.destroyed = true;
    this.destroy();
  }

  // 公开方法
  pause() {
    if (this.player) {
      this.player.pause();
    }
  }

  play(url) {
    if (url) {
      this.url = url;
    }
    if (this.player) {
      this.player.play(this.url);
    } else {
      this.init();
    }
  }

  screenshot() {
    if (this.player) {
      return this.player.screenshot();  // 返回 base64 图片
    }
    return null;
  }

  setVolume(volume) {
    if (this.player) {
      this.player.setVolume(volume);  // 0-1
    }
  }
}
```

### 7.1 MultiStreamManager 类

```javascript
class JessibucaMultiStreamManager {
  constructor() {
    this.players = new Map();  // streamID → JessibucaPlayer
  }

  addStream(streamID, container, url, options = {}) {
    // 如果已存在，先销毁
    if (this.players.has(streamID)) {
      this.removeStream(streamID);
    }

    const player = new JessibucaPlayer(container, url, {
      videoBuffer: 0.2,
      hasAudio: false,
      maxReconnectAttempts: 3,
      ...options,
      
      // 多路流性能回调（可选）
      onPerformance: (stats) => {
        // 收集所有流的性能数据，用于监控
        this.updateStreamStats(streamID, stats);
      },
    });

    try {
      player.init();
      this.players.set(streamID, player);
    } catch (err) {
      console.error(`初始化流 ${streamID} 失败:`, err);
    }
  }

  removeStream(streamID) {
    const player = this.players.get(streamID);
    if (player) {
      player.dispose();
      this.players.delete(streamID);
    }
  }

  // 按需激活：只播放可见的流
  pauseInvisibleStreams(visibleStreamIDs) {
    for (const [streamID, player] of this.players.entries()) {
      if (!visibleStreamIDs.includes(streamID)) {
        player.pause();
      }
    }
  }

  resumeVisibleStreams(visibleStreamIDs) {
    for (const streamID of visibleStreamIDs) {
      const player = this.players.get(streamID);
      if (player) {
        player.play();
      }
    }
  }

  // 收集所有流的性能统计
  updateStreamStats(streamID, stats) {
    // 存储到 Map 或上报到监控系统
    // stats = { fps, bitrate, packetLoss, decodeType }
  }

  getAllStats() {
    const stats = {};
    for (const [streamID, player] of this.players.entries()) {
      stats[streamID] = player.player ? {
        fps: player.player.fps || 0,
        bitrate: player.player.kBps || 0,
      } : null;
    }
    return stats;
  }

  destroyAll() {
    for (const player of this.players.values()) {
      player.dispose();
    }
    this.players.clear();
  }
}
```

## 八、性能优化策略

### 8.1 H.264 vs H.265 性能对比（实测数据）

**测试环境**：Chrome 125, Intel i7-12700, 16GB RAM

| 场景 | 编码格式 | 解码模式 | 单路 CPU 占用 | 16 路 CPU 占用 | 是否流畅 |
|------|---------|---------|--------------|---------------|---------|
| **场景 1** | H.264 | MSE 硬解 | < 2% | < 30% | ✅ 流畅 |
| **场景 2** | H.265 | WASM 软解 | 20-30% | > 350% | ❌ 卡顿 |
| **场景 3** | H.265 | WASM 软解 (SIMD) | 15-20% | > 250% | ❌ 卡顿 |
| **场景 4** | 混合（前 8 路 H.264 + 后 8 路 H.265） | 混合 | - | 150% | ⚠️ 勉强流畅 |

**结论**：
- **H.264 + MSE 硬解**：16 路无压力
- **H.265 + WASM 软解**：4 路即可能卡顿，16 路完全不可行
- **生产建议**：服务端统一转码为 H.264，或前端只播放关键机位（4-9 路）

### 8.2 降低 CPU 占用的方法

**方法 1：服务端转码为 H.264**（推荐）


## 九、Canvas 画框集成

### 9.1 为什么用 Canvas 而不是 CSS

**CSS 叠加的问题**：
- `<div>` 叠加在 `<video>` 上，全屏时可能丢失
- 无法精确同步视频帧（CSS 动画是 60fps，视频可能是 25fps）

**Canvas 叠加的优势**：
- 精确控制每一帧的绘制
- 与视频尺寸完全同步
- 可以绘制复杂的轨迹、热力图

### 9.2 Canvas 坐标系统同步

```javascript
class CanvasOverlay {
  constructor(videoContainer) {
    this.videoContainer = videoContainer;
    this.canvas = document.createElement('canvas');
    this.ctx = this.canvas.getContext('2d');
    
    // Canvas 绝对定位覆盖在 video 上
    this.canvas.style.position = 'absolute';
    this.canvas.style.top = '0';
    this.canvas.style.left = '0';
    this.canvas.style.pointerEvents = 'none';  // 不阻挡 video 的点击
    
    videoContainer.appendChild(this.canvas);
    
    this.syncSize();
  }

  syncSize() {
    // Canvas 分辨率 = 容器显示尺寸
    this.canvas.width = this.videoContainer.clientWidth;
    this.canvas.height = this.videoContainer.clientHeight;
    this.canvas.style.width = this.videoContainer.clientWidth + 'px';
    this.canvas.style.height = this.videoContainer.clientHeight + 'px';
  }

  drawBox(box) {
    // box = { x: 0.5, y: 0.3, w: 0.2, h: 0.3, label: 'person', confidence: 0.92 }
    // 坐标是 0-1 归一化坐标
    const pixelX = box.x * this.canvas.width;
    const pixelY = box.y * this.canvas.height;
    const pixelW = box.w * this.canvas.width;
    const pixelH = box.h * this.canvas.height;

    // 绘制矩形
    this.ctx.strokeStyle = box.confidence > 0.9 ? '#ff0000' : '#ffaa00';
    this.ctx.lineWidth = 2;
    this.ctx.strokeRect(pixelX, pixelY, pixelW, pixelH);

    // 绘制标签
    const label = `${box.label} ${(box.confidence * 100).toFixed(0)}%`;
    this.ctx.font = '14px Arial';
    const textWidth = this.ctx.measureText(label).width;

    this.ctx.fillStyle = this.ctx.strokeStyle;
    this.ctx.fillRect(pixelX, pixelY - 20, textWidth + 8, 20);

    this.ctx.fillStyle = '#ffffff';
    this.ctx.fillText(label, pixelX + 4, pixelY - 6);
  }

  clear() {
    this.ctx.clearRect(0, 0, this.canvas.width, this.canvas.height);
  }
}
```

## 十、常见问题排查

### 10.1 播放黑屏

| 现象 | 可能原因 | 解决方法 |
|------|---------|---------|
| **Chrome 黑屏** | H.265 流且 MSE 模式 | 检查 `useWCS: true` 是否开启 |
| **Firefox 黑屏** | CORS 跨域问题 | 服务端配置 CORS 头 |
| **移动端黑屏** | 浏览器不支持 WASM | 降级到 MSE 模式（仅 H.264） |
| **全黑且无错误** | 流地址错误 | 检查 Network 面板，确认流可访问 |

### 10.2 延迟过高（> 5s）

| 可能原因 | 解决方法 |
|---------|---------|
| `videoBuffer` 过大 | 降低到 0.2 秒 |
| 服务端 GOP 过大 | 要求服务端设置 GOP = 1-2s（关键帧间隔） |
| 网络带宽不足 | 降低码率或分辨率 |
| `hasAudio: true` 但流无音频 | 设为 `false`，避免等待音频同步 |

### 10.3 CPU 占用过高

| 现象 | 可能原因 | 解决方法 |
|------|---------|---------|
| 单路 H.264 CPU 30%+ | MSE 未生效 | 检查 `useMSE: true`，查看 `decodeType` |
| 单路 H.265 CPU 40%+ | WASM 软解正常 | 服务端转码为 H.264 |
| 16 路 H.264 CPU 100%+ | 浏览器并发数超限，降级为 WASM | 重启浏览器，或减少并发数 |

### 10.4 内存持续增长

| 可能原因 | 解决方法 |
|---------|---------|
| 切换流时未销毁旧播放器 | 调用 `player.dispose()` |
| Canvas 未清理 | 定期 `ctx.clearRect()` |
| WebSocket 未关闭 | 页面卸载时 `ws.close()` |

### 10.5 H.265 无法播放

```javascript
// 检查是否成功降级到 WASM 软解
player.on('performance', (stats) => {
  console.log('解码模式:', stats.decodeType);  // 应为 'wasm'
});

// 如果仍然黑屏，检查浏览器是否支持 WASM
if (!window.WebAssembly) {
  console.error('浏览器不支持 WebAssembly');
  // 降级方案：服务端转码为 H.264
}
```
