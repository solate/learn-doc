## 1. 录制策略概览

### 1.1 三种切片场景

```
┌─────────────────────────────────────────────────────────┐
│                   录制策略选择                            │
│                                                          │
│  按时长切片       适合：监控录制、比赛录制               │
│  ├── 每 30 分钟一个文件                                  │
│  └── 文件大小均匀，便于管理                              │
│                                                          │
│  按文件大小切片   适合：存储空间受限场景                  │
│  ├── 每个文件 ≤ 2GB                                     │
│  └── 跨 FAT32 文件系统必用                               │
│                                                          │
│  按时钟切片       适合：整点归档、SLA 对齐               │
│  ├── 00:00、01:00、02:00 等整点切换                      │
│  └── 文件名带时间戳，归档查询方便                        │
└─────────────────────────────────────────────────────────┘
```

### 1.2 容器格式选择

| 场景 | 推荐格式 | 理由 |
|------|----------|------|
| 普通录制存档 | MP4（+faststart）| 播放兼容性最好 |
| 直播实时切片 | TS | 无 moov box，断流不损坏 |
| 后处理场景 | MKV | 支持更多编解码器 |
| 上传 CDN | FLV | 历史兼容，体积较大 |

**TS vs MP4 的核心区别**：
- TS：流式格式，写一帧存一帧，断流不丢数据
- MP4：需要最后写 moov box，异常退出会导致文件损坏（需要修复工具）

## 2. 按时长切片（segment）

### 2.1 segment 复用器基础

```bash
# 每 600 秒（10分钟）切一个文件
ffmpeg -i rtmp://localhost:1935/live/stream \
  -c copy \
  -f segment \
  -segment_time 600 \
  -reset_timestamps 1 \
  "record_%03d.ts"

# 输出：record_000.ts, record_001.ts, record_002.ts ...
```

**关键参数**：

| 参数 | 说明 |
|------|------|
| `-f segment` | 启用切片复用器 |
| `-segment_time 600` | 每段时长（秒） |
| `-reset_timestamps 1` | 每段时间戳从 0 开始（独立播放必需） |
| `%03d` | 序号占位符，3 位补零 |

### 2.2 关键帧对齐问题

`segment` 只能在**关键帧**处切分，如果 GOP 过长，实际切片时长会偏离设定值：

```
设定 -segment_time 600（10分钟）
GOP = 10 秒（关键帧间隔）

实际切片点：
  600s 附近的关键帧 → 可能在 598s 或 605s
  偏差最大 = 1 个 GOP 时长
```

**解决方案：重新编码时强制关键帧**

```bash
# 每 600 秒强制插入关键帧，确保精确切片
ffmpeg -i rtmp://localhost:1935/live/stream \
  -c:v libx264 -preset veryfast \
  -force_key_frames "expr:gte(t,n_forced*600)" \
  -c:a aac \
  -f segment \
  -segment_time 600 \
  -reset_timestamps 1 \
  "record_%03d.mp4"
```

### 2.3 MP4 切片（需要 movflags）

```bash
# MP4 格式切片（每段独立可播放）
ffmpeg -i rtmp://localhost:1935/live/stream \
  -c copy \
  -f segment \
  -segment_time 1800 \
  -segment_format mp4 \
  -segment_format_options movflags=+faststart \
  -reset_timestamps 1 \
  "record_%03d.mp4"
```

**注意**：`-segment_format_options` 传递参数给子复用器，`movflags=+faststart` 让每段 MP4 的 moov box 前置。

### 2.4 切片列表文件

```bash
# 生成切片清单（便于后续拼接）
ffmpeg -i rtmp://localhost:1935/live/stream \
  -c copy \
  -f segment \
  -segment_time 600 \
  -segment_list "playlist.txt" \
  -segment_list_type ffconcat \
  -reset_timestamps 1 \
  "record_%03d.ts"

# playlist.txt 内容（ffconcat 格式）：
# ffconcat version 1.0
# file record_000.ts
# file record_001.ts
```

之后可以直接用 concat 复用器拼回完整文件：
```bash
ffmpeg -f concat -i playlist.txt -c copy full_record.mp4
```

## 3. 按文件大小切片

### 3.1 fs 复用器（按大小）

FFmpeg 的 `segment` 不直接支持按大小切分，但可以用 `-fs`（file size）配合循环：

```bash
# 单个文件限制 2GB（超出后停止）
ffmpeg -i rtmp://localhost:1935/live/stream \
  -c copy \
  -fs 2000000000 \
  record.ts
```

**限制**：`-fs` 达到上限后 FFmpeg 会退出，需要外部循环续录：

```bash
#!/bin/bash
# 按 2GB 切片的循环录制脚本
INDEX=0
while true; do
  FILENAME=$(printf "record_%03d.ts" $INDEX)
  echo "开始录制: $FILENAME"
  
  ffmpeg -i rtmp://localhost:1935/live/stream \
    -c copy \
    -fs 2000000000 \
    "$FILENAME"
  
  # 检查流是否还存在
  if ! ffprobe -v quiet -timeout 3000000 -i rtmp://localhost:1935/live/stream 2>/dev/null; then
    echo "流已结束，退出录制"
    break
  fi
  
  INDEX=$((INDEX + 1))
done
```

### 3.2 按码率估算时长

更可控的方案是**用码率反推时长**，转化为按时长切片：

```
目标文件大小 = 2GB = 16,000 Mbit
视频码率 = 3 Mbps，音频码率 = 0.128 Mbps
总码率 ≈ 3.128 Mbps

切片时长 = 16000 / 3.128 ≈ 5115 秒 ≈ 85 分钟
```

```bash
# 按估算时长切片（更稳定）
ffmpeg -i rtmp://localhost:1935/live/stream \
  -c copy \
  -f segment \
  -segment_time 5100 \
  -reset_timestamps 1 \
  "record_%03d.ts"
```

## 4. 按时钟切片（整点录制）

### 4.1 segment_atclocktime

`-segment_atclocktime 1` 让切片点对齐到时钟整数倍，这是监控和归档场景的标准做法：

```bash
# 每小时整点切一个文件
ffmpeg -i rtmp://localhost:1935/live/stream \
  -c copy \
  -f segment \
  -segment_time 3600 \
  -segment_atclocktime 1 \
  -strftime 1 \
  -reset_timestamps 1 \
  "record_%Y%m%d_%H%M%S.ts"

# 输出：
# record_20260728_100000.ts  （10:00 整）
# record_20260728_110000.ts  （11:00 整）
# record_20260728_120000.ts  （12:00 整）
```

**关键参数**：
- `-segment_atclocktime 1`：切片点对齐时钟（而非从启动时刻算）
- `-strftime 1`：文件名支持 strftime 时间格式化

### 4.2 strftime 格式符

| 格式符 | 含义 | 示例 |
|--------|------|------|
| `%Y` | 4 位年 | 2026 |
| `%m` | 2 位月 | 07 |
| `%d` | 2 位日 | 28 |
| `%H` | 24 小时制 | 14 |
| `%M` | 分钟 | 30 |
| `%S` | 秒 | 45 |
| `%s` | Unix 时间戳 | 1785312645 |
| `%j` | 一年中第几天 | 209 |

```bash
# 按日期目录组织录制文件
mkdir -p /var/rec/$(date +%Y%m%d)

ffmpeg -i rtmp://localhost:1935/live/stream \
  -c copy \
  -f segment \
  -segment_time 1800 \
  -segment_atclocktime 1 \
  -strftime 1 \
  -reset_timestamps 1 \
  "/var/rec/%Y%m%d/cam1_%H%M%S.ts"
```

### 4.3 每 15 分钟对齐切片

```bash
# 每 15 分钟切片，对齐到 :00 :15 :30 :45
ffmpeg -i rtsp://admin:pass@192.168.1.100:554/stream1 \
  -rtsp_transport tcp \
  -c copy \
  -f segment \
  -segment_time 900 \
  -segment_atclocktime 1 \
  -strftime 1 \
  -reset_timestamps 1 \
  "/var/rec/%Y%m%d/%H%M.ts"
```

## 5. 断点续录

### 5.1 问题：断流导致录制中断

直播推流不稳定时，FFmpeg 会退出，录制中断：

```
推流断开 → FFmpeg 退出 → 录制停止
重连推流 → 需手动重启 FFmpeg → 管理复杂
```

### 5.2 解决方案一：FFmpeg 内置重连

```bash
# FFmpeg 8.0+ 支持自动重连
ffmpeg -reconnect 1 \
  -reconnect_streamed 1 \
  -reconnect_delay_max 10 \
  -i rtmp://localhost:1935/live/stream \
  -c copy \
  -f segment \
  -segment_time 600 \
  -strftime 1 \
  -reset_timestamps 1 \
  "record_%Y%m%d_%H%M%S.ts"
```

**限制**：仅对**拉流**场景有效（RTMP/RTSP/HLS 输入），推流录制（本地文件 → RTMP）不支持。

### 5.3 解决方案二：Shell 循环重启

```bash
#!/bin/bash
# 监控录制脚本：FFmpeg 退出后自动重启

while true; do
  echo "[$(date)] 启动录制..."
  
  ffmpeg -i rtmp://localhost:1935/live/stream \
    -c copy \
    -f segment \
    -segment_time 1800 \
    -segment_atclocktime 1 \
    -strftime 1 \
    -reset_timestamps 1 \
    "/var/rec/%Y%m%d/stream_%H%M%S.ts"
  
  EXIT_CODE=$?
  echo "[$(date)] FFmpeg 退出，状态码: $EXIT_CODE"
  
  # 检查流是否还存在
  if ! ffprobe -v quiet -timeout 3000000 -i rtmp://localhost:1935/live/stream 2>/dev/null; then
    echo "[$(date)] 流不存在，10秒后重试..."
    sleep 10
  else
    echo "[$(date)] 流正常，立即重启录制"
  fi
done
```

### 5.4 解决方案三：Go 守护进程

```go
// Go 实现的录制守护服务（后文第 9 节有完整代码）
type RecordService struct {
    inputURL    string
    outputPattern string
    maxRetries  int
}

func (s *RecordService) StartWithRetry(ctx context.Context) error {
    retries := 0
    for {
        if err := s.record(ctx); err != nil {
            retries++
            if s.maxRetries > 0 && retries >= s.maxRetries {
                return fmt.Errorf("录制失败，重试次数达上限: %w", err)
            }
            time.Sleep(3 * time.Second)
            continue
        }
        return nil // 正常退出
    }
}
```

### 5.5 TS 格式的天然优势

**TS 格式不需要 moov box**，断流时不会损坏已写入的数据：

```
MP4 断流：
  ├── 已写入帧数据（mdat）
  └── ❌ 未写入 moov → 文件损坏，需修复工具

TS 断流：
  ├── 已写入帧数据
  └── ✅ 无全局索引，已写部分直接可播放
```

**最佳实践**：直播录制优先用 TS，存档时再转 MP4。

## 6. 多格式同时录制

### 6.1 tee 复用器：一次编码多路输出

```bash
# 同时输出 HLS + MP4 录制（共享编码结果）
ffmpeg -i rtmp://localhost:1935/live/stream \
  -c:v libx264 -preset veryfast -b:v 2M \
  -c:a aac -b:a 128k \
  -f tee -map 0:v -map 0:a \
  "[f=hls:hls_time=6:hls_list_size=5:hls_flags=delete_segments]/var/hls/live.m3u8|\
[f=segment:segment_time=1800:strftime=1:reset_timestamps=1]/var/rec/%Y%m%d_%H%M%S.mp4"
```

**tee 语法**：
```
[f=格式:参数1=值1:参数2=值2]路径|[f=格式:...]路径
```

**注意**：`|` 前后不能有空格。

### 6.2 多码率同时录制

```bash
# 高清录制 + 标清录制（不同码率）
ffmpeg -i rtmp://localhost:1935/live/stream \
  -filter_complex "[0:v]split=2[v1][v2]" \
  -map "[v1]" -c:v libx264 -b:v 4M -s 1920x1080 \
    -map 0:a -c:a aac -b:a 192k \
    -f mp4 /var/rec/hd_$(date +%H%M%S).mp4 \
  -map "[v2]" -c:v libx264 -b:v 1M -s 1280x720 \
    -map 0:a -c:a aac -b:a 128k \
    -f mp4 /var/rec/sd_$(date +%H%M%S).mp4
```

### 6.3 同时录制与推流

```bash
# 推 RTMP 的同时录制本地文件（流复制）
ffmpeg -re -i input.mp4 \
  -c copy \
  -f tee \
  "[f=flv]rtmp://live.example.com/live/stream|\
[f=segment:segment_time=3600:strftime=1]/var/rec/%Y%m%d_%H.ts"
```

## 7. 录制文件管理

### 7.1 存储容量估算

```
单路录制存储需求 = 码率 × 时长

1080p @ 4Mbps 录制 24 小时：
  4 Mbps × 86400s = 345,600 Mbit = 43.2 GB/天

监控场景 720p @ 2Mbps 录制 30 天：
  2 × 86400 × 30 = 5,184,000 Mbit = 648 GB
```

| 分辨率 | 码率 | 每小时 | 每天 | 30 天 |
|--------|------|--------|------|-------|
| 480p | 1 Mbps | 0.45 GB | 10.8 GB | 324 GB |
| 720p | 2 Mbps | 0.9 GB | 21.6 GB | 648 GB |
| 1080p | 4 Mbps | 1.8 GB | 43.2 GB | 1.3 TB |
| 4K | 15 Mbps | 6.75 GB | 162 GB | 4.9 TB |

### 7.2 自动清理过期文件

```bash
# 删除 30 天前的录制文件
find /var/rec -name "*.ts" -mtime +30 -delete

# 删除空目录
find /var/rec -type d -empty -delete

# crontab 定时清理（每天凌晨 3 点）
# 0 3 * * * find /var/rec -name "*.ts" -mtime +30 -delete
```

### 7.3 磁盘水位保护

```bash
#!/bin/bash
# 磁盘使用率超过 85% 时删除最老的文件
THRESHOLD=85
REC_DIR="/var/rec"

USAGE=$(df -h "$REC_DIR" | awk 'NR==2 {print $5}' | tr -d '%')

while [ "$USAGE" -gt "$THRESHOLD" ]; do
  OLDEST=$(find "$REC_DIR" -name "*.ts" -type f -printf '%T@ %p\n' | sort -n | head -1 | cut -d' ' -f2-)
  
  if [ -z "$OLDEST" ]; then
    echo "无可删除文件，磁盘仍然告警"
    break
  fi
  
  echo "删除最老文件: $OLDEST"
  rm -f "$OLDEST"
  
  USAGE=$(df -h "$REC_DIR" | awk 'NR==2 {print $5}' | tr -d '%')
done
```


## 9. Go 集成：录制服务

### 9.1 录制服务核心结构

```go
package record

import (
	"context"
	"fmt"
	"os"
	"os/exec"
	"path/filepath"
	"sync"
	"time"
)

// RecordConfig 录制配置
type RecordConfig struct {
	InputURL      string        // 输入流地址
	OutputDir     string        // 输出目录
	SegmentTime   int           // 切片时长（秒），0 = 不切片
	Format        string        // 输出格式：ts/mp4
	MaxRetries    int           // 最大重试次数（-1 无限）
	RetryDelay    time.Duration // 重试间隔
	AtClockTime   bool          // 是否整点对齐
	SnapshotDir   string        // 截图目录（空=不截图）
	SnapshotInterval int        // 截图间隔（秒）
}

// RecordService 录制服务
type RecordService struct {
	config  RecordConfig
	mu      sync.Mutex
	cmd     *exec.Cmd
	snapCmd *exec.Cmd
	cancel  context.CancelFunc
	running bool
}

// NewRecordService 创建录制服务
func NewRecordService(cfg RecordConfig) *RecordService {
	if cfg.MaxRetries == 0 {
		cfg.MaxRetries = -1
	}
	if cfg.RetryDelay == 0 {
		cfg.RetryDelay = 3 * time.Second
	}
	if cfg.Format == "" {
		cfg.Format = "ts"
	}
	return &RecordService{config: cfg}
}

// Start 启动录制（带自动重连）
func (s *RecordService) Start(ctx context.Context) error {
	ctx, cancel := context.WithCancel(ctx)
	
	s.mu.Lock()
	s.cancel = cancel
	s.running = true
	s.mu.Unlock()
	
	defer func() {
		s.mu.Lock()
		s.running = false
		s.mu.Unlock()
	}()
	
	// 启动截图协程
	if s.config.SnapshotDir != "" && s.config.SnapshotInterval > 0 {
		go s.startSnapshot(ctx)
	}
	
	retries := 0
	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}
		
		if err := s.record(ctx); err != nil {
			if ctx.Err() != nil {
				return ctx.Err()
			}
			retries++
			if s.config.MaxRetries > 0 && retries >= s.config.MaxRetries {
				return fmt.Errorf("录制重试次数达上限: %w", err)
			}
			
			select {
			case <-ctx.Done():
				return ctx.Err()
			case <-time.After(s.config.RetryDelay):
			}
			continue
		}
		return nil
	}
}
```

### 9.2 record 方法与截图

```go
// record 单次录制（segment 切片模式）
func (s *RecordService) record(ctx context.Context) error {
	cfg := s.config
	if err := os.MkdirAll(cfg.OutputDir, 0755); err != nil {
		return fmt.Errorf("创建录制目录失败: %w", err)
	}
	
	// 构建输出路径模板
	pattern := filepath.Join(cfg.OutputDir, "%Y%m%d_%H%M%S."+cfg.Format)
	
	args := []string{
		"-reconnect", "1",
		"-reconnect_streamed", "1",
		"-reconnect_delay_max", "10",
		"-i", cfg.InputURL,
		"-c", "copy",
	}
	
	if cfg.SegmentTime > 0 {
		args = append(args,
			"-f", "segment",
			"-segment_time", fmt.Sprintf("%d", cfg.SegmentTime),
			"-strftime", "1",
			"-reset_timestamps", "1",
		)
		if cfg.AtClockTime {
			args = append(args, "-segment_atclocktime", "1")
		}
		if cfg.Format == "mp4" {
			args = append(args, "-segment_format", "mp4", "-segment_format_options", "movflags=+faststart")
		}
	} else {
		// 不切片，直接录制单文件
		pattern = filepath.Join(cfg.OutputDir, time.Now().Format("20060102_150405")+"."+cfg.Format)
		if cfg.Format == "mp4" {
			args = append(args, "-movflags", "+faststart")
		}
	}
	
	args = append(args, pattern)
	
	cmd := exec.CommandContext(ctx, "ffmpeg", args...)
	s.mu.Lock()
	s.cmd = cmd
	s.mu.Unlock()
	
	return cmd.Run()
}

// startSnapshot 持续截图协程
func (s *RecordService) startSnapshot(ctx context.Context) {
	if err := os.MkdirAll(s.config.SnapshotDir, 0755); err != nil {
		return
	}
	
	// 覆盖式更新 latest.jpg + 定时归档
	latestPath := filepath.Join(s.config.SnapshotDir, "latest.jpg")
	
	cmd := exec.CommandContext(ctx, "ffmpeg",
		"-i", s.config.InputURL,
		"-vf", fmt.Sprintf("fps=1/%d", s.config.SnapshotInterval),
		"-update", "1",
		"-q:v", "2",
		"-y", latestPath,
	)
	
	s.mu.Lock()
	s.snapCmd = cmd
	s.mu.Unlock()
	
	cmd.Run() // 忽略错误（截图是辅助功能）
}

// Stop 停止录制
func (s *RecordService) Stop() {
	s.mu.Lock()
	defer s.mu.Unlock()
	
	if s.cancel != nil {
		s.cancel()
	}
}

// IsRunning 是否正在录制
func (s *RecordService) IsRunning() bool {
	s.mu.Lock()
	defer s.mu.Unlock()
	return s.running
}
```

### 9.3 录制文件清理服务

```go
// CleanupConfig 清理配置
type CleanupConfig struct {
	RecordDir   string
	MaxAgeDays  int     // 最大保留天数
	MaxDiskUsage float64 // 最大磁盘使用率（0-1）
}

// CleanupService 录制文件清理服务
type CleanupService struct {
	config CleanupConfig
}

// NewCleanupService 创建清理服务
func NewCleanupService(cfg CleanupConfig) *CleanupService {
	return &CleanupService{config: cfg}
}

// Run 执行清理（定时调用）
func (s *CleanupService) Run() error {
	// 1. 清理过期文件
	if s.config.MaxAgeDays > 0 {
		cutoff := time.Now().AddDate(0, 0, -s.config.MaxAgeDays)
		if err := s.deleteOlderThan(cutoff); err != nil {
			return fmt.Errorf("清理过期文件失败: %w", err)
		}
	}
	
	// 2. 磁盘水位保护
	if s.config.MaxDiskUsage > 0 {
		for s.diskUsage() > s.config.MaxDiskUsage {
			if err := s.deleteOldest(); err != nil {
				break
			}
		}
	}
	
	return nil
}

// diskUsage 获取目录所在磁盘使用率
func (s *CleanupService) diskUsage() float64 {
	var stat syscall.Statfs_t
	if err := syscall.Statfs(s.config.RecordDir, &stat); err != nil {
		return 0
	}
	total := stat.Blocks * uint64(stat.Bsize)
	free := stat.Bfree * uint64(stat.Bsize)
	if total == 0 {
		return 0
	}
	return float64(total-free) / float64(total)
}

// deleteOlderThan 删除指定时间前的文件
func (s *CleanupService) deleteOlderThan(cutoff time.Time) error {
	return filepath.Walk(s.config.RecordDir, func(path string, info os.FileInfo, err error) error {
		if err != nil || info.IsDir() {
			return nil
		}
		if info.ModTime().Before(cutoff) {
			return os.Remove(path)
		}
		return nil
	})
}

// deleteOldest 删除最旧的文件
func (s *CleanupService) deleteOldest() error {
	var oldest string
	var oldestTime time.Time
	
	filepath.Walk(s.config.RecordDir, func(path string, info os.FileInfo, err error) error {
		if err != nil || info.IsDir() {
			return nil
		}
		if oldest == "" || info.ModTime().Before(oldestTime) {
			oldest = path
			oldestTime = info.ModTime()
		}
		return nil
	})
	
	if oldest == "" {
		return fmt.Errorf("无可删除文件")
	}
	return os.Remove(oldest)
}
```

### 实验一：无视频文件的快速演示（10 秒切片）

**场景**：没有测试视频文件时，用 FFmpeg 生成测试流并快速验证录制切片功能。

**第一步：生成测试流并推送到 SRS**

```bash
# 生成彩条测试画面 + 1kHz 音频，推送到本地 SRS
ffmpeg -re -f lavfi -i testsrc=size=1280x720:rate=30 \
  -f lavfi -i sine=frequency=1000:sample_rate=44100 \
  -c:v libx264 -preset ultrafast -pix_fmt yuv420p \
  -c:a aac -f flv \
  rtmp://localhost:1935/live/stream
```

**第二步：启动录制切片（另开终端）**

```bash
# 创建输出目录
mkdir -p ./rtmp-record && cd ./rtmp-record

# 每 10 秒切一个文件（快速验证）
ffmpeg -i rtmp://localhost:1935/live/stream \
  -c copy \
  -f segment \
  -segment_time 10 \
  -reset_timestamps 1 \
  "record_%03d.ts"
```

**验证结果**（等待 30 秒后）：

```bash
# 查看生成的切片
ls -lh record_*.ts
# 输出：record_000.ts, record_001.ts, record_002.ts

# 查看第一个切片的时长
ffprobe -v error -show_entries format=duration \
  -of default=noprint_wrappers=1:nokey=1 record_000.ts
# 输出应接近 10.000000

# 播放验证
ffplay record_000.ts
```

**参数说明**：
- `-f lavfi -i testsrc`：生成测试图案（不依赖外部视频文件）
- `-f lavfi -i sine`：生成测试音频
- `-segment_time 10`：每 10 秒切一个文件（生产环境通常用 600-1800）
- `-c copy`：不重新编码，直接切片（性能最佳）

### 实验四：Go 录制服务启动

```go
package main

import (
	"context"
	"log"
	"os"
	"os/signal"
	"time"
)

func main() {
	svc := NewRecordService(RecordConfig{
		InputURL:         "rtmp://localhost:1935/live/stream",
		OutputDir:        "/tmp/rec",
		SegmentTime:      300,   // 5 分钟一个文件
		Format:           "ts",
		MaxRetries:       -1,
		RetryDelay:       3 * time.Second,
		AtClockTime:      true,
		SnapshotDir:      "/tmp/snapshots",
		SnapshotInterval: 30,    // 每 30 秒截图
	})
	
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()
	
	go func() {
		if err := svc.Start(ctx); err != nil && ctx.Err() == nil {
			log.Printf("录制异常退出: %v", err)
		}
	}()
	
	log.Println("录制已启动，Ctrl+C 停止")
	
	// 启动定时清理（每小时执行一次）
	cleanup := NewCleanupService(CleanupConfig{
		RecordDir:    "/tmp/rec",
		MaxAgeDays:   30,
		MaxDiskUsage: 0.85,
	})
	
	ticker := time.NewTicker(1 * time.Hour)
	defer ticker.Stop()
	
	go func() {
		for range ticker.C {
			if err := cleanup.Run(); err != nil {
				log.Printf("清理失败: %v", err)
			}
		}
	}()
	
	c := make(chan os.Signal, 1)
	signal.Notify(c, os.Interrupt)
	<-c
	
	svc.Stop()
	log.Println("录制已停止")
}
```

## 11. 本章总结

本章覆盖了直播录制从策略到实现的完整链路：

| 场景 | 推荐方案 | 关键参数 |
|------|----------|----------|
| 普通录制（整时长）| `-f segment -segment_time` | `-reset_timestamps 1` |
| 整点归档 | `-segment_atclocktime 1 -strftime 1` | `%Y%m%d_%H%M%S` |
| 断流不损坏 | 优先用 TS 格式 | 避免 MP4 断流损坏 |
| 直播 + 录制同步 | `-f tee` | 一次编码多路输出 |
| 定时截图 | `-vf fps=1/30 -update 1` | 覆盖式更新 latest.jpg |
| 磁盘保护 | Go CleanupService | `MaxAgeDays + MaxDiskUsage` |

**关键原则**：

1. **直播录制首选 TS 格式**：流式写入，断流不损坏，事后转 MP4 开销极低
2. **整点切片需 `-segment_atclocktime 1`**：否则切片点从启动时刻算，时间对不上
3. **tee 复用器是多路输出的最佳方案**：一次编码，节省 50%+ CPU
4. **必须有断流重连**：直播场景推流不稳定，任何录制服务都需要自动重连机制
5. **定时清理不可少**：设定 MaxAgeDays 和磁盘水位，避免磁盘打满
6. **MP4 合并前建 concat 清单**：`-f concat -safe 0` 速度接近流复制，不重新编码

## 12. 术语表

| 术语 | 说明 |
|------|------|
| segment 复用器 | FFmpeg 内置的切片输出复用器（`-f segment`）|
| segment_atclocktime | 切片时钟对齐参数，让切片点对准整分/整时 |
| strftime | Unix 时间格式化函数，用于生成带时间戳的文件名 |
| reset_timestamps | 每段时间戳从 0 开始，使切片独立可播 |
| tee 复用器 | 一路输入多路输出复用器，共享编解码结果 |
| moov box | MP4 容器的索引元数据，必须在文件写完后才生成 |
| faststart | MP4 的 moov box 前置优化，可边下边播 |
| ffconcat | FFmpeg 专用 concat 格式，用于合并切片 |
| VBV | Video Buffering Verifier，码率平滑控制缓冲 |
| GOP | Group of Pictures，关键帧间隔，影响切片精度 |
