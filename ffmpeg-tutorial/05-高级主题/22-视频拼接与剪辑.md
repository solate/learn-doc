## 1. 拼接与剪辑原理

### 1.1 两种拼接方式对比

```
concat demuxer（文件级拼接）：
  file1.mp4 ──┐
  file2.mp4 ──┤  demuxer 顺序读取  →  复用器  →  output.mp4
  file3.mp4 ──┘  不重编码（-c copy）    速度极快

  限制：所有文件必须编码参数完全相同（分辨率/帧率/编码器）

concat filter（帧级拼接）：
  file1.mp4 →  解码 → 帧序列 1 ─┐
  file2.mp4 →  解码 → 帧序列 2 ─┤→  concat → 重编码 → output.mp4
  file3.mp4 →  解码 → 帧序列 3 ─┘
  优势：支持不同分辨率/帧率/格式，可加转场
  代价：必须重编码，速度较慢
```

### 1.2 帧级精确剪辑 vs 关键帧剪辑

```
视频帧结构（GOP = Group of Pictures）：
  I─B─B─P─B─B─P─B─B─I─B─B─P...
  │               │           │
  关键帧          中间帧      下一关键帧
  (完整画面)      (只有差值)

问题：剪辑点落在 P/B 帧时，不重编码就无法精确裁剪

解决：
  快速模式（-c copy）：剪辑点自动向前对齐到最近关键帧
  精确模式（重编码）：先解码再按帧裁剪，但速度慢
  折中方案：input-seeking（-ss 在 -i 前）
```

## 2. concat demuxer 文件拼接

### 2.1 基础用法

```bash
# 创建 playlist.txt（每行 file 指定路径）
cat > playlist.txt << 'EOF'
file 'part1.mp4'
file 'part2.mp4'
file 'part3.mp4'
EOF

# 无损拼接（不重编码）
ffmpeg -f concat -safe 0 -i playlist.txt -c copy output.mp4

# -safe 0：允许绝对路径和 .. 路径（默认 1 只允许相对路径）
```

**⚠️ 常见问题：时间戳不连续导致元数据错误**

使用上面的基础用法拼接视频后，**文件大小正常**（接近输入文件之和），但播放器显示的**总时长异常**（如实际 46 秒的视频显示为 149 分钟）。

```bash
# 检查文件大小：正常（6.4M = 4.9M + 1.5M）
ls -lh *.mp4

# 检查元数据时长：异常
ffprobe -v error -show_entries format=duration -of csv=p=0 output.mp4
# 输出：538918.900000（约 149 分钟）—— 错误！

# 检查实际可播放内容：正常
ffmpeg -i output.mp4 -f null - 2>&1 | grep "time="
# 实际解码 46 秒视频内容
```

**根本原因**：不同来源的视频可能有**时间戳（PTS/DTS）不连续**的问题。比如一个 2026 年录制的 1920x1080 视频（时间基 1/30000）和一个 2015 年的 480x270 视频（时间基 1/1000），它们的时间戳起点和时间基不一致。`concat demuxer` 用 `-c copy` 直接拼接时，只是把数据流前后拼在一起，容器元数据的 `duration` 字段计算错误。

**这不是文件损坏**，只是容器元数据中的时长字段错了，实际视频和音频数据完全正常。

**解决方案 1：通过 TS 格式中转（推荐，无损）**

```bash
# 1. 转换为 TS 格式（保持编码不变）
ffmpeg -i video1.mp4 -c copy -bsf:v h264_mp4toannexb video1.ts
ffmpeg -i video2.mp4 -c copy -bsf:v h264_mp4toannexb video2.ts

# 2. 拼接 TS 并转回 MP4（自动修正时间戳）
ffmpeg -i "concat:video1.ts|video2.ts" -c copy -bsf:a aac_adtstoasc output_fixed.mp4

# 3. 清理临时文件
rm video1.ts video2.ts

# -bsf:v h264_mp4toannexb：H.264 从 MP4 格式转为 Annex B（TS 要求）
# -bsf:a aac_adtstoasc：AAC 从 ADTS 转回 ASC（MP4 要求）
```

TS 格式对时间戳容忍度更高，转回 MP4 时 ffmpeg 会重新生成正确的时间戳。**完全无损，速度快。**

**解决方案 2：重编码（最可靠但慢且有损）**

```bash
# 完全重编码，ffmpeg 会生成连续的时间戳
ffmpeg -f concat -safe 0 -i playlist.txt \
  -c:v libx264 -preset fast -crf 18 \
  -c:a aac -b:a 128k \
  output.mp4
```

**解决方案 3：concat filter（适合异构视频）**

如果视频分辨率/帧率本来就不同，直接用 concat filter（见第 3 节）。

**验证修复结果**：

```bash
# 元数据时长和实际解码时长应该一致（误差 < 1 秒）
ffprobe -v error -show_entries format=duration -of csv=p=0 output_fixed.mp4
ffmpeg -i output_fixed.mp4 -f null - 2>&1 | grep "time="
```

### 2.2 playlist.txt 完整语法

#### 问题现象

使用 `concat demuxer` + `-c copy` 拼接视频后，**文件大小正常**（接近输入文件之和），但播放器显示的**总时长异常**（如实际 46 秒的视频显示为 149 分钟）。

```bash
# 拼接两个视频
ffmpeg -f concat -safe 0 -i playlist.txt -c copy output.mp4

# 检查文件大小：正常（6.4M = 4.9M + 1.5M）
ls -lh *.mp4

# 检查元数据时长：异常
ffprobe -v error -show_entries format=duration -of csv=p=0 output.mp4
# 输出：538918.900000（约 149 分钟）—— 错误！

# 检查实际可播放内容：正常
ffmpeg -i output.mp4 -f null - 2>&1 | grep "time="
# 实际解码 46 秒视频内容
```

#### 根本原因

不同来源的视频可能有**时间戳（PTS/DTS）不连续**的问题：

```
video1.mp4（2026 年录制）：
  PTS 从 0 开始，时间基 1/30000

video2.mp4（2015 年录制）：
  PTS 从 0 开始，时间基 1/1000，时间戳跳变

concat demuxer 用 -c copy 直接拼接：
  → 只是把数据流前后拼在一起
  → 容器元数据的 duration 字段计算错误
  → 实际视频数据是对的，但播放器读到错误的总时长
```

**这不是文件损坏**，只是容器元数据（MP4 的 `moov` atom）中的时长字段计算错了，实际视频和音频数据完全正常。

#### 解决方案 1：通过 TS 格式中转（推荐）

TS 格式对时间戳容忍度更高，转 TS → 拼接 → 转回 MP4 时 ffmpeg 会重新生成时间戳：

```bash
# 1. 转换为 TS 格式（保持编码不变）
ffmpeg -i video1.mp4 -c copy -bsf:v h264_mp4toannexb video1.ts
ffmpeg -i video2.mp4 -c copy -bsf:v h264_mp4toannexb video2.ts

# 2. 拼接 TS 并转回 MP4（自动修正时间戳）
ffmpeg -i "concat:video1.ts|video2.ts" -c copy -bsf:a aac_adtstoasc output_fixed.mp4

# 3. 清理临时文件
rm video1.ts video2.ts

# -bsf:v h264_mp4toannexb：将 H.264 从 MP4 格式转为 Annex B 格式（TS 要求）
# -bsf:a aac_adtstoasc：将 AAC 从 ADTS 格式转回 ASC 格式（MP4 要求）
```

**优点**：
- 完全无损（不重编码）
- 自动修正时间戳，元数据正确
- 速度快（只有流格式转换开销）

#### 解决方案 2：重编码（最可靠但慢）

```bash
# 完全重编码，ffmpeg 会生成连续的时间戳
ffmpeg -f concat -safe 0 -i playlist.txt \
  -c:v libx264 -preset fast -crf 18 \
  -c:a aac -b:a 128k \
  output.mp4
```

**权衡**：
- 优点：100% 可靠，时间戳完全连续
- 缺点：有损（重新编码），速度慢（取决于视频时长）

#### 解决方案 3：concat filter（适合异构视频）

如果视频分辨率/帧率本来就不同，直接用 concat filter 统一参数后拼接：

```bash
ffmpeg -i video1.mp4 -i video2.mp4 \
  -filter_complex "
    [0:v]scale=1920:1080:force_original_aspect_ratio=decrease,
         pad=1920:1080:(ow-iw)/2:(oh-ih)/2,fps=30[v0];
    [1:v]scale=1920:1080:force_original_aspect_ratio=decrease,
         pad=1920:1080:(ow-iw)/2:(oh-ih)/2,fps=30[v1];
    [v0][0:a][v1][1:a]concat=n=2:v=1:a=1[vout][aout]
  " \
  -map "[vout]" -map "[aout]" \
  -c:v libx264 -preset medium -crf 20 -c:a aac output.mp4
```

#### 如何选择

```
concat demuxer 拼接后时长异常
  │
  ├─ 所有视频编码参数完全相同？
  │    ├─ 是 → 方案 1（TS 中转，无损 + 修正时间戳）
  │    └─ 否 → 方案 3（concat filter + 统一参数）
  │
  └─ 对质量要求极高（专业后期）？
       └─ 方案 2（重编码，最可靠但慢）
```

#### 验证修复结果

```bash
# 检查元数据时长
ffprobe -v error -show_entries format=duration -of csv=p=0 output_fixed.mp4

# 检查实际可播放时长（解码全部帧）
ffmpeg -i output_fixed.mp4 -f null - 2>&1 | grep "time="

# 两个时长应该一致（误差 < 1 秒）
```

## 3. concat filter 流式拼接

### 3.1 基础 concat filter

```bash
# 两个视频流式拼接（必须解码重编码）
ffmpeg -i part1.mp4 -i part2.mp4 \
  -filter_complex "[0:v][0:a][1:v][1:a]concat=n=2:v=1:a=1[vout][aout]" \
  -map "[vout]" -map "[aout]" \
  -c:v libx264 -preset fast -crf 20 \
  -c:a aac -b:a 128k \
  output.mp4

# n=2: 拼接 2 个输入
# v=1: 1 路视频输出
# a=1: 1 路音频输出
```

### 3.2 自动统一分辨率后拼接

```bash
# 不同分辨率的视频统一为 1280x720 后拼接
ffmpeg -i video_1080p.mp4 -i video_720p.mp4 -i video_480p.mp4 \
  -filter_complex "
    [0:v]scale=1280:720:force_original_aspect_ratio=decrease,
         pad=1280:720:(ow-iw)/2:(oh-ih)/2,fps=30[v0];
    [1:v]scale=1280:720:force_original_aspect_ratio=decrease,
         pad=1280:720:(ow-iw)/2:(oh-ih)/2,fps=30[v1];
    [2:v]scale=1280:720:force_original_aspect_ratio=decrease,
         pad=1280:720:(ow-iw)/2:(oh-ih)/2,fps=30[v2];
    [v0][0:a][v1][1:a][v2][2:a]concat=n=3:v=1:a=1[vout][aout]
  " \
  -map "[vout]" -map "[aout]" \
  -c:v libx264 -preset medium -crf 20 \
  -c:a aac -b:a 128k \
  output.mp4
```

### 3.3 无音频视频的拼接（补静音轨）

```bash
# 部分视频无音频轨时，用 anullsrc 生成静音
ffmpeg -i with_audio.mp4 -i no_audio.mp4 \
  -f lavfi -t 0.1 -i anullsrc=channel_layout=stereo:sample_rate=44100 \
  -filter_complex "
    [0:v][0:a][1:v][2:a]concat=n=2:v=1:a=1[vout][aout]
  " \
  -map "[vout]" -map "[aout]" \
  -c:v libx264 -crf 20 -c:a aac output.mp4
```

### 3.4 两种拼接方式选择决策

```
需要拼接视频
  │
  ├─ 所有文件编码参数完全相同？（分辨率/帧率/编码器/采样率）
  │    │
  │    ├─ 是 → concat demuxer + -c copy（秒级完成，无损）
  │    │
  │    └─ 否 → 需要转场效果吗？
  │              ├─ 是 → xfade filter（见第 5 节）
  │              └─ 否 → concat filter（统一 scale/fps 后拼接）
  │
  └─ 文件数量 > 100？
       └─ 优先 concat demuxer（filter 的输入数量有上限）
```

## 4. 精确裁剪与分割

### 4.1 -ss 位置的关键区别

```
input seeking（-ss 在 -i 前）：
  ffmpeg -ss 60 -i input.mp4 -t 30 -c copy out.mp4
  → 先跳转到 60s 再解封装，速度极快（毫秒级）
  → 剪辑点自动对齐到最近的关键帧（可能偏移 0~GOP时长）

output seeking（-ss 在 -i 后）：
  ffmpeg -i input.mp4 -ss 60 -t 30 -c copy out.mp4
  → 从头解封装到 60s 再输出，慢（大文件几十秒）
  → 精度更高，但 -c copy 时依然受关键帧限制

精确裁剪（重编码）：
  ffmpeg -ss 60 -i input.mp4 -t 30 -c:v libx264 -crf 18 -c:a aac out.mp4
  → 帧级精确，但需要重编码
```

#### 三种模式详细对比

**第一种（output seeking，-ss 在 -i 后）：**

```bash
ffmpeg -i input.mp4 -ss 60 -t 30 -c copy out.mp4
```

- 从头**读取**（不是解码）到60秒
- 如果用 `-c copy`，**不解码**，只是读取数据包
- 慢是因为要读取大量不需要的数据

**第二种（精确模式/重编码）：**

```bash
ffmpeg -i input.mp4 -ss 60 -t 30 -c:v libx264 out.mp4
# 或
ffmpeg -ss 60 -i input.mp4 -t 30 -c:v libx264 out.mp4
```

- 不是"全部重新解码"
- 而是：读到60秒 → **解码这30秒** → 重新编码输出
- 慢是因为有解码+编码的计算开销

**第三种（input seeking，-ss 在 -i 前）：**

```bash
ffmpeg -ss 60 -i input.mp4 -t 30 -c copy out.mp4
```

- **直接跳到60秒附近**（利用文件索引）
- 如果用 `-c copy`，跳过去后**不解码**，直接复制数据包
- 快是因为跳过了前60秒的数据读取

#### -ss 位置对比表

| 命令 | 从哪开始？ | 对齐关键帧？ | 速度 |
|------|-----------|-------------|------|
| `ffmpeg -i input.mp4 -c copy out.mp4` | 从 0 秒开始 | 不涉及 | 快（无跳转） |
| `ffmpeg -i input.mp4 -ss 60 -c copy out.mp4` | 从头读到60秒 | 是 | 慢（读取大量数据） |
| `ffmpeg -ss 60 -i input.mp4 -c copy out.mp4` | 从 58/61 秒（最近的关键帧） | 是 | **极快**（索引跳转） |
| `ffmpeg -ss 60 -i input.mp4 -c:v libx264 out.mp4` | 精确从 60.000 秒 | 否（重编码） | 中等（跳转快但需编码） |

#### -ss 不仅用于剪辑

`-ss` 可以用在**任何需要跳过开头的场景**，不限于剪辑：

```bash
# 转码（从1分钟开始转）
ffmpeg -ss 60 -i input.mp4 -c:v libx264 -crf 20 output.mp4

# 提取音频（从30秒开始）
ffmpeg -ss 30 -i video.mp4 -vn -c:a copy audio.aac

# 截图（截取第10秒的帧）
ffmpeg -ss 10 -i video.mp4 -frames:v 1 thumb.jpg

# 加水印（只给后半段加水印）
ffmpeg -ss 120 -i input.mp4 -i logo.png -filter_complex overlay output.mp4
```

只要**不需要处理视频开头部分**，就可以用 `-ss` 跳过，节省时间。

### 4.2 常用剪辑命令

```bash
# 1. 快速无损裁剪（从 1:30 开始，取 30 秒）
ffmpeg -ss 00:01:30 -i input.mp4 -t 30 -c copy -avoid_negative_ts make_zero output.mp4

# 2. 指定起止时间（-to 是绝对结束时间，-t 是时长）
ffmpeg -ss 00:01:30 -to 00:02:00 -i input.mp4 -c copy output.mp4

# 3. 帧级精确裁剪（重编码）
ffmpeg -ss 00:01:30.500 -i input.mp4 -t 30 \
  -c:v libx264 -preset medium -crf 18 \
  -c:a aac -b:a 128k output.mp4

# 4. 混合模式（快速跳转 + 精确起点）
# 先粗跳到 88s（关键帧前），再精确裁剪 2s
ffmpeg -ss 88 -i input.mp4 -ss 2 -t 30 \
  -c:v libx264 -crf 18 -c:a aac output.mp4

# 5. 去掉视频开头（跳过片头）
ffmpeg -ss 00:00:15 -i input.mp4 -c copy -avoid_negative_ts make_zero output.mp4

# 6. 去掉视频结尾（保留前 N 秒）
DURATION=$(ffprobe -v error -show_entries format=duration -of csv=p=0 input.mp4)
KEEP=$(echo "$DURATION - 20" | bc)  # 去掉最后 20 秒
ffmpeg -i input.mp4 -t "$KEEP" -c copy output.mp4
```

### 4.3 -avoid_negative_ts 的作用

```
问题：-c copy 剪辑后，第一帧的 PTS 可能是负数或非零
      → 部分播放器开头黑屏/音画不同步

解决：-avoid_negative_ts make_zero
      → 把第一帧 PTS 重置为 0，后续帧相应偏移

```

## 5. 转场特效

### 5.1 xfade 滤镜（交叉转场）

**基础用法（仅适用于相同分辨率和帧率的视频）**：

```bash
# 两段视频交叉溶解转场（1 秒转场）
# 前提：part1.mp4 和 part2.mp4 的分辨率、帧率、时间基完全相同
# offset = 第一段时长 - 转场时长
ffmpeg -i part1.mp4 -i part2.mp4 \
  -filter_complex "
    [0:v][1:v]xfade=transition=fade:duration=1:offset=9[vout];
    [0:a][1:a]acrossfade=d=1[aout]
  " \
  -map "[vout]" -map "[aout]" \
  -c:v libx264 -preset medium -crf 20 -c:a aac output.mp4
```

**⚠️ 常见问题：分辨率或时间基不匹配**

如果两个视频的**分辨率不同**（如 1920x1080 和 480x270）或**时间基不同**（如一个是 1/30，另一个是 1/1000000），上面的命令会报错：

```
[Parsed_xfade_0] First input link main parameters (size 1920x1080) 
do not match the corresponding second input link xfade parameters (size 480x270)
```

或：

```
[Parsed_xfade_0] First input link main timebase (1/1000000) 
do not match the corresponding second input link xfade timebase (1/30)
```

**实际可用的命令（统一分辨率、帧率、时间基）**：

```bash
# 适用于任意分辨率/帧率的两个视频
ffmpeg -i video1.mp4 -i video2.mp4 \
  -filter_complex "
    [0:v]scale=1920:1080:force_original_aspect_ratio=decrease,
         pad=1920:1080:(ow-iw)/2:(oh-ih)/2,fps=30,setpts=PTS-STARTPTS[v0];
    [1:v]scale=1920:1080:force_original_aspect_ratio=decrease,
         pad=1920:1080:(ow-iw)/2:(oh-ih)/2,fps=30,setpts=PTS-STARTPTS[v1];
    [v0][v1]xfade=transition=fade:duration=1:offset=15[vout];
    [0:a][1:a]acrossfade=d=1[aout]
  " \
  -map "[vout]" -map "[aout]" \
  -c:v libx264 -preset medium -crf 20 -c:a aac output.mp4

# scale=1920:1080：统一分辨率
# force_original_aspect_ratio=decrease：保持宽高比不变形
# pad=...：加黑边居中（如果缩放后尺寸不够）
# fps=30：统一帧率
# setpts=PTS-STARTPTS：重置时间戳，统一时间基
# offset=15：假设第一段 16 秒，offset = 16-1 = 15
```

如果要用较小的分辨率输出（减少文件大小），把两处 `1920:1080` 改成 `1280:720` 或 `480:270`。

**xfade 常用转场类型**：

| transition | 效果 |
|------------|------|
| `fade` | 交叉溶解（最常用） |
| `fadeblack` | 经过黑场过渡 |
| `fadewhite` | 经过白场过渡 |
| `wipeleft` / `wiperight` | 左/右擦除 |
| `wipeup` / `wipedown` | 上/下擦除 |
| `slideleft` / `slideright` | 左/右滑动推入 |
| `circleopen` / `circleclose` | 圆形开合 |
| `dissolve` | 像素随机溶解 |
| `pixelize` | 马赛克过渡 |
| `radial` | 径向扫描 |

### 5.2 淡入淡出（单视频头尾）

```bash
# 视频开头淡入 1s，结尾淡出 2s（假设视频总长 60s）
ffmpeg -i input.mp4 \
  -vf "fade=t=in:st=0:d=1,fade=t=out:st=58:d=2" \
  -af "afade=t=in:st=0:d=1,afade=t=out:st=58:d=2" \

FADE_OUT_START=$(echo "$DURATION - 2" | bc)
ffmpeg -i input.mp4 \
  -vf "fade=t=in:st=0:d=1,fade=t=out:st=$FADE_OUT_START:d=2" \
  -af "afade=t=in:st=0:d=1,afade=t=out:st=$FADE_OUT_START:d=2" \
  -c:v libx264 -crf 20 -c:a aac output.mp4
```

### 5.3 多段视频串联转场

```bash
# 3 段视频，每段 10s，转场 1s
# offset1 = 10-1 = 9
# offset2 = 9 + 10 - 1 = 18
ffmpeg -i clip1.mp4 -i clip2.mp4 -i clip3.mp4 \
  -filter_complex "
    [0:v][1:v]xfade=transition=fade:duration=1:offset=9[v01];
    [v01][2:v]xfade=transition=wipeleft:duration=1:offset=18[vout];
    [0:a][1:a]acrossfade=d=1[a01];
    [a01][2:a]acrossfade=d=1[aout]
  " \
  -map "[vout]" -map "[aout]" \
  -c:v libx264 -preset medium -crf 20 -c:a aac output.mp4
```

**offset 累加公式**：
```
offset[n] = Σ(前 n 段时长) - n × 转场时长
```

### 6.1 视频变速（setpts）

```bash
# 2 倍速（时间缩短一半）
```

**setpts 与 atempo 的关系**：

| 效果 | setpts | atempo | 说明 |
|------|--------|--------|------|
| 2x 快 | `0.5*PTS` | `2.0` | 时长减半 |
| 4x 快 | `0.25*PTS` | `2.0,atempo=2.0` | atempo 单次上限 2.0 |
| 0.5x 慢 | `2.0*PTS` | `0.5` | 时长翻倍 |
| 0.25x 慢 | `4.0*PTS` | `0.5,atempo=0.5` | atempo 单次下限 0.5 |


```go
type TransitionType string

const (

	TransitionFade      TransitionType = "fade"

	TransitionSlideLeft TransitionType = "slideleft"
	TransitionDissolve  TransitionType = "dissolve"
)

// EditConfig 剪辑配置
type EditConfig struct {

	Transition     TransitionType

	FPS            int           // 统一帧率
	VideoBitrate   string        // 如 "3M"
	AudioBitrate   string        // 如 "128k"
	BGMPath        string        // 背景音乐（可选）

}

}

func NewEditor(ffmpegPath, tempDir string) *Editor {
	if ffmpegPath == "" {
		ffmpegPath = "ffmpeg"
	}
	if tempDir == "" {
		tempDir = os.TempDir()
	}
	return &Editor{ffmpegPath: ffmpegPath, tempDir: tempDir}
}
```

### 8.2 无损拼接（concat demuxer）

```go
// ConcatLossless 无损拼接（要求所有文件编码参数一致）
func (e *Editor) ConcatLossless(ctx context.Context, inputPaths []string, outputPath string) error {
	if len(inputPaths) == 0 {
		return fmt.Errorf("输入文件列表为空")
	}

	// 生成临时 playlist 文件
	playlistPath := filepath.Join(e.tempDir, fmt.Sprintf("concat_%d.txt", time.Now().UnixNano()))
	var sb strings.Builder
	for _, p := range inputPaths {
		abs, err := filepath.Abs(p)
		if err != nil {
			return fmt.Errorf("解析路径失败: %w", err)
		}
		// 单引号内的单引号需转义为 '\''
		escaped := strings.ReplaceAll(abs, "'", `'\''`)
		sb.WriteString(fmt.Sprintf("file '%s'\n", escaped))
	}
	if err := os.WriteFile(playlistPath, []byte(sb.String()), 0o600); err != nil {
		return fmt.Errorf("写入 playlist 失败: %w", err)
	}
	defer os.Remove(playlistPath)

	args := []string{
		"-f", "concat", "-safe", "0",
		"-i", playlistPath,
		"-c", "copy",
		"-movflags", "+faststart",
		"-y", outputPath,
	}

	cmd := exec.CommandContext(ctx, e.ffmpegPath, args...)
	if out, err := cmd.CombinedOutput(); err != nil {
		return fmt.Errorf("无损拼接失败: %w\noutput: %s", err, string(out))
	}
	return nil
}
```

```go
// TrimSegment 剪辑单个片段（快速模式用 copy，精确模式重编码）
func (e *Editor) TrimSegment(ctx context.Context, seg ClipSegment, outputPath string, precise bool) error {
	args := []string{}

	// -ss 放在 -i 前实现快速 seek
	args = append(args, "-ss", formatDuration(seg.StartTime))
	args = append(args, "-i", seg.SourcePath)
	if seg.Duration > 0 {
		args = append(args, "-t", formatDuration(seg.Duration))
	}

	if precise {
		// 精确模式：重编码
		args = append(args,
			"-c:v", "libx264", "-preset", "medium", "-crf", "20",
			"-c:a", "aac", "-b:a", "128k")
	} else {
		// 快速模式：不重编码（剪辑点对齐关键帧）
		args = append(args, "-c", "copy", "-avoid_negative_ts", "make_zero")
	}

	args = append(args, "-y", outputPath)

	cmd := exec.CommandContext(ctx, e.ffmpegPath, args...)
	if out, err := cmd.CombinedOutput(); err != nil {
		return fmt.Errorf("剪辑片段失败: %w\noutput: %s", err, string(out))
	}
	return nil
}

// formatDuration 转换为 FFmpeg 时间格式 HH:MM:SS.mmm
func formatDuration(d time.Duration) string {
	total := d.Milliseconds()
	h := total / 3600000
	m := (total % 3600000) / 60000
	s := (total % 60000) / 1000
	ms := total % 1000
	return fmt.Sprintf("%02d:%02d:%02d.%03d", h, m, s, ms)
}
```

### 8.4 带转场的多片段拼接

```go
// ConcatWithTransition 带转场效果的拼接（需重编码）
func (e *Editor) ConcatWithTransition(ctx context.Context, cfg EditConfig) error {
	n := len(cfg.Segments)
	if n == 0 {
		return fmt.Errorf("片段列表为空")
	}
	if n == 1 {
		return e.TrimSegment(ctx, cfg.Segments[0], cfg.OutputPath, true)
	}

	args := []string{}
	// 每个片段作为独立输入，用 -ss/-t 裁剪
	for _, seg := range cfg.Segments {
		args = append(args, "-ss", formatDuration(seg.StartTime))
		if seg.Duration > 0 {
			args = append(args, "-t", formatDuration(seg.Duration))
		}
		args = append(args, "-i", seg.SourcePath)
	}

	var filters []string
	// 统一每路视频的分辨率和帧率
	for i := 0; i < n; i++ {
		filters = append(filters, fmt.Sprintf(
			"[%d:v]scale=%d:%d:force_original_aspect_ratio=decrease,"+
				"pad=%d:%d:(ow-iw)/2:(oh-ih)/2,fps=%d,setsar=1[v%d]",
			i, cfg.Width, cfg.Height, cfg.Width, cfg.Height, cfg.FPS, i))
	}

	transDur := cfg.TransitionDur.Seconds()
	if cfg.Transition == TransitionNone || transDur <= 0 {
		// 无转场：直接 concat
		var inputs strings.Builder
		for i := 0; i < n; i++ {
			inputs.WriteString(fmt.Sprintf("[v%d][%d:a]", i, i))
		}
		filters = append(filters, fmt.Sprintf("%sconcat=n=%d:v=1:a=1[vout][aout]", inputs.String(), n))
	} else {
		// 有转场：xfade 链式串联，offset 累加
		offset := cfg.Segments[0].Duration.Seconds() - transDur
		prev := "v0"
		for i := 1; i < n; i++ {
			outTag := fmt.Sprintf("vx%d", i)
			if i == n-1 {
				outTag = "vout"
			}
			filters = append(filters, fmt.Sprintf(
				"[%s][v%d]xfade=transition=%s:duration=%.2f:offset=%.2f[%s]",
				prev, i, cfg.Transition, transDur, offset, outTag))
			prev = outTag
			if i < n-1 {
				offset += cfg.Segments[i].Duration.Seconds() - transDur
			}
		}
		// 音频交叉淡化
		prevA := "0:a"
		for i := 1; i < n; i++ {
			outTag := fmt.Sprintf("ax%d", i)
			if i == n-1 {
				outTag = "aout"
			}
			filters = append(filters, fmt.Sprintf(
				"[%s][%d:a]acrossfade=d=%.2f[%s]", prevA, i, transDur, outTag))
			prevA = outTag
		}
	}

	args = append(args,
		"-filter_complex", strings.Join(filters, ";"),
		"-map", "[vout]", "-map", "[aout]",
		"-c:v", "libx264", "-preset", "medium", "-crf", "20",
		"-b:v", cfg.VideoBitrate,
		"-c:a", "aac", "-b:a", cfg.AudioBitrate,
		"-movflags", "+faststart",
		"-y", cfg.OutputPath)

	cmd := exec.CommandContext(ctx, e.ffmpegPath, args...)
	if out, err := cmd.CombinedOutput(); err != nil {
		return fmt.Errorf("带转场拼接失败: %w\noutput: %s", err, string(out))
	}
	return nil
}
```

### 常见问题排查

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 拼接后音画不同步 | 各片段时间基不同 | concat filter + 重编码（不要用 -c copy） |
| xfade 黑屏闪烁 | offset 计算错误 | offset = Σ前段时长 - n×转场时长 |
| concat demuxer 报格式不匹配 | 各文件参数不同 | 先用 scale/fps 统一，或换用 concat filter |
| trim 后开头有黑帧 | 忘加 setpts=PTS-STARTPTS | 每个 trim 后必须加 setpts 重置时间戳 |
| -c copy 裁剪结果偏移 | 关键帧对齐 | 换用重编码模式（-c:v libx264）精确裁剪 |
| reverse 内存溢出 | 长视频全部读入内存 | 先用 -ss/-t 切成短片段再 reverse |

## 10. 本章总结

### 核心要点

1. **concat demuxer vs concat filter**：相同格式无损拼接用 demuxer（秒级），异构格式或需转场用 filter（需重编码）
2. **-ss 位置影响精度和速度**：-ss 在 -i 前快但偏关键帧，在 -i 后慢但略精确，重编码才能帧级精确
3. **trim 后必须 setpts=PTS-STARTPTS**：否则时间戳从原始值开始，导致输出有大段空白
4. **xfade offset 累加计算**：`offset[n] = Σ(前n段时长) - n × 转场时长`
5. **atempo 范围 0.5~2.0**：超出范围需串联多个 atempo 滤镜

### 剪辑场景速查

| 场景 | 推荐方案 |
|------|----------|
| 相同格式视频合并 | `concat demuxer` + `-c copy` |
| 不同格式视频合并 | `concat filter` + scale/fps 统一 |
| 单文件精确剪辑 | `trim` + `setpts` + 重编码 |
| 批量提取片段 | `-ss` + `-t` + `-c copy` |
| 两段视频溶解转场 | `xfade=transition=fade` + `acrossfade` |
| 视频加速/减速 | `setpts` + `atempo` 配合 |
| 多画面拼贴 | `xstack` 或 `hstack`+`vstack` |
| 替换背景音乐 | `-map 0:v -map 1:a` |

## 11. 术语表

| 术语 | 英文 | 解释 |

| 拼接 | Concatenation | 将多个视频片段首尾相接合并为一个文件 |
