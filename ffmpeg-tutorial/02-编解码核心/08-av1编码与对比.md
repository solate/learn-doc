## AV1 是什么？为什么重要？

### 背景

**专利费困境**：
- H.264、H.265 均需支付专利费
- H.265 专利联盟（MPEG LA、HEVC Advance、Velos Media）费用复杂，一度阻碍采用

**AV1 的诞生**：
- 2018 年由 **Alliance for Open Media（AOM）** 发布
- 成员：Google、Apple、Amazon、Netflix、Microsoft、Mozilla、Intel、ARM...
- 完全免费、开源、无专利费

---

### 设计目标

```
AV1 设计目标
├── 比 H.265 再节省 30% 码率
├── 免版权费（完全开放）
├── 针对 Web 和流媒体优化
├── 支持 8K、HDR、高帧率
└── 软件/硬件都能高效解码
```

**实际达成**：
- 相同质量：AV1 比 H.265 小 30%，比 H.264 小 60%
- **代价**：libaom-av1 编码极慢（比 libx265 慢 10-50 倍）

---

## AV1 技术特点

### 主要技术创新

```
┌──────────────────────────────────────────────────────────────┐
│ AV1 技术特点                                                  │
├──────────────────────────────────────────────────────────────┤
│ 1. 超块（Superblock）：128×128（H.265 最大 64×64）           │
│    → 大块区域（如天空、背景墙）更高效                          │
│                                                              │
│ 2. 更多预测模式：67 种帧内预测方向（H.265 仅 35 种）          │
│    → 细节纹理预测更精确                                       │
│                                                              │
│ 3. 复合预测（Compound Prediction）                            │
│    → 一个块可以由多个参考帧加权预测                           │
│                                                              │
│ 4. 环路滤波改进                                               │
│    - 去块效应（deblocking）                                   │
│    - 约束方向增强滤波器（CDEF）                               │
│    - 环路恢复滤波器（Loop Restoration Filter）                │
│    → 消除压缩伪影更彻底                                       │
│                                                              │
│ 5. 无损压缩支持                                               │
│ 6. 透明度（Alpha 通道）支持                                   │
│ 7. 高比特率（10/12-bit）和 HDR 原生支持                      │
└──────────────────────────────────────────────────────────────┘
```

---

### 代价：极高的编码复杂度

```
编码器速度（1 分钟 1080p30，Intel i9）

H.264 libx264 medium:   ████                           (3 分钟)
H.265 libx265 medium:   ████████████████               (15 分钟)
AV1 libaom medium:      ████████████████████████████████████████████████████ (300 分钟!!)
AV1 SVT-AV1 preset 6:   ████████                       (8 分钟) ← 实用方案
```

## libaom-av1 vs SVT-AV1

### 两个 AV1 编码器的定位

| 特性 | libaom-av1 | SVT-AV1（libsvtav1） |
|------|-----------|---------------------|
| 开发者 | Google/Mozilla（参考实现） | Intel/Netflix |
| 设计目标 | 最高质量，参考标准 | 实用生产环境 |
| 编码速度 | 极慢 | 快（medium 下~6-10x faster） |
| 质量 | 最高 | 略低（非常接近） |
| 并行支持 | 有限 | 优秀（多核利用率高） |
| CPU 利用率 | 低（单线程为主） | 高（多线程设计） |
| 典型使用 | 质量测试、长时间归档 | 生产环境、YouTube |
| FFmpeg 参数 | `-c:v libaom-av1` | `-c:v libsvtav1` |

---

### 关键结论

**libaom-av1**：
- 参考实现，质量最高
- 实际使用慢到不可接受（1 分钟视频编 2-5 小时）
- 适合：极度追求质量、不在乎时间的归档

**SVT-AV1**：
- Netflix/Intel 主导，专为生产环境设计
- 速度比 libaom 快 10-50 倍
- 质量损失 <5%（人眼几乎看不出来）
- **实际使用推荐 SVT-AV1**

## libaom-av1 使用指南

### 验证可用性

```bash
ffmpeg -encoders | grep av1
# 应看到：
# V..... libaom-av1           libaom AV1
# V..... libsvtav1            SVT-AV1(Scalable Video Technology for AV1)
```

---

### 基本配置

```bash
# 最简使用
ffmpeg -i input.mp4 -c:v libaom-av1 output.webm

# 常用配置
ffmpeg -i input.mp4 -c:v libaom-av1 \
  -crf 30 \
  -b:v 0 \
  output.webm

# -b:v 0 是必须的！告诉 libaom 使用 CRF 模式而不是 CBR 模式
```

**警告**：不加 `-b:v 0` 会默认使用 ABR 模式，质量不可控

---

### libaom 的 CRF 范围

**libaom CRF 范围：0-63**（与 libx264/libx265 不同！）

| CRF 值 | 质量描述 | 等效 H.265 CRF |
|--------|---------|--------------|
| 10-15 | 近似无损 | ~18 |
| 23-27 | 高质量 | ~20 |
| 30-35 | 标准质量（推荐） | ~26 |
| 40-45 | 较低质量 | ~32 |
| 55-60 | 低质量 | ~40 |

---

### libaom 速度控制

**libaom 的速度参数**：`-cpu-used`（0-8，值越大越快）

```bash
# 最高质量（极慢，通常不可用）
ffmpeg -i input.mp4 -c:v libaom-av1 -crf 30 -b:v 0 -cpu-used 0 output.webm

# 平衡（推荐的最快 libaom 配置）
ffmpeg -i input.mp4 -c:v libaom-av1 -crf 30 -b:v 0 -cpu-used 4 output.webm

# 最快（质量下降明显）
ffmpeg -i input.mp4 -c:v libaom-av1 -crf 30 -b:v 0 -cpu-used 8 output.webm
```

| cpu-used | 编码时间（相对） | 质量损失 | 备注 |
|----------|--------------|---------|------|
| 0 | 100x（极慢） | 0% | 参考质量 |
| 4 | 30x | <2% | 最慢的可用配置 |
| 6 | 10x | ~5% | 相当于 H.265 veryslow |
| 8 | 5x | ~10% | 最快但质量明显下降 |

---

### libaom 2-Pass 编码

```bash
# 第一遍
ffmpeg -i input.mp4 -c:v libaom-av1 -b:v 4M \
  -cpu-used 4 \
  -pass 1 -an -f null /dev/null

# 第二遍
ffmpeg -i input.mp4 -c:v libaom-av1 -b:v 4M \
  -cpu-used 4 \
  -pass 2 output.webm
```

## SVT-AV1 使用指南

### 为什么推荐 SVT-AV1

**性能测试（1 分钟 1080p30）**：
```
libaom cpu-used=4:    120 分钟
SVT-AV1 preset=4:      10 分钟
SVT-AV1 preset=6:       6 分钟
SVT-AV1 preset=8:       3 分钟
```

**在相同速度下**，SVT-AV1 比 libaom 质量更高或相当。

---

### 基本配置

```bash
# 最简使用
ffmpeg -i input.mp4 -c:v libsvtav1 output.mp4

# 常用配置（CRF 模式）
ffmpeg -i input.mp4 -c:v libsvtav1 \
  -crf 35 \
  -preset 6 \
  output.mp4
```

---

### SVT-AV1 的 Preset（速度控制）

**SVT-AV1 Preset 范围：0-13**（值越大越快）

```bash
# 最高质量（非常慢）
ffmpeg -i input.mp4 -c:v libsvtav1 -crf 35 -preset 0 output.mp4

# 推荐日常（平衡）
ffmpeg -i input.mp4 -c:v libsvtav1 -crf 35 -preset 6 output.mp4

# 快速（略有质量损失）
ffmpeg -i input.mp4 -c:v libsvtav1 -crf 35 -preset 10 output.mp4
```

| Preset | 编码时间（相对） | 文件大小（相对） | 推荐场景 |
|--------|--------------|--------------|---------|
| 0-2 | 100x | 90% | 极限质量 |
| 3-5 | 20x | 95% | 归档 |
| **6-8（推荐）** | **5-10x** | **100%** | 日常使用 |
| 9-11 | 2-5x | 110% | 快速转码 |
| 12-13 | 1x | 120% | 实时（质量差） |

---

### SVT-AV1 的 CRF 范围

**SVT-AV1 CRF 范围：1-63**

| CRF 值 | 质量描述 | 等效 H.265 CRF |
|--------|---------|--------------|
| 15-20 | 近似无损 | ~18 |
| 25-30 | 高质量 | ~22 |
| 35-40 | 标准质量（推荐） | ~28 |
| 45-50 | 较低质量 | ~35 |

---

### SVT-AV1 高级配置

```bash
# HLS 配置（固定 GOP）
ffmpeg -i input.mp4 -c:v libsvtav1 \
  -crf 35 \
  -preset 6 \
  -g 60 \
  -svtav1-params "scd=0" \
  output.mp4

# svtav1-params 传递参数
ffmpeg -i input.mp4 -c:v libsvtav1 \
  -crf 35 -preset 6 \
  -svtav1-params "film-grain=0:film-grain-denoise=0" \
  output.mp4
```

## AV1 vs H.265 vs H.264 全面对比

### 压缩率对比（相同视觉质量）

**测试条件**：1080p30，60 秒，medium/默认 preset

| 编码器 | 配置 | 文件大小 | 编码时间 |
|-------|------|---------|---------|
| H.264 libx264 | CRF 23, medium | 50 MB | 30s |
| H.265 libx265 | CRF 28, medium | 25 MB | 3min |
| AV1 libaom | CRF 30, cpu-used=4 | 20 MB | 180min |
| AV1 SVT-AV1 | CRF 35, preset=6 | 22 MB | 20min |

**结论**：
- AV1 文件最小（比 H.264 小 60%，比 H.265 小 20%）
- libaom 编码时间不可接受（180 分钟编 1 分钟视频）
- SVT-AV1 是实用选择（20 分钟，质量接近 libaom）

---

### 三编码器详细对比表

| 维度 | H.264 | H.265 | AV1 |
|------|-------|-------|-----|
| **压缩率** | 基准 | +50% | +60% |
| **编码速度** | 快 | 慢 4-6x | 极慢 50x（libaom）或 6x（SVT） |
| **解码速度** | 极快 | 快 | 中 |
| **硬件解码** | 几乎全支持 | 新设备支持 | 2022+ 设备支持 |
| **Web 支持** | 全支持 | Safari 仅限 | Chrome 70+, Firefox 67+ |
| **iOS 支持** | ✅ 全部 | ✅ iOS 11+ | ✅ iOS 16+ |
| **Android** | ✅ 全部 | ⚠️ 5+ | ⚠️ 需要硬件支持 |
| **专利费** | 有 | 有（更贵） | **免费** |
| **典型 CRF** | 23 | 28 | 35（SVT-AV1） |
| **推荐场景** | Web, 直播 | 4K, 存储 | YouTube, 未来标准 |

---

### 质量对比（VMAF，100 分为满分）

| 编码器 | VMAF 分数 | 文件大小 |
|-------|---------|---------|
| H.264 CRF 23 | 88 | 50 MB |
| H.265 CRF 28 | 88 | 25 MB |
| AV1 SVT-AV1 CRF 35 | 88 | 22 MB |

**结论**：三者视觉质量相同，但文件大小递减

## 实际场景选择

### 什么时候用 AV1？

**✅ 推荐使用**：
1. **YouTube/Netflix 上传**（他们会自己转 AV1）
2. **Web 端 H.264 的替代方案**（Chrome 全支持，省 60% 流量）
3. **长期归档**（文件小 60%，硬件支持越来越普遍）
4. **流媒体 CDN**（节省带宽成本）

**❌ 不推荐**：
1. **直播推流**（太慢，SVT-AV1 也不够快）
2. **Android 低端设备**（解码不稳定）
3. **需要快速交付**（编码时间是 H.264 的 6-20 倍）

---

### 场景 1：Web 视频（H.264 降级备用）


### 实践 5：Go 封装批量转 AV1 工具

```go
package main

import (
	"fmt"
	"os"
	"os/exec"
	"path/filepath"
	"sync"
	"time"
)

type TranscodeJob struct {
	InputPath  string
	OutputPath string
	Encoder    string
	CRF        int
	Preset     int
}

func transcodeToAV1(job TranscodeJob) error {
	args := []string{
		"-y", "-v", "error",
		"-i", job.InputPath,
	}

	if job.Encoder == "libsvtav1" {
		args = append(args,
			"-c:v", "libsvtav1",
			"-crf", fmt.Sprintf("%d", job.CRF),
			"-preset", fmt.Sprintf("%d", job.Preset),
			"-pix_fmt", "yuv420p",
			"-c:a", "libopus", "-b:a", "128k",
		)
	} else {
		args = append(args,
			"-c:v", "libaom-av1",
			"-crf", fmt.Sprintf("%d", job.CRF),
			"-b:v", "0",
			"-cpu-used", fmt.Sprintf("%d", job.Preset),
		)
	}

	args = append(args, job.OutputPath)

	start := time.Now()
	cmd := exec.Command("ffmpeg", args...)
	
	if output, err := cmd.CombinedOutput(); err != nil {
		return fmt.Errorf("转码失败: %s\n%s", err, string(output))
	}
	
	elapsed := time.Since(start)
	
	// 获取文件大小
	inputInfo, _ := os.Stat(job.InputPath)
	outputInfo, _ := os.Stat(job.OutputPath)
	
	savings := (inputInfo.Size() - outputInfo.Size()) * 100 / inputInfo.Size()
	
	fmt.Printf("✅ %s -> %s (耗时: %v, 节省: %d%%)\n",
		filepath.Base(job.InputPath),
		filepath.Base(job.OutputPath),
		elapsed.Round(time.Second),
		savings,
	)
	
	return nil
}

func main() {
	inputDir := "."
	if len(os.Args) > 1 {
		inputDir = os.Args[1]
	}

	// 查找所有 MP4 文件
	files, _ := filepath.Glob(filepath.Join(inputDir, "*.mp4"))

	jobs := make([]TranscodeJob, 0, len(files))
	for _, f := range files {
		output := f[:len(f)-4] + "_av1.mp4"
		jobs = append(jobs, TranscodeJob{
			InputPath:  f,
			OutputPath: output,
			Encoder:    "libsvtav1",
			CRF:        35,
			Preset:     6,
		})
	}

	fmt.Printf("找到 %d 个文件，开始转码（SVT-AV1 preset=6）...\n", len(jobs))

	// 并发处理（限制 2 个并发）
	var wg sync.WaitGroup
	semaphore := make(chan struct{}, 2)

	for _, job := range jobs {
		wg.Add(1)
		go func(j TranscodeJob) {
			defer wg.Done()
			semaphore <- struct{}{}
			defer func() { <-semaphore }()

			if err := transcodeToAV1(j); err != nil {
				fmt.Printf("❌ %s: %v\n", filepath.Base(j.InputPath), err)
			}
		}(job)
	}

	wg.Wait()
	fmt.Println("所有文件处理完成")
}
```

## 本篇小结

1. **AV1 的价值**：
   - 无专利费（Alliance for Open Media 开放标准）
   - 比 H.265 再节省 **30%** 码率，比 H.264 节省 **60%**
   - Web 友好（Chrome 70+, Firefox 67+ 原生支持）

2. **libaom-av1 vs SVT-AV1**：
   - libaom：参考实现，质量最高，**编码极慢**（实际不可用）
   - SVT-AV1：Netflix/Intel 出品，速度快 10-50 倍，质量接近
   - **实际应用推荐 SVT-AV1（libsvtav1）**

3. **CRF 范围（注意与 H.264/H.265 不同）**：
   - libaom/SVT：0-63（值越小质量越高）
   - SVT-AV1 标准质量推荐：**CRF 35**
   - **一定要加 `-b:v 0`**（libaom CRF 模式必须）

4. **SVT-AV1 Preset**：
   - 0-13（越小越慢越好）
   - 推荐：**6-8**（速度/质量平衡）
   - 不要用 <4（太慢）

5. **兼容性现状（2025 年）**：
   - Chrome/Firefox：支持
   - Safari：macOS 11+, iOS 16+ 支持
   - 硬件解码：Intel 11 代+、NVIDIA RTX 30+、AMD RDNA2+
   - 低端 Android：不支持

6. **三编码器选择指南**：
   - **H.264**：Web 视频、直播、Android、需要快速编码
   - **H.265**：4K 内容、本地归档、iOS App
   - **AV1**：Web 主流媒体、YouTube、长期归档、未来标准

7. **实际使用模板**：
   ```bash
   # Web（Chrome 原生 + Safari 降级）
   ffmpeg -i input.mp4 -c:v libsvtav1 -crf 35 -preset 6 output.webm
   ffmpeg -i input.mp4 -c:v libx264 -crf 23 -movflags +faststart output.mp4
   ```
