## H.264 编码原理简介

### 为什么需要压缩？

1080p30 未压缩视频：
```
1920 × 1080 × 3 字节(RGB) × 30fps = 186,624,000 字节/秒 ≈ 178 MB/s
90 分钟电影 = 178 MB/s × 5400s ≈ 940 GB
```

H.264 压缩后：
```
典型码率：4-8 Mbps
90 分钟电影 = 6 Mbps × 5400s ÷ 8 ≈ 4 GB
```

**压缩比：约 235:1**

---

### H.264 的三种冗余消除

```
┌─────────────────────────────────────────────────────────┐
│                   视频压缩技术栈                          │
├─────────────────────────────────────────────────────────┤
│  1. 空间冗余（Spatial Redundancy）                        │
│     一帧内相邻像素高度相关                                  │
│     → 帧内预测（Intra Prediction）+ DCT + 量化             │
│                                                         │
│  2. 时间冗余（Temporal Redundancy）                        │
│     连续帧之间只有局部变化                                   │
│     → 帧间预测（Inter Prediction）+ 运动补偿               │
│                                                         │
│  3. 编码冗余（Coding Redundancy）                          │
│     不同符号出现频率不同                                    │
│     → CABAC / CAVLC 熵编码                               │
└─────────────────────────────────────────────────────────┘
```

---

### 帧类型

```
GOP（Group of Pictures）

I   P   B   B   P   B   B   I
│   │   │   │   │   │   │   │
│   ↑   ↑↑  ↑↑  ↑   ↑↑  ↑↑  │
│   │   ││  ││  │   ││  ││  │
│   └─参考─┘│  ││  └─参考─┘│  │
│           └─参考─┘       │  │
└────────── GOP ───────────┘
```

| 帧类型 | 全称 | 说明 | 相对大小 |
|-------|------|------|---------|
| **I 帧** | Intra-coded frame | 完整编码，不依赖其他帧（关键帧） | 100% |
| **P 帧** | Predictive frame | 参考前面的帧，只编码差异 | 30-50% |
| **B 帧** | Bi-predictive frame | 参考前后帧，压缩率最高 | 10-20% |

**关键概念**：
- **GOP 大小**：两个 I 帧之间的帧数
  - GOP 小 → 可以精确裁剪、随机访问好 → 文件较大
  - GOP 大 → 压缩率高、文件小 → 随机访问慢
- **GOP = 30**（默认）表示每 30 帧有一个关键帧（1fps@30fps）

---

### DCT 量化过程（空间压缩核心）

```
原始像素块          DCT 变换           量化（压缩关键）
┌──┬──┬──┬──┐     ┌──┬──┬──┬──┐      ┌──┬──┬──┬──┐
│52│55│61│66│     │415│-30│-61│27│    │26│-2│-4│2 │
├──┼──┼──┼──┤     ├──┼──┼──┼──┤      ├──┼──┼──┼──┤
│70│61│64│73│     │-23│-17│-15│-9│   │-1│-1│-1│-1│
├──┼──┼──┼──┤  →  ├──┼──┼──┼──┤  →  ├──┼──┼──┼──┤
│63│59│55│90│     │-18│13│-9│-1│    │-1│1 │-1│0 │
├──┼──┼──┼──┤     ├──┼──┼──┼──┤      ├──┼──┼──┼──┤
│76│68│98│72│     │5 │-2│-1│0 │     │0 │0 │0 │0 │
└──┴──┴──┴──┘     └──┴──┴──┴──┘      └──┴──┴──┴──┘
8x8 像素块        频率域系数          量化后（高频置0）
```

**量化参数 QP（0-51）**：
- **QP 低**：量化步长小 → 保留更多细节 → 质量高 → 文件大
- **QP 高**：量化步长大 → 丢弃高频信息 → 质量低 → 文件小
- **CRF 与 QP 的关系**：CRF 约等于平均 QP 目标

## 三种码率控制模式

### 模式对比

```
码率控制模式选择
        │
        ├── CRF（恒定质量）
        │   ├── 适用：本地存储、视频库、后期制作
        │   ├── 质量：始终一致，复杂场景自动多分配码率
        │   └── 缺点：文件大小不可预测
        │
        ├── ABR（平均码率）
        │   ├── 适用：带宽限制的流媒体
        │   ├── 优点：平均码率可控
        │   └── 缺点：无法精确控制最大码率
        │
        └── CBR / 2-Pass
            ├── 适用：直播推流、硬件解码器
            ├── 优点：码率严格可控
            └── 缺点：静态场景浪费带宽
```

---

### CRF（恒定质量因子，推荐首选）

**原理**：维持恒定的感知质量，允许码率随内容复杂度波动

```bash
# 语法
ffmpeg -i input.mp4 -c:v libx264 -crf <0-51> output.mp4

# 典型配置
ffmpeg -i input.mp4 -c:v libx264 -crf 18 output.mp4  # 近似无损
ffmpeg -i input.mp4 -c:v libx264 -crf 23 output.mp4  # 默认质量
ffmpeg -i input.mp4 -c:v libx264 -crf 28 output.mp4  # 较低质量
```

**CRF 值参考**：

| CRF 值 | 质量描述 | 典型使用场景 |
|--------|---------|-------------|
| 0 | 无损（文件极大） | 几乎不用 |
| 17-18 | 视觉无损 | 视频制作母版 |
| 20-23 | 高质量（默认 23） | 本地观影 |
| 24-28 | 中等质量 | 在线视频 |
| 29-35 | 较低质量 | 移动端 |
| >35 | 低质量 | 预览、节省空间 |

**实验：CRF 对文件大小的影响**

```bash
for crf in 18 23 28 33; do
    ffmpeg -y -i input.mp4 -c:v libx264 -crf $crf output_crf${crf}.mp4
    size=$(du -sh output_crf${crf}.mp4 | cut -f1)
    echo "CRF $crf: $size"
done
```

**预期输出（30 秒 1080p 视频）**：
```
CRF 18: 45M
CRF 23: 22M
CRF 28: 11M
CRF 33: 6M
```

---

### ABR（平均码率）

**原理**：以目标码率编码，允许局部波动

```bash
# 只指定目标码率
ffmpeg -i input.mp4 -c:v libx264 -b:v 5M output.mp4

# 同时指定 buffer 大小（控制抖动）
ffmpeg -i input.mp4 -c:v libx264 -b:v 5M -bufsize 10M output.mp4
```

**注意**：ABR 模式下 libx264 会忽略 CRF

---

### 2-Pass ABR（推荐：精确码率控制）

**原理**：
1. 第一遍（Pass 1）：分析视频内容，不输出文件
2. 第二遍（Pass 2）：根据分析结果，精确分配码率

```bash
# 第一遍（分析）
ffmpeg -i input.mp4 -c:v libx264 -b:v 5M \
  -pass 1 -an -f null /dev/null

# 第二遍（编码）
ffmpeg -i input.mp4 -c:v libx264 -b:v 5M \
  -pass 2 output.mp4

# 查看生成的分析文件
ls -la x264_2pass.log*
```

**2-Pass vs 1-Pass ABR 对比**：

| 维度 | 1-Pass ABR | 2-Pass ABR |
|------|-----------|-----------|
| 速度 | 正常 | 慢 2 倍 |
| 码率精度 | 偏差 ±10-20% | 偏差 ±1-5% |
| 质量分配 | 均匀 | 按复杂度分配 |
| 适用场景 | 实时推流 | 离线转码 |

---

### CBR（恒定码率）

**原理**：码率恒定，需要 `-maxrate` 和 `-bufsize`

```bash
# CBR 配置
ffmpeg -i input.mp4 -c:v libx264 \
  -b:v 5M -maxrate 5M -bufsize 10M \
  output.mp4
```

**HLS 场景 CBR**（确保播放器缓冲区稳定）：

```bash
ffmpeg -i input.mp4 -c:v libx264 \
  -b:v 4M -maxrate 4.5M -bufsize 9M \
  -g 60 -keyint_min 60 \
  -sc_threshold 0 \
  -c:a aac -b:a 128k \
  output_cbr.mp4
```

## Preset（速度/质量权衡）

### Preset 的本质

Preset 控制 libx264 内部算法的"努力程度"：
- **越慢的 preset** → 使用更多分析技术 → 相同质量的文件更小（或相同大小质量更高）
- **越快的 preset** → 跳过部分分析 → 编码速度快但压缩效率低

**可选值（从快到慢）**：
```
ultrafast > superfast > veryfast > faster > fast > medium > slow > slower > veryslow
```

---

### Preset 性能对比

**测试条件**：CRF=23，1080p30 视频，Intel i7

```bash
for preset in ultrafast superfast veryfast faster fast medium slow slower veryslow; do
    echo -n "$preset: "
    start_time=$(date +%s%N)
    ffmpeg -y -i input.mp4 -c:v libx264 -crf 23 -preset $preset output_${preset}.mp4 2>/dev/null
    end_time=$(date +%s%N)
    elapsed=$(( (end_time - start_time) / 1000000 ))
    size=$(du -sh output_${preset}.mp4 | cut -f1)
    echo "${elapsed}ms, $size"
done
```

**预期结果**（相对值）：

| Preset | 编码时间（相对） | 文件大小（相对） |
|--------|--------------|--------------|
| ultrafast | 1x | 100% |
| superfast | 1.5x | 90% |
| veryfast | 2x | 75% |
| faster | 2.5x | 70% |
| fast | 3x | 67% |
| **medium（默认）** | **4x** | **65%** |
| slow | 6x | 62% |
| slower | 9x | 60% |
| veryslow | 15x | 58% |

**实际建议**：
- **日常使用**：`medium`（速度/质量最佳平衡）
- **快速预览**：`veryfast` 或 `faster`
- **归档存储**：`slow` 或 `slower`（节省存储空间）
- **直播推流**：`veryfast` 或 `ultrafast`（实时性要求）

---

### Preset 与 CRF 组合

```bash
# 归档：最小文件，不在乎时间
ffmpeg -i input.mp4 -c:v libx264 -crf 20 -preset slower output_archive.mp4

# 日常：平衡速度和质量
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -preset medium output_normal.mp4

# 实时：速度优先
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -preset veryfast output_fast.mp4
```

## Profile 与 Level

### Profile（功能集合）

Profile 限制编码器可以使用哪些功能：

```
Baseline    Main    High    High 10   High 4:2:2   High 4:4:4
│           │       │       │         │            │
│ 最兼容    │       │ 最常用│         │            │ 最大功能集
│ 无 B 帧   │ B 帧  │ 8-bit  │ 10-bit │            │ 无损
│ 无 CABAC  │ CABAC │ CABAC  │        │            │
└───────────┴───────┴────────┴────────┴────────────┘
         兼容性 ←──────────────────→ 压缩效率
```

| Profile | B 帧 | CABAC | 位深 | 适用场景 |
|---------|------|-------|------|---------|
| **Baseline** | ❌ | ❌ | 8-bit | iOS 旧设备、实时通信 |
| **Main** | ✅ | ✅ | 8-bit | 移动设备、主流播放器 |
| **High（默认）** | ✅ | ✅ | 8-bit | PC、流媒体、蓝光 |
| High 10 | ✅ | ✅ | 10-bit | HDR 内容 |

---

### Level（硬件解码限制）

Level 限制分辨率、帧率和码率：

| Level | 最大分辨率 | 最大帧率 | 最大码率 | 适用场景 |
|-------|---------|---------|---------|---------|
| 3.0 | 720x576 | 25fps | 10 Mbps | SD 视频 |
| 3.1 | 1280x720 | 30fps | 14 Mbps | 720p |
| 4.0 | 1920x1080 | 30fps | 20 Mbps | 1080p30 |
| 4.1 | 1920x1080 | 30fps | 50 Mbps | 蓝光标准 |
| 5.0 | 2560x1920 | 30fps | 135 Mbps | 4K |
| 5.1 | 3840x2160 | 30fps | 240 Mbps | 4K UHD |

---

### Profile/Level 配置

```bash
# 高兼容性（旧设备）
ffmpeg -i input.mp4 -c:v libx264 \
  -profile:v baseline -level 3.0 \
  output_baseline.mp4

# 主流设备
ffmpeg -i input.mp4 -c:v libx264 \
  -profile:v main -level 4.0 \
  output_main.mp4

# 最优压缩（默认）
ffmpeg -i input.mp4 -c:v libx264 \
  -profile:v high -level 4.1 \
  output_high.mp4

# Apple/iOS 设备（特别要求）
ffmpeg -i input.mp4 -c:v libx264 \
  -profile:v high -level 4.1 \
  -pix_fmt yuv420p \
  -movflags faststart \
  output_ios.mp4
```

**注意**：
- `-pix_fmt yuv420p`：iOS 要求 4:2:0 色彩空间
- `-movflags faststart`：将索引数据移到文件头，支持网络边下边播

## Tune（针对内容优化）

### Tune 参数的作用

Tune 针对特定内容类型调整编码参数：

```bash
# 可用的 tune 选项
ffmpeg -i input.mp4 -c:v libx264 -tune film output.mp4
```

| Tune | 内容类型 | 调整效果 |
|------|---------|---------|
| `film` | 电影（暗部细节丰富） | 增强暗部质量，降低量化噪声 |
| `animation` | 动画（大块纯色） | 提高色块压缩效率 |
| `grain` | 胶片噪点视频 | 保留胶片噪点 |
| `stillimage` | 幻灯片、截图序列 | 更高质量的静态帧 |
| `fastdecode` | 低端解码设备 | 禁用 B 帧等复杂特性 |
| `zerolatency` | 实时推流 | 禁用 B 帧，最低延迟 |
| `psnr` | 质量测试 | 优化 PSNR 指标 |
| `ssim` | 质量测试 | 优化 SSIM 指标 |

---

### 实时推流专用配置

```bash
# RTMP 直播推流（最低延迟）
ffmpeg -i input.mp4 -c:v libx264 \
  -tune zerolatency \
  -preset veryfast \
  -crf 23 \
  -g 60 \
  output_live.mp4
```

## 高级参数

### GOP 控制

```bash
# 设置关键帧间隔（GOP 大小）
ffmpeg -i input.mp4 -c:v libx264 \
  -g 60 \          # 每 60 帧一个关键帧（2秒@30fps）
  -keyint_min 60 \ # 最小关键帧间隔（防止自动插入）
  -sc_threshold 0 \ # 禁用场景变换自动关键帧
  output.mp4
```

**HLS 分片要求**：
```bash
# HLS 需要关键帧间隔等于分片时长
# 分片 2 秒，30fps → -g 60
ffmpeg -i input.mp4 -c:v libx264 \
  -g 60 -keyint_min 60 -sc_threshold 0 \
  -hls_time 2 -hls_list_size 0 \
  output.m3u8
```

---

### 色彩空间控制

```bash
# 标准 SDR（YouTube、Netflix 要求）
ffmpeg -i input.mp4 -c:v libx264 \
  -pix_fmt yuv420p \
  -colorspace bt709 -color_primaries bt709 -color_trc bt709 \
  output.mp4

# 检查色彩空间
ffprobe -v error -select_streams v:0 \
  -show_entries stream=color_space,color_primaries,color_transfer \
  output.mp4
```

---

### 参考帧数量

```bash
# 增加参考帧数（提高压缩率，增加解码复杂度）
ffmpeg -i input.mp4 -c:v libx264 \
  -refs 6 \     # 默认 3
  output.mp4

# 注意：-profile:v baseline 只支持 -refs 1
```

---

### x264opts（高级参数传递）

```bash
# 通过 x264opts 传递 libx264 内部参数
ffmpeg -i input.mp4 -c:v libx264 \
  -x264opts "keyint=60:min-keyint=60:no-scenecut:ref=6:bframes=3" \
  output.mp4
```

## 实际场景配置

### 场景 1：YouTube 上传

**YouTube 官方推荐**：
```bash
ffmpeg -i input.mp4 -c:v libx264 \
  -preset slow \
  -crf 18 \
  -profile:v high -level 4.2 \
  -pix_fmt yuv420p \
  -c:a aac -b:a 192k \
  -ar 48000 \
  -movflags +faststart \
  output_youtube.mp4
```

**参数解释**：
- `-preset slow`：YouTube 会二次转码，上传高质量源文件
- `-crf 18`：接近无损
- `-pix_fmt yuv420p`：确保兼容性
- `-movflags +faststart`：索引前置，加快加载

---

### 场景 2：Netflix/流媒体平台

```bash
# 1080p 主流质量
ffmpeg -i input.mp4 -c:v libx264 \
  -crf 23 \
  -preset slow \
  -profile:v high -level 4.0 \
  -pix_fmt yuv420p \
  -g 48 -keyint_min 48 -sc_threshold 0 \
  -c:a aac -b:a 128k \
  -movflags +faststart \
  output_streaming.mp4
```

**关键点**：
- `-g 48`：GOP 2 秒（HLS 分片对齐）
- `-sc_threshold 0`：禁用场景变换检测（避免额外关键帧）

---

### 场景 3：RTMP 直播推流

```bash
# 实时推流配置（低延迟）
ffmpeg -re -i input.mp4 -c:v libx264 \
  -preset veryfast \
  -tune zerolatency \
  -crf 23 \
  -g 60 -keyint_min 60 \
  -profile:v baseline \
  -c:a aac -b:a 128k -ar 44100 \
  -f flv rtmp://server/live/stream_key
```

**参数解释**：
- `-re`：按真实帧率读取（模拟实时流）
- `-tune zerolatency`：禁用 B 帧，降低延迟
- `-preset veryfast`：实时性优先

---

### 场景 4：移动端 H5 视频

```bash
# iOS/Android 通用配置
ffmpeg -i input.mp4 -c:v libx264 \
  -crf 28 \
  -preset fast \
  -profile:v main -level 3.1 \
  -vf scale=-2:720 \
  -pix_fmt yuv420p \
  -c:a aac -b:a 96k \
  -movflags +faststart \
  output_mobile.mp4
```

**关键点**：
- `-vf scale=-2:720`：缩放到 720p（-2 保证宽度是偶数）
- `-crf 28`：较高压缩，节省流量
- `-profile:v main -level 3.1`：旧设备兼容性

---

### 场景 5：HLS 多码率自适应

```bash
# 生成 3 个码率版本
# 1080p
ffmpeg -i input.mp4 -c:v libx264 \
  -b:v 5000k -maxrate 5500k -bufsize 10000k \
  -s 1920x1080 \
```

## 本篇小结

1. **H.264 压缩原理**：
   - 空间冗余：帧内预测 + DCT + 量化
   - 时间冗余：帧间预测 + 运动补偿
   - 编码冗余：CABAC/CAVLC 熵编码
   - 压缩比：约 200:1

2. **三种码率控制模式**：
   - **CRF（推荐）**：恒定质量，码率波动，适合本地存储
   - **ABR**：平均码率，适合流媒体
   - **2-Pass ABR**：精确码率控制，适合离线转码
   - **CBR**：恒定码率，适合直播推流

3. **Preset（速度/质量）**：
   - `ultrafast ~ veryslow`：编码时间差 15 倍，文件大小差 40%
   - 推荐：`medium`（日常）、`slow`（归档）、`veryfast`（实时）

4. **Profile/Level**：
   - **Baseline**：无 B 帧，最兼容
   - **Main**：有 B 帧，主流设备
   - **High**：最优压缩，默认选择
   - **Level**：限制分辨率、帧率、码率

5. **Tune**：
   - `film`：电影
   - `animation`：动画
   - `zerolatency`：实时推流
   - `grain`：胶片噪点

6. **关键参数**：
   - CRF：18（近无损） ~ 23（默认） ~ 28（低质量）
   - GOP：`-g 60`（2 秒@30fps，HLS 对齐）
   - `-pix_fmt yuv420p`：兼容性
   - `-movflags +faststart`：网络播放

7. **实际场景**：
   - YouTube：CRF 18 + slow
   - 流媒体：CRF 23 + slow + GOP 对齐
   - 直播：veryfast + zerolatency + baseline
   - 移动端：CRF 28 + 720p + main
   - 归档：CRF 16 + veryslow

8. **性能建议**：
   - 日常转码：`-crf 23 -preset medium`
   - 快速预览：`-crf 23 -preset veryfast`
   - 最小文件：`-crf 20 -preset veryslow`

## 关键术语速查表

| 术语 | 英文 | 解释 |
|------|------|------|
| CRF | Constant Rate Factor | 恒定质量因子（0-51，值越小质量越高） |
| ABR | Average Bit Rate | 平均码率模式 |
| CBR | Constant Bit Rate | 恒定码率模式 |
| Preset | Encoding Preset | 编码速度预设（ultrafast ~ veryslow） |
| Profile | Encoding Profile | 功能集合（Baseline/Main/High） |
| Level | Level | 硬件解码能力限制 |
| Tune | Tuning | 针对内容类型优化 |
| GOP | Group of Pictures | 关键帧间隔（一组帧） |
| QP | Quantization Parameter | 量化参数（0-51，值越小质量越高） |
| DCT | Discrete Cosine Transform | 离散余弦变换（空间→频率域） |
| CABAC | Context-Adaptive Binary Arithmetic Coding | 上下文自适应二进制算术编码 |
| CAVLC | Context-Adaptive Variable-Length Coding | 上下文自适应可变长度编码 |
| 帧内预测 | Intra Prediction | 利用同一帧内相邻像素预测 |
| 帧间预测 | Inter Prediction | 利用前后帧预测 |
| 运动补偿 | Motion Compensation | 根据运动向量预测像素 |
