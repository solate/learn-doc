## 1. 为什么需要质量评估

### 1.1 "越小越好"的陷阱

初学者常见的错误逻辑：

```
转码目标：尽可能压缩文件大小
策略：调高 CRF 值，用更激进的压缩
结果：文件缩小了 60%，但用户看到明显的块状伪影
```

**正确逻辑**：在**可接受质量**的前提下，找到最小的文件大小。

```
质量目标：VMAF ≥ 93（高清视频标准）
策略：自动找到满足质量目标的最低码率
结果：比固定 CRF 再节省 15-25% 体积，且质量有保障
```

---

### 1.2 质量评估的三个应用场景

**场景 1：编码器选型**
```
问题：H.265 和 AV1 谁更适合我的场景？
答案：用 VMAF 测量相同码率下的质量差异，量化决策依据
```

**场景 2：码率优化**
```
问题：YouTube 上传用 CRF 23 还是 CRF 26？
答案：测量两者的 VMAF 分数，如果差异 <3 分，选 CRF 26（文件更小）
```

**场景 3：ABR 码率梯队设计**
```
问题：1080p 视频应该提供 6M / 4M / 2M 三档，还是 8M / 5M / 3M？
答案：测量每档的 VMAF，确保最低档 ≥90 分（行业标准）
```

---

### 1.3 主观质量 vs 客观指标

**主观质量评估（MOS，Mean Opinion Score）**：
- 找 20-50 人观看，打分 1-5 分，取平均值
- 成本高、周期长、难以自动化
- 适合最终验收阶段

**客观质量指标（PSNR/SSIM/VMAF）**：
- 机器自动计算，秒级完成，可批量化
- 成本低、可重复、CI/CD 友好
- VMAF 是目前与主观评分最接近的指标

**结论**：生产环境用 VMAF 做质量守门，重要项目补充 MOS 抽检。

## 2. 三大质量指标详解

### 2.1 PSNR（峰值信噪比）

**原理**：测量压缩视频与原始视频的像素差异（逐像素对比）。

```
PSNR = 10 × log₁₀(MAX² / MSE)

MAX = 255（8-bit 视频）
MSE = 均方误差（每个像素点的差值平方和再平均）
```

**评分标准**：
```
PSNR < 30dB  ：质量差，明显伪影
PSNR 30-35dB ：可接受（低质量场景）
PSNR 35-40dB ：良好（标清/高清常见范围）
PSNR 40-45dB ：优秀（高质量编码）
PSNR > 50dB  ：近无损（视觉无差异）
```

**优点**：
- 计算简单快速
- 数学定义明确

**缺点**：
- 不考虑人眼感知特性（人眼对边缘敏感，对平滑区域不敏感）
- 高 PSNR 不一定主观质量好（如轻微模糊会提高 PSNR，但画面不清晰）

---

### 2.2 SSIM（结构相似度指数）

**原理**：对比亮度、对比度、结构三个维度，更接近人眼感知。

```
SSIM(x, y) = [l(x,y)]^α · [c(x,y)]^β · [s(x,y)]^γ

l = 亮度相似度
c = 对比度相似度
s = 结构相似度
```

**评分标准**：
```
SSIM 0.0-0.8 ：质量差
SSIM 0.8-0.9 ：可接受
SSIM 0.9-0.95：良好（生产标准）
SSIM 0.95-1.0：优秀
SSIM 1.0     ：完全相同
```

**优点**：
- 比 PSNR 更符合人眼感知
- 对模糊、噪声、块状伪影敏感度高

**缺点**：
- 仍无法完全模拟人眼（例如色彩失真检测不足）
- 不同内容类型（动画 vs 真人）敏感度不同


---

### 2.3 VMAF（视频多方法评估融合）

**VMAF（Video Multi-Method Assessment Fusion）** 是 Netflix 于 2016 年开源的质量评估框架，是目前行业标准。

**原理**：机器学习模型融合多个特征：
```
输入特征：
  - VIF（视觉信息保真度）：信息量损失
  - DLM（细节损失度量）：纹理细节保留
  - MOTION（运动感知）：帧间运动复杂度

融合模型：SVM 回归 → VMAF Score (0-100)
```

**评分标准**：
```
VMAF < 60   ：质量差，不可接受
VMAF 60-70  ：低质量，适合低带宽场景
VMAF 70-80  ：中等质量，移动端可接受
VMAF 80-90  ：良好，标准流媒体质量
VMAF 90-95  ：优秀，高清流媒体标准
VMAF 95-100 ：接近无损，超高清场景
```

**VMAF 模型版本**：
```
vmaf_v0.6.1        ：原始模型（1080p 基准）
vmaf_4k_v0.6.1     ：4K 内容优化版
vmaf_v0.6.1neg     ：neg 模型（更接近主观评分）
vmaf_b_v0.6.3      ：Phone 模型（手机小屏优化）
```

**为什么 VMAF 优于 PSNR/SSIM**：
```
场景：对视频进行轻微模糊处理
PSNR：升高（像素差异减小）
SSIM：可能升高（结构差异减小）
VMAF：降低（细节信息丢失，与人眼感知一致）
```

**三指标对比总结**：
```
指标    计算速度    感知准确度    适用场景
PSNR    最快        低            快速粗略评估
SSIM    快          中            补充参考
VMAF    慢          高            生产质量门控
```

## 3. FFmpeg 测量质量指标

### 3.1 测量 PSNR

```bash
# 基础 PSNR 测量
ffmpeg -i distorted.mp4 -i reference.mp4 \
  -lavfi "[0:v][1:v]psnr" \
  -f null -

# 输出示例：
# [Parsed_psnr_0 @ 0x...] PSNR y:42.34 u:44.20 v:43.87 average:42.78 min:38.45 max:47.21
# y = 亮度通道 PSNR（最重要）
# u/v = 色度通道 PSNR
```

```bash
# 保存逐帧 PSNR 到文件
ffmpeg -i distorted.mp4 -i reference.mp4 \
  -lavfi "[0:v][1:v]psnr=stats_file=psnr_stats.txt" \
  -f null -
```

---

### 3.2 测量 SSIM

```bash
# 基础 SSIM 测量
ffmpeg -i distorted.mp4 -i reference.mp4 \
  -lavfi "[0:v][1:v]ssim" \
  -f null -

# 输出示例：
# [Parsed_ssim_0 @ 0x...] SSIM Y:0.9823 U:0.9901 V:0.9889 All:0.9838
```

```bash
# 同时测量 PSNR + SSIM（一次运行）
ffmpeg -i distorted.mp4 -i reference.mp4 \
  -lavfi "[0:v][1:v]psnr;[0:v][1:v]ssim" \
  -f null -
```

---

### 3.3 测量 VMAF（核心）

```bash
# 基础 VMAF 测量（需要 FFmpeg 编译包含 libvmaf）
ffmpeg -i distorted.mp4 -i reference.mp4 \
  -lavfi "[0:v][1:v]libvmaf" \
  -f null -

# 输出示例：
# [libvmaf @ 0x...] VMAF score: 93.42
```

```bash
# 输出 JSON 格式详细报告
ffmpeg -i distorted.mp4 -i reference.mp4 \
  -lavfi "[0:v][1:v]libvmaf=log_fmt=json:log_path=vmaf_report.json" \
  -f null -

# 指定模型版本（推荐）
ffmpeg -i distorted.mp4 -i reference.mp4 \
  -lavfi "[0:v][1:v]libvmaf=model=version=vmaf_v0.6.1" \
  -f null -
```

```bash
# 完整生产级命令（含子指标）
ffmpeg -i distorted.mp4 -i reference.mp4 \
  -lavfi "[0:v][1:v]libvmaf=log_fmt=json:log_path=vmaf_report.json:feature=name=psnr|name=ssim" \
  -f null -
```

### 3.4 批量对比不同编码器

```bash
#!/bin/bash
# 对比 H.264/H.265/AV1 在相同码率下的质量

REFERENCE="original.mp4"
BITRATE="4M"

# H.264 编码
ffmpeg -i "$REFERENCE" -c:v libx264 -b:v $BITRATE -c:a copy h264_4m.mp4
# H.265 编码
ffmpeg -i "$REFERENCE" -c:v libx265 -b:v $BITRATE -c:a copy h265_4m.mp4
# AV1 编码
ffmpeg -i "$REFERENCE" -c:v libaom-av1 -b:v $BITRATE -cpu-used 6 -c:a copy av1_4m.mp4

# 测量 VMAF
ffmpeg -i h264_4m.mp4 -i "$REFERENCE" \
  -lavfi "[0:v][1:v]libvmaf=log_fmt=json:log_path=h264_vmaf.json" -f null -
ffmpeg -i h265_4m.mp4 -i "$REFERENCE" \
  -lavfi "[0:v][1:v]libvmaf=log_fmt=json:log_path=h265_vmaf.json" -f null -
ffmpeg -i av1_4m.mp4 -i "$REFERENCE" \
  -lavfi "[0:v][1:v]libvmaf=log_fmt=json:log_path=av1_vmaf.json" -f null -

# 对比结果
echo "H.264 VMAF: $(jq '.pooled_metrics.vmaf.mean' h264_vmaf.json)"
echo "H.265 VMAF: $(jq '.pooled_metrics.vmaf.mean' h265_vmaf.json)"
echo "AV1 VMAF:   $(jq '.pooled_metrics.vmaf.mean' av1_vmaf.json)"
```

---

### 3.5 测量注意事项

**分辨率必须一致**：
```bash
# ❌ 错误 - 分辨率不同会报错
ffmpeg -i 1080p_distorted.mp4 -i 720p_reference.mp4 \
  -lavfi "[0:v][1:v]libvmaf" -f null -
# Error: frame dimension mismatch

# ✅ 正确 - 先缩放到相同分辨率
ffmpeg -i 1080p_distorted.mp4 -i 720p_reference.mp4 \
  -lavfi "[0:v]scale=1280:720[d];[d][1:v]libvmaf" -f null -
```

**帧率必须一致**：
```bash
# 如果帧率不同，先统一帧率
ffmpeg -i 60fps.mp4 -i 30fps_ref.mp4 \
  -lavfi "[0:v]fps=30[d];[d][1:v]libvmaf" -f null -
```

**输入顺序**：`[待测视频][参考视频]`，顺序反了会导致错误结果。

## 4. VMAF 深度解析

### 4.1 VMAF JSON 报告结构

```json
{
  "version": "2.3.1",
  "pooled_metrics": {
    "vmaf": {
      "min": 78.23,
      "max": 98.45,
      "mean": 93.42,      // ← 最重要：整体平均分
      "harmonic_mean": 92.87
    },
    "psnr": {
      "min": 35.12,
      "max": 48.34,
      "mean": 42.15
    }
  },
  "frames": [
    {
      "frameNum": 0,
      "metrics": {
        "vmaf": 95.23,     // 逐帧分数
        "psnr": 43.21
      }
    }
  ]
}
```

---

### 4.2 如何解读 VMAF 分数

**决策表**：
```
VMAF 分数    质量评级    决策建议
< 70         差          拒绝，重新编码
70-80        低          仅用于极低带宽场景
80-85        中低        移动端可接受，PC 端慎用
85-90        中          标准流媒体质量
90-93        良好        高清视频推荐目标
93-95        优秀        超高清推荐目标
> 95         卓越        接近透明（体积可能过大）
```

**Netflix 内部标准**（2023）：
```
1080p 高质量 Tier：VMAF ≥ 93
1080p 标准 Tier：VMAF ≥ 90
720p 标准 Tier：VMAF ≥ 88
480p 标准 Tier：VMAF ≥ 85
```

**VMAF 差异的实际含义**：
```
VMAF 差异    主观感知
< 1 分       人眼几乎无法察觉
1-3 分       需要仔细对比才能发现
3-5 分       明显可见，但可接受
5-10 分      显著差异
> 10 分      巨大差异，影响观看体验
```

---

### 4.3 VMAF 的局限性

**场景 1：极低码率失效**
```
当 VMAF < 60 时，分数差异不再可靠
例如：VMAF 40 vs 50，主观质量差异可能比 80 vs 90 还大
```

**场景 2：不同内容类型敏感度不同**
```
动画/屏幕录制：相同码率下 VMAF 通常更高（纹理简单）
电影/体育赛事：相同码率下 VMAF 较低（纹理复杂）
```

**场景 3：模型训练偏差**
```
VMAF 基于 1080p 内容训练
  → 720p 视频：分数偏高（相对保守）
  → 4K 视频：分数偏低（需用 vmaf_4k 模型）
```

## 5. 码率梯队（ABR Ladder）设计

### 5.1 什么是码率梯队

**码率梯队** 是流媒体平台为同一视频提供多个质量档位（分辨率+码率组合），播放器根据网络状况自动切换。

```
用户带宽 10Mbps ──→ 播放 1080p@6Mbps（最高质量）
用户带宽 3Mbps  ──→ 切换到 720p@2Mbps
用户带宽 1Mbps  ──→ 切换到 480p@800Kbps
```

**为什么需要码率梯队**：
```
单一码率的问题：
  高码率 → 低带宽用户卡顿
  低码率 → 高带宽用户画质差

自适应码率（ABR）解决方案：
  → 多个档位 → 播放器动态选择 → 所有用户最优体验
```

---

### 5.2 行业标准梯队表

**Netflix 2025 生产码率梯队**：
```
分辨率    码率档位 1    码率档位 2    码率档位 3
4K       15Mbps        10Mbps        6Mbps
1080p    6Mbps         4Mbps         2Mbps
720p     3Mbps         2Mbps         1Mbps
480p     1Mbps         600Kbps       —
360p     400Kbps       250Kbps       —
```

**YouTube 推荐上传码率（H.264）**：
```
分辨率    帧率       SDR 码率        HDR 码率
2160p     24-30fps   35-45Mbps       53-68Mbps
2160p     48-60fps   53-68Mbps       80-102Mbps
1440p     24-30fps   16Mbps          24Mbps
1080p     24-30fps   8Mbps           12Mbps
1080p     48-60fps   12Mbps          18Mbps
720p      24-30fps   5Mbps           7.5Mbps
```

**Apple HLS 推荐梯队（H.264 + AAC）**：
```
分辨率    码率        说明
1920×1080 7800Kbps    最高质量
1280×720  4500Kbps    高质量
960×540   3000Kbps    中等质量
640×480   2000Kbps    基础质量
400×300   600Kbps     低带宽
400×300   200Kbps     极低带宽（仅音频推荐改为纯音频）
```

---

### 5.3 关键帧对齐

ABR 流畅切换依赖于所有档位的关键帧完全对齐。

```
错误：各档位关键帧不对齐
  720p:  [I]   B    B    B   [I]   B    B
  480p:  [I]   B    B   [I]   B    B    B
                           ↑ 切换点不同步，切换卡顿

正确：所有档位关键帧对齐
  720p:  [I]   B    B    B    B    B   [I]
  480p:  [I]   B    B    B    B    B   [I]
                                       ↑ 同一帧位置，无缝切换
```

```bash
# 生产级关键帧对齐编码（以 2 秒间隔为例）
SEGMENT_DURATION=2  # HLS 分段时长（秒）
FPS=30
GOP_SIZE=$((SEGMENT_DURATION * FPS))  # = 60

# 1080p 6Mbps
ffmpeg -i input.mp4 \
  -c:v libx264 -b:v 6M \
  -g $GOP_SIZE -keyint_min $GOP_SIZE -sc_threshold 0 \
  -c:a aac -b:a 128k \
  output_1080p.mp4

# 720p 3Mbps（相同 GOP 设置）
ffmpeg -i input.mp4 \
  -vf scale=1280:720 \
  -c:v libx264 -b:v 3M \
  -g $GOP_SIZE -keyint_min $GOP_SIZE -sc_threshold 0 \
  -c:a aac -b:a 128k \
  output_720p.mp4
```

**参数说明**：
```
-g $GOP_SIZE        ：固定 GOP 大小（帧数）
-keyint_min $GOP_SIZE：最小关键帧间隔等于 GOP 大小（强制等间隔）
-sc_threshold 0     ：禁用场景变化检测（否则会插入额外关键帧破坏对齐）
```

## 6. 逐片编码（Per-Title Encoding）

### 6.1 传统固定梯队的问题

```
传统固定梯队：对所有视频用相同码率
  动画片（内容简单） → 1080p@6Mbps 过度编码（浪费带宽）
  体育赛事（内容复杂）→ 1080p@6Mbps 质量不足（画面模糊）
```

**Per-Title（逐片）编码**：Netflix 2015 年提出，针对每段内容动态确定最优码率梯队。

```
动画片   → VMAF 93 @ 1080p 2Mbps    （节省 67% 带宽）
体育赛事 → VMAF 93 @ 1080p 8Mbps    （提升画质或降低码率）
```

**Netflix 数据**：Per-title 编码平均减少 20% 带宽消耗，同时提升画质。

---

### 6.2 Per-Title 实现原理

```
步骤 1：探针编码（Probe Encoding）
  用不同 CRF 值编码同一段内容的代表片段（30-60 秒）
  CRF 18, 22, 26, 30, 34, 38 → 6 个文件

步骤 2：质量测量
  对每个文件测量 VMAF 分数
  得到：码率-质量曲线（RQ 曲线）

步骤 3：目标点选择
  在 RQ 曲线上找到 VMAF = 目标分 的码率
  例如：目标 VMAF 93 对应 3.2Mbps（而非固定梯队的 6Mbps）

步骤 4：最终编码
  用步骤 3 确定的码率进行 2-pass ABR 编码
```

---

### 6.3 构建 RQ 曲线

```bash
#!/bin/bash
# 对代表片段进行多 CRF 探针编码

SOURCE="input.mp4"
PROBE_CLIP="probe.mp4"

# 提取代表片段（视频中间 1 分钟）
DURATION=$(ffprobe -v error -show_entries format=duration -of csv=p=0 "$SOURCE")
START=$(echo "$DURATION / 2 - 30" | bc)
ffmpeg -ss $START -t 60 -i "$SOURCE" -c copy "$PROBE_CLIP"

# 探针编码（6 个 CRF 点）
for CRF in 18 22 26 30 34 38; do
    ffmpeg -i "$PROBE_CLIP" \
      -c:v libx264 -crf $CRF \
      -vf scale=1920:1080 \
      probe_crf${CRF}.mp4 -y 2>/dev/null

    # 测量 VMAF
    VMAF=$(ffmpeg -i "probe_crf${CRF}.mp4" -i "$PROBE_CLIP" \
      -lavfi "[0:v][1:v]libvmaf=log_fmt=json:log_path=vmaf_crf${CRF}.json" \
      -f null - 2>&1 | grep "VMAF score" | awk '{print $NF}')

    # 获取文件大小（估算码率）
    SIZE=$(stat -f%z "probe_crf${CRF}.mp4")
    BITRATE=$(echo "scale=0; $SIZE * 8 / 60 / 1000" | bc)

    echo "CRF $CRF: ${BITRATE}Kbps, VMAF ${VMAF}"
done
```

## 7. 两遍编码（2-Pass Encoding）

### 7.1 1-Pass vs 2-Pass 原理

```
1-Pass ABR（单遍目标码率）：
  视频开始 → 编码器实时分配码率 → 视频结束
  问题：不知道后面内容的复杂度，码率分配不精确
       复杂场景码率超支 → 简单场景浪费 → 整体质量抖动

2-Pass ABR（双遍目标码率）：
  第一遍：分析整个视频，记录每帧的复杂度统计
         生成 ffmpeg2pass-0.log 分析文件
  第二遍：根据全局统计，精确分配每帧码率
         复杂场景多分配码率，简单场景少分配
  结果：整体平均码率精确达标，质量更均匀
```

**适用场景**：
```
CRF 模式    → 不需要 2-Pass（编码器自动控制质量，码率不固定）
ABR 模式    → 需要 2-Pass（目标是精确控制码率）
CBR 模式    → 使用 2-Pass 也有限（CBR 强制固定码率，不允许浮动）
```

---

### 7.2 2-Pass 编码命令

```bash
# H.264 2-Pass 编码
# 第一遍：分析（不输出视频，只生成 .log 文件）

  -c:v libx264 -b:v 4M \
  -pass 1 -an \
  -f null /dev/null

# 第二遍：编码

  -pass 2 \
  -c:a aac -b:a 128k \
```

### 7.3 2-Pass 质量对比

```
测试场景：4 分钟混合内容（动作 + 对话）, 目标 4Mbps

模式          实际码率    码率偏差    VMAF
1-Pass ABR   3.92Mbps   -2%         88.3
2-Pass ABR   4.01Mbps   +0.25%      91.7（+3.4 分）
CRF 23       4.45Mbps   +11%        93.2（质量最高，码率不固定）

结论：
- 需要严格控制码率（VOD 存储成本）→ 2-Pass ABR
- 需要最高质量（不在意码率波动）→ CRF
```

### 7.4 2-Pass 优化技巧

**技巧 1：第一遍加速（不影响质量）**
```bash

  -c:v libx264 -b:v 4M -preset ultrafast \
  -pass 1 -an -f null /dev/null

# 第二遍用正常预设
ffmpeg -i input.mp4 \
  -c:v libx264 -b:v 4M -preset medium \
  -pass 2 -c:a aac output.mp4
```

```bash

```

**技巧 3：多文件并行 2-Pass**
```bash

  -c:v libx264 -b:v 4M \
  -pass 1 -passlogfile video1_pass -an -f null /dev/null

  -pass 2 -passlogfile video1_pass \
```

## 8. 质量评估工作流程

### 8.1 完整评估流程

```
步骤 1：确定目标质量
  → 定义 VMAF 门槛（如 1080p ≥ 93）

步骤 2：探针编码
  → 提取代表片段（1-2 分钟）
  → 多 CRF/码率编码（6-8 个点）

步骤 3：质量测量
  → 测量每个文件的 VMAF 分数
  → 绘制码率-质量曲线

步骤 4：选择最优点
  → 找到满足 VMAF 目标的最低码率点
  → 设计码率梯队（1080p/720p/480p）

步骤 5：全片编码
  → 用确定的码率进行 2-Pass 编码
  → 验证最终文件 VMAF ≥ 目标值

步骤 6：批量应用
  → 相似内容类型使用相同梯队
  → 定期抽检质量（每周 5-10% 样本）
```

```bash
    # 获取码率
    BITRATE=$(ffprobe -v error -select_streams v:0 \
      -show_entries stream=bit_rate -of csv=p=0 "$OUTPUT")
    BITRATE=$((BITRATE / 1000))
    
    # 获取文件大小
    SIZE=$(stat -f%z "$OUTPUT")
    SIZE_MB=$(echo "scale=2; $SIZE / 1048576" | bc)
    
    # 输出到 CSV
    echo "$CRF,$BITRATE,$SIZE_MB,$VMAF,$PSNR,$SSIM,$ENCODE_TIME" >> results.csv
```

```go
func (s *QualityService) MeasureVMAF(ctx context.Context, distortedPath, referencePath string) (*VMAFReport, error) {
	reportPath := filepath.Join(s.workDir, "vmaf_report.json")
	
	// 构建 FFmpeg 命令
	cmd := exec.CommandContext(ctx, "ffmpeg",
		"-i", distortedPath,
		"-i", referencePath,
		"-lavfi", fmt.Sprintf("[0:v][1:v]libvmaf=log_fmt=json:log_path=%s:feature=name=psnr", reportPath),
		"-f", "null", "-",
	)
	
	// 执行测量
	if err := cmd.Run(); err != nil {
		return nil, fmt.Errorf("VMAF 测量失败: %w", err)
	}
	
	// 解析报告
	data, err := os.ReadFile(reportPath)
	if err != nil {
		return nil, fmt.Errorf("读取报告失败: %w", err)
	}
	
	var report VMAFReport
	if err := json.Unmarshal(data, &report); err != nil {
		return nil, fmt.Errorf("解析报告失败: %w", err)
	}
	
	return &report, nil
}

	case vmaf >= 95:
		return "excellent"
	case vmaf >= 90:
		return "high"
	case vmaf >= 85:
		return "medium"
	case vmaf >= 80:
		return "low"
	default:
		return "poor"
	}
```

### 9.2 Per-Title 编码实现

```go
// PerTitleEncoder 逐片编码器
type PerTitleEncoder struct {
	service *QualityService
}

// BitrateQualityPoint 码率-质量数据点
type BitrateQualityPoint struct {
	CRF     int     `json:"crf"`
	Bitrate int64   `json:"bitrate"` // Kbps
	VMAF    float64 `json:"vmaf"`
	PSNR    float64 `json:"psnr"`
}

// ProbeEncoding 探针编码（生成 RQ 曲线）
func (e *PerTitleEncoder) ProbeEncoding(ctx context.Context, sourcePath string, targetVMAF float64) ([]BitrateQualityPoint, error) {
	// 提取代表片段（中间 60 秒）
	probePath := filepath.Join(e.service.workDir, "probe.mp4")
	if err := e.extractProbeClip(ctx, sourcePath, probePath, 60); err != nil {
		return nil, err
	}
	
	// 多 CRF 点编码
	crfValues := []int{18, 22, 26, 30, 34, 38}
	points := make([]BitrateQualityPoint, 0, len(crfValues))
	
	for _, crf := range crfValues {
		outputPath := filepath.Join(e.service.workDir, fmt.Sprintf("probe_crf%d.mp4", crf))
		
		// CRF 编码
		cmd := exec.CommandContext(ctx, "ffmpeg",
			"-i", probePath,
			"-c:v", "libx264",
			"-crf", fmt.Sprintf("%d", crf),
			"-an", // 探针不需要音频
			outputPath, "-y",
		)
		if err := cmd.Run(); err != nil {
			return nil, fmt.Errorf("CRF %d 编码失败: %w", crf, err)
		}
		
		// 测量质量
		report, err := e.service.MeasureVMAF(ctx, outputPath, probePath)
		if err != nil {
			return nil, err
		}
		
		// 获取码率
		bitrate, err := e.getBitrate(outputPath)
		if err != nil {
			return nil, err
		}
		
		points = append(points, BitrateQualityPoint{
			CRF:     crf,
			Bitrate: bitrate,
			VMAF:    report.PooledMetrics.VMAF.Mean,
			PSNR:    report.PooledMetrics.PSNR.Mean,
		})
		
		// 清理临时文件
		os.Remove(outputPath)
	}
	
	return points, nil
}

// FindOptimalBitrate 在 RQ 曲线上找到最优码率点
func (e *PerTitleEncoder) FindOptimalBitrate(points []BitrateQualityPoint, targetVMAF float64) (int64, error) {
	// 找到第一个 VMAF ≥ targetVMAF 的点
	for i := 0; i < len(points)-1; i++ {
		if points[i].VMAF >= targetVMAF {
			return points[i].Bitrate, nil
		}
		
		// 线性插值（如果目标在两点之间）
		if points[i].VMAF > targetVMAF && points[i+1].VMAF < targetVMAF {
			// 插值计算最优码率
			ratio := (targetVMAF - points[i+1].VMAF) / (points[i].VMAF - points[i+1].VMAF)
			bitrate := int64(float64(points[i+1].Bitrate) + ratio*float64(points[i].Bitrate-points[i+1].Bitrate))
			return bitrate, nil
		}
	}
	
	return 0, fmt.Errorf("无法达到目标 VMAF %.1f", targetVMAF)
}

// extractProbeClip 提取代表片段
func (e *PerTitleEncoder) extractProbeClip(ctx context.Context, sourcePath, outputPath string, durationSec int) error {
	// 获取视频总时长
	cmd := exec.CommandContext(ctx, "ffprobe",
		"-v", "error",
		"-show_entries", "format=duration",
		"-of", "csv=p=0",
		sourcePath,
	)
	out, err := cmd.Output()
	if err != nil {
		return err
	}
	
	var totalDuration float64
	fmt.Sscanf(string(out), "%f", &totalDuration)
	
	// 从中间位置提取
	startTime := totalDuration/2 - float64(durationSec)/2
	
	cmd = exec.CommandContext(ctx, "ffmpeg",
		"-ss", fmt.Sprintf("%.2f", startTime),
		"-t", fmt.Sprintf("%d", durationSec),
		"-i", sourcePath,
		"-c", "copy",
		outputPath, "-y",
	)
	
	return cmd.Run()
}

// getBitrate 获取视频码率
func (e *PerTitleEncoder) getBitrate(videoPath string) (int64, error) {
	cmd := exec.Command("ffprobe",
		"-v", "error",
		"-select_streams", "v:0",
		"-show_entries", "stream=bit_rate",
		"-of", "csv=p=0",
		videoPath,
	)
	out, err := cmd.Output()
	if err != nil {
		return 0, err
	}
	
	var bitrate int64
	fmt.Sscanf(string(out), "%d", &bitrate)
	return bitrate / 1000, nil // 转 Kbps
}
```

```go
// BatchQualityReport 批量质量评估报告
type BatchQualityReport struct {
	TotalVideos   int                     `json:"total_videos"`
	PassedCount   int                     `json:"passed_count"`
	FailedCount   int                     `json:"failed_count"`
	Results       []VideoQualityResult    `json:"results"`
	Summary       QualitySummary          `json:"summary"`
}

type VideoQualityResult struct {
	VideoID       string  `json:"video_id"`
	OriginalPath  string  `json:"original_path"`
	EncodedPath   string  `json:"encoded_path"`
	VMAF          float64 `json:"vmaf"`
	PSNR          float64 `json:"psnr"`
	QualityLevel  string  `json:"quality_level"`
	Passed        bool    `json:"passed"`
	BitrateKbps   int64   `json:"bitrate_kbps"`
	FileSizeMB    float64 `json:"file_size_mb"`
}

type QualitySummary struct {
	AvgVMAF      float64 `json:"avg_vmaf"`
	MinVMAF      float64 `json:"min_vmaf"`
	MaxVMAF      float64 `json:"max_vmaf"`
	AvgBitrate   int64   `json:"avg_bitrate_kbps"`
}

// BatchEvaluate 批量评估视频质量
func (s *QualityService) BatchEvaluate(ctx context.Context, pairs []VideoPair, minVMAF float64) (*BatchQualityReport, error) {
	report := &BatchQualityReport{
		TotalVideos: len(pairs),
		Results:     make([]VideoQualityResult, 0, len(pairs)),
	}
	
	var totalVMAF float64
	var minVMAFValue = 100.0
	var maxVMAFValue = 0.0
	var totalBitrate int64
	
	for _, pair := range pairs {
		// 测量 VMAF
		vmafReport, err := s.MeasureVMAF(ctx, pair.EncodedPath, pair.OriginalPath)
		if err != nil {
			return nil, fmt.Errorf("测量 %s 失败: %w", pair.VideoID, err)
		}
		
		vmaf := vmafReport.PooledMetrics.VMAF.Mean
		psnr := 0.0
		if vmafReport.PooledMetrics.PSNR != nil {
			psnr = vmafReport.PooledMetrics.PSNR.Mean
		}
		
		// 获取文件信息
		bitrate, _ := s.getBitrate(pair.EncodedPath)
		fileSize, _ := s.getFileSizeMB(pair.EncodedPath)
		
		// 判断是否通过
		passed := vmaf >= minVMAF
		if passed {
			report.PassedCount++
		} else {
			report.FailedCount++
		}
		
		result := VideoQualityResult{
			VideoID:      pair.VideoID,
			OriginalPath: pair.OriginalPath,
			EncodedPath:  pair.EncodedPath,
			VMAF:         vmaf,
			PSNR:         psnr,
			QualityLevel: QualityLevel(vmaf),
			Passed:       passed,
			BitrateKbps:  bitrate,
			FileSizeMB:   fileSize,
		}
		
		report.Results = append(report.Results, result)
		
		// 更新统计
		totalVMAF += vmaf
		totalBitrate += bitrate
		if vmaf < minVMAFValue {
			minVMAFValue = vmaf
		}
		if vmaf > maxVMAFValue {
			maxVMAFValue = vmaf
		}
	}
	
	// 生成摘要
	report.Summary = QualitySummary{
		AvgVMAF:    totalVMAF / float64(len(pairs)),
		MinVMAF:    minVMAFValue,
		MaxVMAF:    maxVMAFValue,
		AvgBitrate: totalBitrate / int64(len(pairs)),
	}
	
	return report, nil
}

type VideoPair struct {
	VideoID      string
	OriginalPath string
	EncodedPath  string
}

func (s *QualityService) getFileSizeMB(path string) (float64, error) {
	info, err := os.Stat(path)
	if err != nil {
		return 0, err
	}
	return float64(info.Size()) / 1048576, nil
}
```

```go
	batchReport, err := qualityService.BatchEvaluate(ctx, pairs, 90.0)
	if err != nil {
		log.Fatal(err)
	}
	
	// 输出报告
	reportJSON, _ := json.MarshalIndent(batchReport, "", "  ")
	fmt.Printf("\n批量评估报告:\n%s\n", reportJSON)
	
	// 保存报告
	os.WriteFile("quality_report.json", reportJSON, 0644)
}
```

### 实践 2：设计你自己的码率梯队

**目标**：为一个视频确定 1080p/720p/480p 三档质量

```bash
#!/bin/bash
# design_ladder.sh - 自动设计码率梯队

INPUT="original.mp4"
TARGET_VMAF=90

design_tier() {
    local RESOLUTION=$1
    local SCALE=$2
    local TIER_NAME=$3
    local OUTPUT="tier_${TIER_NAME}.mp4"
    
    echo "=== 测试 ${TIER_NAME} (${RESOLUTION}) ==="
    
    # 先用 CRF 23 测试基准质量
    ffmpeg -i "$INPUT" \
      -vf scale=$RESOLUTION \
      -c:v libx264 -crf 23 \
      "$OUTPUT" -y 2>/dev/null
    
    # 测量 VMAF
    ffmpeg -i "$OUTPUT" -i "$INPUT" \
      -lavfi "[0:v]scale=${RESOLUTION}[d];[d][1:v]scale=${RESOLUTION}[r];[0:v][1:v]libvmaf=log_fmt=json:log_path=${TIER_NAME}_vmaf.json" \
      -f null - 2>/dev/null
    
    VMAF=$(jq -r '.pooled_metrics.vmaf.mean' "${TIER_NAME}_vmaf.json")
    BITRATE=$(ffprobe -v error -select_streams v:0 \
      -show_entries stream=bit_rate -of csv=p=0 "$OUTPUT")
    BITRATE_K=$((BITRATE / 1000))
    
    echo "  CRF 23 → ${BITRATE_K}Kbps, VMAF ${VMAF}"
    rm -f "$OUTPUT" "${TIER_NAME}_vmaf.json"
}

design_tier "1920:1080" "1080" "1080p"
design_tier "1280:720"  "720"  "720p"
design_tier "854:480"   "480"  "480p"

echo ""
echo "=== 推荐码率梯队 ==="
echo "基于上述测试结果调整到 VMAF ≥ ${TARGET_VMAF}"
```

### 实践 3：2-Pass 精确码率控制

```bash
# 目标：1080p 视频压缩到 4Mbps，VMAF ≥ 90

INPUT="original.mp4"
TARGET_BITRATE="4M"

# 第一遍分析
ffmpeg -i "$INPUT" \
  -c:v libx264 -b:v $TARGET_BITRATE \
  -pass 1 -an -f null /dev/null

# 第二遍编码
ffmpeg -i "$INPUT" \
  -c:v libx264 -b:v $TARGET_BITRATE -preset slow \
  -pass 2 -c:a aac -b:a 128k \
  output_2pass.mp4

# 验证结果
echo "=== 2-Pass 编码验证 ==="
echo "实际码率:"
ffprobe -v error -select_streams v:0 \
  -show_entries stream=bit_rate -of csv=p=0 output_2pass.mp4

echo "VMAF 评分:"
ffmpeg -i output_2pass.mp4 -i "$INPUT" \
  -lavfi "[0:v][1:v]libvmaf" -f null - 2>&1 | grep "VMAF score"

# 清理
rm -f ffmpeg2pass-*.log
```

## 11. 本章总结

本章从质量评估理论出发，系统讲解了 PSNR、SSIM、VMAF 三大指标的原理和使用场景，重点掌握了以下内容：

**质量评估基础**：
- PSNR：简单快速，但与人眼感知相关性弱
- SSIM：考虑结构信息，准确度中等
- VMAF：机器学习融合模型，目前行业标准，与主观评分最接近

**工程化测量**：
- FFmpeg `libvmaf` 滤镜测量质量
- JSON 报告解析，逐帧数据分析
- 批量测试脚本，生成 RQ 曲线

**码率梯队设计**：
- 固定梯队 vs Per-Title 动态梯队
- 关键帧对齐确保无缝切换
- Netflix/Apple HLS 行业标准参考

**两遍编码**：
- 1-Pass 简单快速，2-Pass 精确控制码率
- 相同码率下 2-Pass VMAF 提升 3-5 分
- 需要严格码率控制时首选 2-Pass ABR

**Go 工程集成**：
- `QualityService` 封装 VMAF 测量
- `PerTitleEncoder` 实现探针编码和最优码率选择
- `BatchEvaluate` 支持 CI/CD 质量门控

## 术语表

| 术语 | 英文全称 | 说明 |
|------|----------|------|
| PSNR | Peak Signal-to-Noise Ratio | 峰值信噪比，基于像素差异的质量指标 |
| SSIM | Structural Similarity Index | 结构相似度指数，考虑亮度/对比度/结构三维度 |
| VMAF | Video Multi-Method Assessment Fusion | 视频多方法评估融合，Netflix 开发的机器学习质量模型 |
| MOS | Mean Opinion Score | 平均主观评分，人类观看者的主观评价 |
| ABR | Adaptive Bitrate | 自适应码率，根据网络动态切换质量档位 |
| ABR Ladder | Adaptive Bitrate Ladder | 码率梯队，多个分辨率/码率组合档位 |
| Per-Title | Per-Title Encoding | 逐片编码，针对每段内容动态确定最优码率 |
| GOP | Group of Pictures | 图像组，两个关键帧之间的帧序列 |
| CRF | Constant Rate Factor | 恒定质量因子，控制视频质量的编码参数 |
| 2-Pass | Two-Pass Encoding | 两遍编码，第一遍分析，第二遍精确控制码率 |
| RQ 曲线 | Rate-Quality Curve | 码率-质量曲线，表示不同码率下对应的质量水平 |
| VIF | Visual Information Fidelity | 视觉信息保真度，VMAF 的子特征之一 |
| DLM | Detail Loss Metric | 细节损失度量，VMAF 的子特征之一 |
| HLS | HTTP Live Streaming | Apple 的 HTTP 自适应码率流媒体协议 |
| DASH | Dynamic Adaptive Streaming over HTTP | MPEG 定义的自适应码率流媒体协议 |

---

> **作者提示**：VMAF 分数 93 是 1080p 流媒体的黄金标准——低于此分用户会感知到质量下降，高于此分带宽提升带来的主观收益微乎其微。Per-title 编码的核心价值在于：用数据驱动决策，而不是依赖经验猜测码率。
