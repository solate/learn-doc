## 1. 音频基础：信号→数字的桥梁 {#1-音频基础}

视频的核心是像素帧，音频的核心是**采样点**。理解音频三个基础参数，才能看懂 FFmpeg 音频命令中那些数字的含义。

```
声音信号（连续波形）
         │
         ▼  采样（Sampling）
 ┌───────────────────────────────────────────┐
 │  时间轴上每隔固定间隔取一个测量值           │
 │  间隔越小（采样率越高）→ 还原越精细          │
 └───────────────────────────────────────────┘
         │
         ▼  量化（Quantization）
 ┌───────────────────────────────────────────┐
 │  每个采样值用 N bit 表示                   │
 │  N 越大（位深越高）→ 动态范围越宽            │
 └───────────────────────────────────────────┘
         │
         ▼  编码（Encoding）
 ┌───────────────────────────────────────────┐
 │  PCM（原始）→ AAC/MP3/Opus（压缩）         │
 └───────────────────────────────────────────┘
```

### 1.1 采样率：时域分辨率 {#11-采样率}

采样率（Sample Rate）决定每秒采集多少个样本，单位 Hz。根据**奈奎斯特定理**，要还原最高频率 F 的信号，采样率必须 ≥ 2F。人耳听觉上限约 20kHz，因此 CD 采用 44.1kHz（略高于 2×20kHz）。

| 采样率 | 可还原最高频率 | 典型场景 |
|--------|--------------|--------|
| 8 kHz  | 4 kHz        | 电话语音（VoIP）|
| 16 kHz | 8 kHz        | 宽带语音、语音识别 |
| 22.05 kHz | 11 kHz   | 旧版 MP3、游戏音效 |
| 44.1 kHz | 20 kHz    | CD 音质、音乐制作 |
| 48 kHz | 24 kHz       | 视频音轨、广播、视频会议 |
| 96 kHz | 48 kHz       | 专业录音室 |

**关键结论**：
- 视频的标准音频采样率是 **48kHz**，不是 44.1kHz
- 如果输入是 44.1kHz 音乐、输出到视频容器，FFmpeg 需要重采样到 48kHz
- WebRTC/实时通信默认使用 48kHz（Opus 要求）

---

### 1.2 位深：动态范围 {#12-位深}

位深（Bit Depth）决定每个采样点用多少 bit 表示振幅，影响**信噪比**和**动态范围**。

```
16-bit 采样：
  ┌──────────────────────────────────────┐
  │ 振幅范围：-32768 ~ +32767            │
  │ 理论信噪比（SNR）：96 dB             │
  │ 动态范围：96 dB（安静→最响）         │
  └──────────────────────────────────────┘

24-bit 采样：
  ┌──────────────────────────────────────┐
  │ 振幅范围：-8388608 ~ +8388607        │
  │ 理论信噪比：144 dB                   │
  │ 动态范围：144 dB（超过人耳极限）     │
  └──────────────────────────────────────┘
```

| 位深 | 动态范围 | 文件大小（立体声 48kHz） | 典型场景 |
|------|---------|------------------|---------|
| 8-bit | 48 dB | 86 KB/s | 电话级低质量 |
| 16-bit | 96 dB | 172 KB/s | CD、流媒体标准 |
| 24-bit | 144 dB | 258 KB/s | 专业录音、后期制作 |
| 32-bit float | 无限 | 344 KB/s | 中间处理格式 |

**为什么视频通常用 16-bit？**
- 人耳动态范围约 120 dB，16-bit 的 96 dB 对消费级已足够
- 经过 AAC/Opus 压缩后，位深的优势会被量化噪声抹平
- 24-bit 主要用于录音阶段，避免削波（clipping）

---

### 1.3 声道数：空间维度 {#13-声道数}

声道（Channel）决定音频的空间感。

```
声道布局示例
┌─────────────────────────────────────────────┐
│ Mono（单声道）                               │
│  ┌─────┐                                    │
│  │  C  │                                    │
│  └─────┘                                    │
│  - 文件大小：基准                             │
│  - 场景：语音通话、播客                       │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│ Stereo（立体声）                             │
│  ┌─────┐     ┌─────┐                        │
│  │  L  │     │  R  │                        │
│  └─────┘     └─────┘                        │
│  - 文件大小：2× Mono                         │
│  - 场景：音乐、视频默认                       │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│ 5.1 环绕声                                   │
│       ┌─────┐                               │
│       │  C  │（中置）                         │
│  ┌─────┐     ┌─────┐                        │
│  │  FL │     │  FR │（前左/右）              │
│  └─────┘     └─────┘                        │
│  ┌─────┐     ┌─────┐                        │
│  │  BL │     │  BR │（后左/右）              │
│  └─────┘     └─────┘                        │
│       ┌─────┐                               │
│       │ LFE │（低音炮）                       │
│       └─────┘                               │
│  - 文件大小：6× Mono（实际 LFE 带宽低）       │
│  - 场景：家庭影院、蓝光电影                   │
└─────────────────────────────────────────────┘
```

**声道数对码率的影响**：
```bash
# 单声道 AAC 128kbps
ffmpeg -i input.mp3 -ac 1 -c:a aac -b:a 128k mono.m4a

# 立体声 AAC 128kbps（每声道 64kbps）
ffmpeg -i input.mp3 -ac 2 -c:a aac -b:a 128k stereo.m4a

# 实际建议：立体声用 192-256kbps，单声道用 96-128kbps
```

## 2. 主流音频编码格式 {#2-主流音频编码格式}

音频编码器的核心目标：在保证感知质量的前提下，最大化压缩率。下面介绍四种主流格式及其技术原理。

### 2.1 AAC：流媒体的默认选择 {#21-aac}

**AAC（Advanced Audio Coding）** 是 MP3 的继任者，1997 年标准化，2026 年已成为流媒体事实标准。

#### 技术原理

```
AAC 编码管道
┌────────────┐   ┌────────────┐   ┌────────────┐
│  时域信号   │──▶│ MDCT 变换  │──▶│  量化编码  │
│  (PCM)    │   │ (频域表示)  │   │ (霍夫曼)   │
└────────────┘   └────────────┘   └────────────┘
                       │
                       ▼
              ┌─────────────────┐
              │ 心理声学模型     │
              │ (Psychoacoustic)│
              └─────────────────┘
                 ↓
         分配码率给不同频段
         （人耳敏感频段多分配）
```

**核心技术**：
- **MDCT（修正离散余弦变换）**：时域→频域，每个频段独立量化
- **心理声学模型**：利用人耳遮蔽效应（频域/时域遮蔽），删除不可察觉的频率成分
- **霍夫曼编码**：对量化后的系数无损压缩

#### AAC Profile 分类

| Profile | 全称 | 压缩率 | 质量 | 适用场景 |
|---------|------|--------|------|---------|
| AAC-LC | Low Complexity | 基准 | 标准 | 最常用，HLS/DASH/MP4 默认 |
| HE-AAC | High Efficiency | +30% | 中 | 低码率场景（32-64kbps） |
| HE-AACv2 | HE + PS | +50% | 低 | 极低码率（≤48kbps）|
| AAC-LD | Low Delay | -10% | 高 | 实时通信（已被 Opus 替代）|

**FFmpeg 中的 AAC 编码器**：
- `aac`（native）：FFmpeg 内置，质量中等，兼容性最好
- `libfdk_aac`：Fraunhofer FDK 库，质量最高，但需要手动编译（非自由许可）

**码率推荐**：
```
立体声推荐码率（AAC-LC）
┌──────────────────────────────────┐
│ 96 kbps  │ 可接受（广播级）       │
│ 128 kbps │ 标准质量（YouTube）    │
│ 192 kbps │ 高质量（Apple Music）  │
│ 256 kbps │ 透明质量（接近原始）   │
└──────────────────────────────────┘
```

---

### 2.2 Opus：现代低延迟编码器 {#22-opus}

**Opus** 是 IETF 标准化的开源编码器（2012），结合了 SILK（语音）和 CELT（音乐）两种技术，专为实时通信设计。

#### 双模式架构

```
Opus 编码器架构
            输入信号
               │
               ▼
       ┌──────────────┐
       │   自动检测    │
       │ 语音/音乐类型  │
       └──────────────┘
          ╱        ╲
         ╱          ╲
    SILK 模式      CELT 模式
   (语音优化)      (音乐优化)
    6-40 kbps      48-510 kbps
        ╲          ╱
         ╲        ╱
       混合模式（可选）
               │
               ▼
          Opus 码流
```

**技术优势**：
- **极低延迟**：5ms 算法延迟（AAC 需要 100-200ms）
- **宽码率范围**：6 kbps（窄带语音）到 510 kbps（全频段立体声）
- **动态码率调整**：实时根据网络抖动调整码率
- **前向纠错（FEC）**：丢包时可部分恢复
- **完全开源**：BSD 许可证，无专利费

**Opus vs AAC 对比**：

| 维度 | Opus | AAC |
|------|------|-----|
| 延迟 | 5-60 ms | 100-200 ms |
| 低码率质量 | 优秀（32kbps 接近 AAC 64kbps）| 中等 |
| 高码率质量 | 接近 AAC | 略优 |
| 浏览器支持 | Chrome/Firefox/Edge 原生 | Safari 原生，Chrome 需封装 |
| 适用场景 | WebRTC、游戏语音、播客 | 视频音轨、流媒体点播 |

---

### 2.3 MP3：遗留格式的生命力 {#23-mp3}

**MP3（MPEG-1 Audio Layer 3）** 诞生于 1993 年，虽然技术落后（同码率下质量低于 AAC），但兼容性无敌。

**为什么 2026 年仍在用 MP3？**
- 所有设备 100% 支持（包括老旧 MP3 播放器）
- 专利已过期（2017 年全球专利到期），完全免费
- LAME 编码器质量优化到位（VBR V2 约等于 AAC 128kbps）

**码率推荐**：
```
MP3 VBR 质量等级（LAME）
┌────────────────────────────────────┐
│ -q:a 0 │ 245 kbps │ 极高质量        │
│ -q:a 2 │ 190 kbps │ 高质量（推荐）  │
│ -q:a 4 │ 165 kbps │ 标准质量        │
│ -q:a 6 │ 130 kbps │ 可接受          │
└────────────────────────────────────┘
```

---

### 2.4 FLAC：无损压缩 {#24-flac}

**FLAC（Free Lossless Audio Codec）** 是无损压缩格式，压缩率约 50-60%，适合本地存储和转码源。

**使用场景**：
- 音乐收藏归档
- 转码工作流的中间格式（避免多代有损压缩）
- 高保真音频发烧友

**不适用场景**：
- 流媒体传输（带宽开销大）
- 实时通信（延迟高）

---

### 2.5 格式对比与选型矩阵 {#25-格式对比}

#### 全面对比表

| 维度 | AAC-LC | Opus | MP3 | FLAC |
|------|--------|------|-----|------|
| 压缩率 | 10:1 | 12:1 | 8:1 | 2:1 |
| 延迟 | 100ms | 5ms | 100ms | 50ms |
| 低码率质量 | 中 | 优秀 | 差 | N/A |
| 浏览器兼容性 | 全支持 | Chrome/FF | 全支持 | 部分 |
| 专利费 | 免费（2026）| 开源 | 免费（2017+）| 开源 |
| 推荐码率 | 128-192k | 64-96k | 190k（VBR）| N/A |

#### 选型决策树

```
需要音频编码
    │
    ├─ 实时通信/低延迟？
    │   └─ 是 → Opus（WebRTC 标准）
    │
    ├─ 视频音轨/点播流媒体？
    │   ├─ 标准场景 → AAC-LC
    │   └─ 极低码率（<64kbps）→ HE-AAC 或 Opus
    │
    ├─ 最大兼容性（老设备）？
    │   └─ 是 → MP3
    │
    └─ 无损归档？
        └─ 是 → FLAC
```

## 3. 音频转码命令详解 {#3-音频转码命令}

### 3.1 AAC 编码 {#31-aac-编码}

#### 使用 native aac 编码器

```bash
# 基本用法
ffmpeg -i input.mp3 -c:a aac -b:a 128k output.m4a

# 推荐配置（立体声）
ffmpeg -i input.wav -c:a aac -b:a 192k -ar 48000 output.m4a

# 单声道（播客/语音）
ffmpeg -i input.wav -c:a aac -b:a 96k -ac 1 -ar 48000 output.m4a
```

#### 使用 libfdk_aac（质量更高）

```bash
# 需要自定义编译 FFmpeg 并添加 --enable-libfdk-aac

# VBR 模式（推荐）
ffmpeg -i input.wav -c:a libfdk_aac -vbr 3 output.m4a

# VBR 质量等级：1（最低）到 5（最高）
# 3 = 约 128kbps，4 = 约 192kbps，5 = 约 256kbps

# CBR 模式
ffmpeg -i input.wav -c:a libfdk_aac -b:a 192k output.m4a
```

#### HE-AAC（低码率）

```bash
# HE-AAC v1（适合 32-64 kbps）
ffmpeg -i input.wav -c:a libfdk_aac -profile:a aac_he -b:a 48k output.m4a

# HE-AAC v2（适合 ≤32 kbps，自动转单声道）
ffmpeg -i input.wav -c:a libfdk_aac -profile:a aac_he_v2 -b:a 24k output.m4a
```

### 3.2 Opus 编码 {#32-opus-编码}

```bash
# 基本用法（VBR 模式）
ffmpeg -i input.mp3 -c:a libopus -b:a 64k output.opus

# 推荐配置：不同场景
# 语音通话（低码率）
ffmpeg -i input.wav -c:a libopus -b:a 24k -application voip output.opus

# 音乐点播（高质量）
ffmpeg -i input.wav -c:a libopus -b:a 128k -application audio output.opus

# 低延迟（游戏语音）
ffmpeg -i input.wav -c:a libopus -b:a 64k -application lowdelay output.opus
```

**Opus 参数说明**：
- `-application voip`：优化语音清晰度（6-40 kbps）
- `-application audio`：优化音乐保真度（默认）
- `-application lowdelay`：最小化延迟
- `-frame_duration`：帧大小（2.5/5/10/20/40/60 ms），默认 20ms

**容器选择**：
```bash
# WebM 容器（Web 标准）
ffmpeg -i input.mp3 -c:a libopus -b:a 96k output.webm

# Ogg 容器（传统）
ffmpeg -i input.mp3 -c:a libopus -b:a 96k output.ogg

# Matroska 容器
ffmpeg -i input.mp3 -c:a libopus -b:a 96k output.mka
```

---

### 3.3 MP3 编码 {#33-mp3-编码}

```bash
# VBR 模式（推荐）
ffmpeg -i input.wav -c:a libmp3lame -q:a 2 output.mp3

# VBR 质量等级 0-9（0 最好，9 最差）
# 2 = 约 190 kbps（高质量）
# 4 = 约 165 kbps（标准质量）

# CBR 模式
ffmpeg -i input.wav -c:a libmp3lame -b:a 192k output.mp3

# ABR 模式（平均码率）
ffmpeg -i input.wav -c:a libmp3lame -abr 1 -b:a 192k output.mp3
```

## 4. 音频重采样与声道处理 {#4-重采样与声道处理}

### 4.1 采样率转换 {#41-采样率转换}

```bash
# 转换为 48kHz（视频标准）
ffmpeg -i input_44100.wav -ar 48000 output_48000.wav

# 从 CD 质量（44.1kHz）到电话质量（8kHz）
ffmpeg -i input.wav -ar 8000 output.wav

# 指定重采样算法（默认是 swr）
ffmpeg -i input.wav -ar 48000 -af aresample=resampler=soxr output.wav
```

**重采样器对比**：
- `swr`（默认）：速度快，质量中等
- `soxr`：速度慢，质量最高（专业音频）

---

### 4.2 声道映射与下混 {#42-声道映射与下混}

#### 简单声道转换

```bash
# 立体声 → 单声道（简单下混）
ffmpeg -i stereo.mp3 -ac 1 mono.mp3

# 单声道 → 立体声（复制到两个声道）
ffmpeg -i mono.mp3 -ac 2 stereo.mp3
```

#### 5.1 → 立体声（高级下混）

```bash
# 方案1：FFmpeg 默认下混（简单但不精确）
ffmpeg -i 5.1_input.ac3 -ac 2 stereo.mp3

# 方案2：自定义下混矩阵（推荐）
ffmpeg -i 5.1_input.ac3 -af "pan=stereo|c0=FL+0.707*FC+0.707*BL|c1=FR+0.707*FC+0.707*BR" stereo.mp3
```

**下混公式解释**：
```
L（左输出）= FL（前左）+ 0.707×FC（中置）+ 0.707×BL（后左）
R（右输出）= FR（前右）+ 0.707×FC（中置）+ 0.707×BR（后右）

0.707 = -3dB（避免削波）
```

#### 提取特定声道

```bash
# 只保留左声道
ffmpeg -i stereo.mp3 -af "pan=mono|c0=FL" left.mp3

# 只保留右声道
ffmpeg -i stereo.mp3 -af "pan=mono|c0=FR" right.mp3

# 交换左右声道
ffmpeg -i stereo.mp3 -af "pan=stereo|c0=c1|c1=c0" swapped.mp3
```

## 5. 音量处理：从检测到归一化 {#5-音量处理}

### 5.1 EBU R128 响度标准 {#51-ebu-r128}

传统的峰值归一化（Peak Normalization）会导致不同音频响度不一致。**EBU R128** 是欧洲广播联盟制定的响度标准，基于人耳感知。

#### 核心概念

```
传统峰值归一化 vs 响度归一化

传统方式：
  音频A：峰值 -1dBFS，平均响度 -16 LUFS
  音频B：峰值 -1dBFS，平均响度 -23 LUFS
  → 两者峰值相同，但 A 听起来明显更响

EBU R128 方式：
  音频A：调整到 -23 LUFS
  音频B：调整到 -23 LUFS
  → 听感一致
```

**R128 参数**：
- **I（Integrated Loudness）**：整体响度目标，单位 LUFS
  - `-23 LUFS`：广播标准
  - `-16 LUFS`：播客/YouTube
  - `-14 LUFS`：Spotify/流媒体
- **TP（True Peak）**：真实峰值限制，单位 dBTP
  - `-1 dBTP`：防止 DAC 削波
- **LRA（Loudness Range）**：响度范围，单位 LU
  - 典型值：7-20 LU

---

### 5.2 两遍 loudnorm 流程 {#52-两遍-loudnorm}

`loudnorm` 滤镜需要两遍处理才能达到精确归一化。

#### 第一遍：测量

```bash
ffmpeg -i input.mp3 -af loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json -f null -
```

**输出示例**：
```json
{
  "input_i" : "-18.70",
  "input_tp" : "-0.10",
  "input_lra" : "7.70",
  "input_thresh" : "-29.04",
  "output_i" : "-15.93",
  "output_tp" : "-1.54",
  "output_lra" : "6.90",
  "target_offset" : "-0.07"
}
```

#### 第二遍：应用

```bash
ffmpeg -i input.mp3 -af loudnorm=I=-16:TP=-1.5:LRA=11:measured_I=-18.70:measured_TP=-0.10:measured_LRA=7.70:measured_thresh=-29.04:offset=-0.07:linear=true:print_format=summary -c:a aac -b:a 192k output.m4a
```

**参数说明**：
- `I=-16`：目标响度（LUFS）
- `TP=-1.5`：真实峰值限制（dBTP）
- `LRA=11`：目标响度范围（LU）
- `measured_*`：第一遍测量的值
- `offset`：目标偏移量
- `linear=true`：使用线性增益（更准确）

## 6. 混音与多轨处理 {#6-混音与多轨处理}

### 6.1 混合两路音频

```bash
# 简单混音（等权重）
ffmpeg -i audio1.mp3 -i audio2.mp3 -filter_complex "[0:a][1:a]amix=inputs=2:duration=first" output.mp3

# 调整权重（音频1占70%，音频2占30%）
ffmpeg -i audio1.mp3 -i audio2.mp3 -filter_complex "[0:a][1:a]amix=inputs=2:weights=0.7 0.3:duration=first" output.mp3
```

**duration 参数**：
- `longest`：以最长音频为准
- `shortest`：以最短音频为准
- `first`：以第一路音频为准（推荐）

### 实践 4：Go 封装音频处理工具

```go
package main

import (
	"encoding/json"
	"fmt"
	"os/exec"
	"regexp"
	"strconv"
)

// LoudnessInfo 响度测量结果
type LoudnessInfo struct {
	InputI     float64 `json:"input_i,string"`
	InputTP    float64 `json:"input_tp,string"`
	InputLRA   float64 `json:"input_lra,string"`
	InputThresh float64 `json:"input_thresh,string"`
	TargetOffset float64 `json:"target_offset,string"`
}

// MeasureLoudness 测量音频响度
func MeasureLoudness(inputPath string, targetLUFS float64) (*LoudnessInfo, error) {
	args := []string{
		"-i", inputPath,
		"-af", fmt.Sprintf("loudnorm=I=%.2f:TP=-1.5:LRA=11:print_format=json", targetLUFS),
		"-f", "null", "-",
	}

	cmd := exec.Command("ffmpeg", args...)
	output, err := cmd.CombinedOutput()
	if err != nil {
		return nil, fmt.Errorf("ffmpeg failed: %w", err)
	}

	// 提取 JSON 输出
	re := regexp.MustCompile(`(?s)\{[^}]*"input_i"[^}]*\}`)
	jsonStr := re.FindString(string(output))
	if jsonStr == "" {
		return nil, fmt.Errorf("no loudness info found")
	}

	var info LoudnessInfo
	if err := json.Unmarshal([]byte(jsonStr), &info); err != nil {
		return nil, err
	}

	return &info, nil
}

// NormalizeAudio 归一化音频到目标响度
func NormalizeAudio(inputPath, outputPath string, targetLUFS float64, info *LoudnessInfo) error {
	filterStr := fmt.Sprintf(
		"loudnorm=I=%.2f:TP=-1.5:LRA=11:measured_I=%.2f:measured_TP=%.2f:measured_LRA=%.2f:measured_thresh=%.2f:offset=%.2f:linear=true",
		targetLUFS,
		info.InputI,
		info.InputTP,
		info.InputLRA,
		info.InputThresh,
		info.TargetOffset,
	)

	args := []string{
		"-i", inputPath,
		"-af", filterStr,
		"-c:a", "aac", "-b:a", "192k",
		"-y", outputPath,
	}

	cmd := exec.Command("ffmpeg", args...)
	if output, err := cmd.CombinedOutput(); err != nil {
		return fmt.Errorf("normalization failed: %w\n%s", err, string(output))
	}

	return nil
}

func main() {
	input := "input.mp3"
	output := "output_normalized.m4a"
	targetLUFS := -16.0

	// 第一遍：测量
	fmt.Println("测量响度...")
	info, err := MeasureLoudness(input, targetLUFS)
	if err != nil {
		panic(err)
	}

	fmt.Printf("输入响度: %.2f LUFS\n", info.InputI)
	fmt.Printf("输入峰值: %.2f dBTP\n", info.InputTP)

	// 第二遍：归一化
	fmt.Println("归一化中...")
	if err := NormalizeAudio(input, output, targetLUFS, info); err != nil {
		panic(err)
	}

	fmt.Printf("完成：%s\n", output)
}
```

**运行**：
```bash
go run audio_normalize.go
```

### 实践 5：批量音频转码脚本

#!/bin/bash
# batch_transcode.sh - 批量转码音频为 AAC

INPUT_DIR="./inputs"

BITRATE="192k"

mkdir -p "$OUTPUT_DIR"

    output_file="$OUTPUT_DIR/${filename%.*}.m4a"

        -c:a aac -b:a "$BITRATE" -ar 48000 \
        "$output_file"
    
    if [ $? -eq 0 ]; then
        echo "✅ $filename -> ${filename%.*}.m4a"
    else
        echo "❌ $filename 转码失败"
    fi
done

echo "所有文件处理完成"

## 本篇小结 {#本篇小结}

1. **音频三要素**：
   - **采样率**：时域分辨率，视频标准 48kHz，音乐 CD 44.1kHz
   - **位深**：动态范围，16-bit 足够消费级，24-bit 用于录音
   - **声道数**：空间维度，立体声 = 2× 单声道文件大小

2. **编码器选型**：
   - **AAC-LC**：流媒体默认，128-192 kbps 立体声，兼容性最好
   - **Opus**：实时通信首选，64 kbps ≈ AAC 128 kbps，延迟仅 5ms
   - **MP3**：遗留格式，VBR V2（190kbps）约等于 AAC 128kbps，兼容性无敌
   - **FLAC**：无损压缩，仅用于归档和转码源

3. **关键命令**：
   - AAC 编码：`ffmpeg -i input.wav -c:a aac -b:a 192k -ar 48000 output.m4a`
   - Opus 编码：`ffmpeg -i input.wav -c:a libopus -b:a 64k -application voip output.opus`
   - 采样率转换：`-ar 48000`
   - 声道下混：`-ac 2` 或自定义 `pan` 滤镜

4. **响度归一化**：
   - 传统峰值归一化不保证听感一致
   - **EBU R128** 基于人耳感知，`loudnorm` 滤镜需要两遍处理
   - 播客/YouTube 推荐 `-16 LUFS`，广播标准 `-23 LUFS`
   - 真实峰值限制 `-1.5 dBTP` 防止 DAC 削波

5. **实用技巧**：
   - 5.1 → 立体声：使用自定义 `pan` 滤镜，系数 0.707 = -3dB
   - 混音：`amix` 滤镜可调整权重，`duration=first` 避免长度不一致
   - 多音轨：`-map 0:v -map 1:a -map 2:a` 保留所有音轨
   - Go 集成：用 `json` 格式解析 `loudnorm` 输出，自动化两遍流程

6. **性能对比**：
   - AAC：编码速度快，质量稳定，生态最成熟
   - Opus：编码速度中等，低码率质量最优，WebRTC 标准
   - MP3：编码速度最快，质量略低，但兼容性无可替代

7. **常见陷阱**：
   - 44.1kHz 音乐导入视频需要重采样到 48kHz
   - 单声道误用立体声码率会浪费带宽（应减半）
   - `loudnorm` 不加 `measured_*` 参数只是近似归一化
   - 5.1 默认下混可能音量过大，需手动调整系数

## 术语速查表 {#术语速查表}

| 术语 | 英文 | 解释 |
|------|------|------|
| 采样率 | Sample Rate | 每秒采样次数，单位 Hz，决定可还原的最高频率 |
| 位深 | Bit Depth | 每个采样点的比特数，决定动态范围和信噪比 |
| 声道 | Channel | 音频的空间维度，单声道/立体声/5.1 等 |
| AAC-LC | Advanced Audio Coding - Low Complexity | AAC 标准 Profile，流媒体默认 |
| HE-AAC | High Efficiency AAC | AAC 低码率 Profile，适合 32-64kbps |
| Opus | Opus | IETF 标准化的开源编码器，结合 SILK 和 CELT |
| MDCT | Modified Discrete Cosine Transform | 修正离散余弦变换，AAC/MP3 的核心算法 |
| LUFS | Loudness Units relative to Full Scale | 响度单位，EBU R128 标准 |
| dBTP | Decibels True Peak | 真实峰值，考虑过采样后的峰值 |
| 下混 | Downmix | 多声道转少声道（如 5.1 → 立体声）|
| 心理声学 | Psychoacoustics | 研究人耳感知特性，用于音频压缩 |
| VBR | Variable Bitrate | 可变码率，根据复杂度动态调整 |
