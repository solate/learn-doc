## 转封装 vs 转码

### 概念区分

**转封装（Remux）**：只改变容器格式，不改变编码

```
┌─────────────┐                    ┌─────────────┐
│   MP4 容器   │                    │   MKV 容器   │
│             │    -c copy         │             │
│  H.264 视频 │ ───────────────▶   │  H.264 视频 │
│  AAC 音频   │    (数据不变)       │  AAC 音频   │
└─────────────┘                    └─────────────┘
     3MB                                3MB
   (秒级完成)
```

**转码（Transcode）**：重新编码，改变压缩格式

```
┌─────────────┐                    ┌─────────────┐
│   MP4 容器   │                    │   MP4 容器   │
│             │   重新编码          │             │
│  H.264 视频 │ ───────────────▶   │  H.265 视频 │
│  AAC 音频   │    (数据改变)       │  AAC 音频   │
└─────────────┘                    └─────────────┘
     3MB                                1.5MB
   (分钟级完成)
```

---

### 对比表

| 维度 | 转封装（-c copy） | 转码（重新编码） |
|------|------------------|-----------------|
| 速度 | 秒级（受 IO 限制） | 分钟级（受 CPU/GPU 限制） |
| 质量 | 无损（数据不变） | 有损（重新压缩） |
| 文件大小 | 基本不变（容器开销微调） | 可以大幅改变 |
| CPU 占用 | 极低（只做封装） | 高（解码+编码） |
| 能否改变分辨率 | ❌ 不能 | ✅ 能 |
| 能否改变码率 | ❌ 不能 | ✅ 能 |
| 能否加滤镜/水印 | ❌ 不能 | ✅ 能 |
| 适用场景 | 格式转换、裁剪、合并 | 压缩、调整参数、加特效 |

## 流复制的工作原理

### 处理管道对比

**转码（完整管道）**：

```
┌─────────┐   ┌─────────┐   ┌────────┐   ┌─────────┐   ┌─────────┐
│ Demuxer │──▶│ Decoder │──▶│ Filter │──▶│ Encoder │──▶│  Muxer  │
│ 解封装  │   │  解码   │   │  滤镜  │   │  编码   │   │  封装   │
└─────────┘   └─────────┘   └────────┘   └─────────┘   └─────────┘
  MP4容器       H.264→YUV    调整像素      YUV→H.265    MKV容器
  (快)          (慢)         (慢)         (极慢)        (快)
```

**流复制（跳过中间三步）**：

```
┌─────────┐                                           ┌─────────┐
│ Demuxer │──────────────────────────────────────────▶│  Muxer  │
│ 解封装  │     直接复制压缩数据包                        │  封装   │
└─────────┘                                           └─────────┘
  MP4容器                                              MKV容器
  (快)                                                 (快)
    │                                                     ▲
    └────────────── H.264 数据包 ──────────────────────────┘
                   (不解码，不重编码)
```

**关键点**：
- 数据包（Packet）级别的直接复制
- 不经过解码器和编码器
- 只需要解析容器结构和重新打包

---

### 为什么这么快？

```bash
# 对比实验（1GB 视频文件）
# 转封装（-c copy）
time ffmpeg -i input.mp4 -c copy output.mkv
# 实际时间：5-10 秒（受硬盘 IO 限制）

# 转码（重新编码）
time ffmpeg -i input.mp4 -c:v libx264 -crf 23 output.mkv
# 实际时间：10-30 分钟（受 CPU/GPU 限制）
```

**速度差异原因**：
- 转封装：读取速度 ~500MB/s（SSD） → 写入速度 ~500MB/s
- 转码：编码速度 ~1-5fps（CPU），~30-60fps（GPU）

## 容器格式兼容性

### 常见容器支持的编码格式

| 容器 | 视频编码 | 音频编码 | 字幕 | 多音轨 | 章节 |
|------|---------|---------|------|--------|------|
| **MP4** | H.264, H.265, AV1 | AAC, MP3 | SRT, WebVTT | ✅ | ✅ |
| **MKV** | 几乎全部 | 几乎全部 | SRT, ASS, PGS | ✅ | ✅ |
| **FLV** | H.264, H.263 | AAC, MP3 | ❌ | ❌ | ❌ |
| **WebM** | VP8, VP9, AV1 | Vorbis, Opus | WebVTT | ✅ | ❌ |
| **TS** | H.264, H.265, MPEG-2 | AAC, MP3, AC3 | DVB Sub | ✅ | ❌ |
| **MOV** | ProRes, H.264, H.265 | AAC, PCM | SRT | ✅ | ✅ |

---

### 兼容性检查规则

**规则 1：视频编码必须兼容**

```bash
# ✅ 正确 - MP4 支持 H.264
ffmpeg -i input.mkv -c copy output.mp4

# ❌ 错误 - 传统 FLV 不支持 H.265
ffmpeg -i input_hevc.mp4 -c copy output.flv
# 报错：Codec hevc not currently supported in container

# ✅ 正确 - 用 MKV（万能容器）
ffmpeg -i input_hevc.mp4 -c copy output.mkv
```

---

**规则 2：音频编码必须兼容**

```bash
# ❌ 错误 - MP4 标准不支持 Opus
ffmpeg -i input_opus.mkv -c copy output.mp4
# 可能播放失败或无声音

# ✅ 正确 - 转换音频编码
ffmpeg -i input_opus.mkv -c:v copy -c:a aac output.mp4
```

---

**规则 3：字幕格式必须兼容**

```bash
# ✅ 正确 - MKV 支持 ASS 字幕
ffmpeg -i video.mp4 -i subtitle.ass -c copy -c:s copy output.mkv

# ❌ 错误 - MP4 不支持 ASS
ffmpeg -i video.mp4 -i subtitle.ass -c copy -c:s copy output.mp4
# 报错：Subtitle codec ass not currently supported in container

# ✅ 正确 - 转换为 MP4 支持的 MOV_TEXT
ffmpeg -i video.mp4 -i subtitle.ass -c:v copy -c:a copy -c:s mov_text output.mp4
```

---

### 快速兼容性测试

```bash
# 测试转封装是否成功
ffmpeg -i input.mkv -c copy -t 10 test_output.mp4

# 如果成功（无报错），说明编码兼容
# 如果失败，用 ffprobe 查看编码格式
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name -of default=noprint_wrappers=1:nokey=1 input.mkv
```

## 基础转封装操作

### 1. 简单格式转换

```bash
# MP4 → MKV
ffmpeg -i input.mp4 -c copy output.mkv

# FLV → MP4（常见于下载的直播录像）
ffmpeg -i livestream.flv -c copy output.mp4

# AVI → MP4
ffmpeg -i old_video.avi -c copy output.mp4

# MOV → MP4
ffmpeg -i iphone_video.mov -c copy output.mp4
```

---

### 2. 提取音频轨

```bash
# 提取音频（保留编码）
ffmpeg -i video.mp4 -vn -c:a copy audio.aac

# 提取音频（转换为 MP3）
ffmpeg -i video.mp4 -vn -c:a libmp3lame -q:a 2 audio.mp3

# 提取多音轨中的第二轨
ffmpeg -i video.mkv -map 0:a:1 -c copy audio_track2.aac
```

---

### 3. 提取视频轨（去掉音频）

```bash
# 只保留视频流
ffmpeg -i video.mp4 -an -c:v copy video_only.mp4

# 保留视频和字幕，去掉音频
ffmpeg -i video.mkv -an -c:v copy -c:s copy video_sub_only.mkv
```

---

### 4. 裁剪视频（时间范围）

```bash
# 从第 10 秒开始，裁剪 30 秒
ffmpeg -ss 10 -i input.mp4 -t 30 -c copy output.mp4

# 从第 1 分钟到第 2 分钟
ffmpeg -ss 00:01:00 -to 00:02:00 -i input.mp4 -c copy output.mp4

# 混合方案（精确裁剪）
ffmpeg -ss 00:00:55 -i input.mp4 -ss 5 -t 60 -c copy output.mp4
```

**注意**：
- `-ss` 在 `-i` 前：快速但不精确（关键帧限制）
- `-ss` 在 `-i` 后：精确但慢（需要解码）
- 混合方案：快速跳到接近位置，再精确裁剪

---

### 5. 合并多个文件（相同编码）

**方法 1：使用 concat 协议（简单，但有限制）**

```bash
# 创建文件列表
cat > list.txt << EOF
file 'part1.mp4'
file 'part2.mp4'
file 'part3.mp4'
EOF

# 合并
ffmpeg -f concat -safe 0 -i list.txt -c copy merged.mp4
```

**限制**：
- 所有文件必须相同编码、分辨率、帧率
- 文件路径不能包含特殊字符（或设置 `-safe 0`）

---

**方法 2：使用 concat 滤镜（灵活，但需要重编码）**

```bash
# 不适合流复制场景，需要重编码
ffmpeg -i part1.mp4 -i part2.mp4 \
  -filter_complex "[0:v][0:a][1:v][1:a]concat=n=2:v=1:a=1[v][a]" \
  -map "[v]" -map "[a]" output.mp4
```

---

### 6. 分割大文件

```bash
# 按时长分割（每 600 秒一个文件）
ffmpeg -i long_video.mp4 -c copy -f segment -segment_time 600 -reset_timestamps 1 output_%03d.mp4

# 按文件大小分割（每 100MB 一个文件）
ffmpeg -i long_video.mp4 -c copy -f segment -segment_size 100M output_%03d.mp4
```

**输出示例**：
```
output_000.mp4
output_001.mp4
output_002.mp4
```

## 元数据处理

### 查看元数据

```bash
# 查看所有元数据
ffprobe -v quiet -show_format -show_streams input.mp4 | grep TAG

# 只看容器级别的元数据
ffprobe -v quiet -show_entries format_tags input.mp4
```

**常见元数据标签**：
- `title`：标题
- `artist`：艺术家/作者
- `album`：专辑
- `date`：发布日期
- `comment`：备注
- `creation_time`：创建时间

---

### 添加/修改元数据

```bash
# 设置标题和作者
ffmpeg -i input.mp4 -c copy \
  -metadata title="我的视频" \
  -metadata artist="作者名" \
  output.mp4

# 设置多个元数据
ffmpeg -i input.mp4 -c copy \
  -metadata title="教程视频" \
  -metadata artist="FFmpeg Tutorial" \
  -metadata date="2025-07-28" \
  -metadata comment="示例视频" \
  output.mp4
```

---

### 删除所有元数据

```bash
# 清除容器级别的元数据
ffmpeg -i input.mp4 -c copy -map_metadata -1 output.mp4

# 清除流级别的元数据
ffmpeg -i input.mp4 -c copy -map_metadata:s -1 output.mp4

# 清除所有元数据
ffmpeg -i input.mp4 -c copy -map_metadata -1 -map_metadata:s -1 output.mp4
```

---

### 流级别的元数据（语言、标题）

```bash
# 设置音轨语言
ffmpeg -i video.mp4 -i audio_cn.aac -i audio_en.aac \
  -map 0:v -map 1:a -map 2:a \
  -c copy \
  -metadata:s:a:0 language=zho -metadata:s:a:0 title="中文" \
  -metadata:s:a:1 language=eng -metadata:s:a:1 title="English" \
  output.mkv

# 设置字幕语言
ffmpeg -i video.mp4 -i subtitle_cn.srt -i subtitle_en.srt \
  -map 0:v -map 0:a -map 1:s -map 2:s \
  -c copy -c:s srt \
  -metadata:s:s:0 language=zho -metadata:s:s:0 title="简体中文" \
  -metadata:s:s:1 language=eng -metadata:s:s:1 title="English" \
  output.mkv
```

**语言代码**（ISO 639-2）：
- `zho`：中文
- `eng`：英语
- `jpn`：日语
- `kor`：韩语
- `fra`：法语
- `deu`：德语

## 多流处理

### 保留所有流

```bash
# 默认行为（只保留"最佳"流）
ffmpeg -i multi_track.mkv -c copy output.mp4
# 可能丢失第 2、3 音轨和字幕

# 保留所有流
ffmpeg -i multi_track.mkv -map 0 -c copy output.mkv
```

---

### 选择特定流

```bash
# 视频流 + 第二音轨
ffmpeg -i video.mkv -map 0:v:0 -map 0:a:1 -c copy output.mp4

# 视频流 + 所有音轨 + 所有字幕
ffmpeg -i video.mkv -map 0:v -map 0:a -map 0:s -c copy output.mkv
```

---

### 排除特定流

```bash
# 排除所有字幕流
ffmpeg -i video.mkv -map 0 -map -0:s -c copy output.mp4

# 排除第二音轨
ffmpeg -i video.mkv -map 0 -map -0:a:1 -c copy output.mp4
```

---

### 合并不同来源的流

```bash
# 视频来自一个文件，音频来自另一个文件
ffmpeg -i video_only.mp4 -i audio_only.aac \
  -map 0:v -map 1:a \
  -c copy output.mp4

# 视频 + 多音轨 + 字幕
ffmpeg -i video.mp4 -i audio_cn.aac -i audio_en.aac -i subtitle.srt \
  -map 0:v -map 1:a -map 2:a -map 3:s \
  -c:v copy -c:a copy -c:s srt \
  -metadata:s:a:0 language=zho -metadata:s:a:0 title="中文" \
  -metadata:s:a:1 language=eng -metadata:s:a:1 title="English" \
  -metadata:s:s:0 language=zho \
  output.mkv
```

## 常见问题与限制

### 问题 1：关键帧导致的裁剪不精确

**现象**：使用 `-ss` 输入 seek 裁剪后，视频开头几秒画面花屏或黑屏

**原因**：
- `-c copy` 不解码，只能从关键帧（I 帧）开始
- 如果 `-ss` 跳到的位置不是关键帧，会包含前面的 P/B 帧
- P/B 帧依赖关键帧解码，单独播放会花屏

**解决方案**：

```bash
# 方案 1：输出 seek（精确但慢）
ffmpeg -i input.mp4 -ss 10 -t 30 -c copy output.mp4

# 方案 2：混合方案
ffmpeg -ss 9 -i input.mp4 -ss 1 -t 30 -c copy output.mp4

# 方案 3：重新编码（最精确）
ffmpeg -ss 10 -i input.mp4 -t 30 -c:v libx264 -crf 23 output.mp4
```

---

### 问题 2：容器不支持的编码格式

**现象**：转封装报错 `Codec xxx not currently supported in container`

**示例**：

```bash
# FLV 不支持 H.265
ffmpeg -i hevc_video.mp4 -c copy output.flv
# 报错：Codec hevc not currently supported in container
```

**解决方案**：

```bash
# 方案 1：用支持的容器（MKV 万能）
ffmpeg -i hevc_video.mp4 -c copy output.mkv

# 方案 2：转换编码格式
ffmpeg -i hevc_video.mp4 -c:v libx264 -crf 23 output.flv
```

---

### 问题 3：时间戳不连续

**现象**：合并多个文件后，播放进度条跳动，快进失败

**原因**：
- 每个文件的 PTS（播放时间戳）从 0 开始
- 合并后时间戳重复或不连续

**解决方案**：

```bash
# 使用 -avoid_negative_ts make_zero
ffmpeg -f concat -safe 0 -i list.txt \
  -c copy \
  -avoid_negative_ts make_zero \
  output.mp4

# 或者重置时间戳
ffmpeg -f concat -safe 0 -i list.txt \
  -c copy \
  -fflags +genpts \
  output.mp4
```

---

### 问题 4：音视频不同步

**现象**：转封装后，音频和视频不同步

**原因**：
- 源文件时间戳错误
- 容器格式对时间戳的处理不同

**诊断**：

```bash
# 检查第一帧的 PTS
ffprobe -v error -select_streams v:0 -show_frames -show_entries frame=pkt_pts_time input.mp4 | head -5
ffprobe -v error -select_streams a:0 -show_frames -show_entries frame=pkt_pts_time input.mp4 | head -5
```

**解决方案**：

```bash
# 方案 1：重新生成时间戳
ffmpeg -i input.mp4 -c copy -fflags +genpts output.mp4

# 方案 2：重新编码（最可靠）
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -c:a aac output.mp4
```

---

### 限制总结

| 操作 | 流复制（-c copy） | 重新编码 |
|------|------------------|---------|
| 改变分辨率 | ❌ 不支持 | ✅ 支持 |
| 改变码率 | ❌ 不支持 | ✅ 支持 |
| 改变帧率 | ❌ 不支持 | ✅ 支持 |
| 加水印/字幕 | ❌ 不支持 | ✅ 支持 |
| 旋转视频 | ❌ 不支持（元数据可以）| ✅ 支持 |
| 调整音量 | ❌ 不支持 | ✅ 支持 |
| 裁剪画面 | ❌ 不支持 | ✅ 支持 |
| 格式转换 | ✅ 支持（需兼容）| ✅ 支持 |
| 时间裁剪 | ✅ 支持（关键帧限制）| ✅ 支持 |

## 性能对比与优化

### 实际性能测试

- 文件：1080p H.264 视频，90 分钟，5GB
- CPU：Intel i7-10700K
- 硬盘：NVMe SSD

```bash
# 测试 1：MP4 → MKV（流复制）
time ffmpeg -i input.mp4 -c copy output.mkv
# 实际时间：8 秒

# 测试 2：MP4 → MKV（重新编码）

# 实际时间：25 分钟
# CPU 占用：90%

```

**速度对比**：
- 流复制：8 秒（基准）
- CPU 编码：187.5 倍慢
- GPU 编码：37.5 倍慢

### 优化建议

**1. 大文件处理**：

```bash
# 使用 buffer 优化
ffmpeg -i input.mp4 -c copy -max_muxing_queue_size 1024 output.mkv

# 调整 IO buffer
ffmpeg -analyzeduration 10M -probesize 10M -i input.mp4 -c copy output.mkv
```

---

**2. 批量处理**：

```bash
#!/bin/bash
# 批量转封装
for file in *.flv; do
    output="${file%.flv}.mp4"
    ffmpeg -y -v error -i "$file" -c copy "$output" &
    
    # 限制并发数（避免 IO 瓶颈）
    if (( $(jobs -r | wc -l) >= 4 )); then
        wait -n
    fi
done
wait
echo "所有文件处理完成"
```

---

**3. 网络流转本地**：

```bash
# RTSP 流录制（流复制）
ffmpeg -rtsp_transport tcp -i rtsp://camera/stream \
  -c copy -t 3600 output.mp4

# RTMP 推流转拉流
ffmpeg -i rtmp://live/stream -c copy -f flv output.flv
```

### 实践 7：批量转封装脚本（Go 版本）

```go
package main

import (
	"fmt"
	"os"
	"os/exec"
	"path/filepath"
	"sync"
)

func remuxFile(inputPath, outputPath string) error {
	cmd := exec.Command("ffmpeg",
		"-y",
		"-v", "error",
		"-i", inputPath,
		"-c", "copy",
		outputPath,
	)
	
	output, err := cmd.CombinedOutput()
	if err != nil {
		return fmt.Errorf("转封装失败: %s\n%s", err, string(output))
	}
	
	return nil
}

func main() {
	if len(os.Args) < 2 {
		fmt.Println("用法: go run remux.go <input_dir>")
		return
	}
	
	inputDir := os.Args[1]
	
	// 查找所有 .flv 文件
	files, err := filepath.Glob(filepath.Join(inputDir, "*.flv"))
	if err != nil {
		fmt.Printf("查找文件失败: %v\n", err)
		return
	}
	
	fmt.Printf("找到 %d 个 FLV 文件\n", len(files))
	
	// 并发处理（限制 4 个并发）
	var wg sync.WaitGroup
	semaphore := make(chan struct{}, 4)
	
	for _, inputPath := range files {
		wg.Add(1)
		
		go func(input string) {
			defer wg.Done()
			
			semaphore <- struct{}{}        // 获取信号量
			defer func() { <-semaphore }() // 释放信号量
			
			// 生成输出文件名
			output := input[:len(input)-4] + ".mp4"
			
			fmt.Printf("处理: %s\n", filepath.Base(input))
			
			if err := remuxFile(input, output); err != nil {
				fmt.Printf("❌ %s: %v\n", filepath.Base(input), err)
			} else {
				fmt.Printf("✅ %s -> %s\n", filepath.Base(input), filepath.Base(output))
			}
		}(inputPath)
	}
	
	wg.Wait()
	fmt.Println("所有文件处理完成")
}
```

**运行**：
```bash
go run remux.go /path/to/videos/
```

## 本篇小结

1. **转封装 vs 转码**：
   - 转封装：只改容器，不改编码，秒级完成
   - 转码：重新编码，可以改参数，分钟级完成

2. **流复制原理**：
   - 跳过解码、滤镜、编码三个阶段
   - 直接复制压缩数据包（Packet）
   - 速度受 IO 限制，不受 CPU/GPU 限制

3. **容器兼容性**：
   - MP4：支持 H.264/H.265/AV1 + AAC/MP3
   - MKV：万能容器，几乎支持所有编码
   - FLV：只支持 H.264/H.263 + AAC/MP3
   - WebM：只支持 VP8/VP9/AV1 + Vorbis/Opus

4. **基础操作**：
   - 格式转换：`ffmpeg -i input.mp4 -c copy output.mkv`
   - 提取音频：`ffmpeg -i video.mp4 -vn -c:a copy audio.aac`
   - 裁剪视频：`ffmpeg -ss 10 -i input.mp4 -t 30 -c copy output.mp4`
   - 合并文件：`ffmpeg -f concat -safe 0 -i list.txt -c copy output.mp4`

5. **元数据处理**：
   - 添加：`-metadata title="标题"`
   - 删除：`-map_metadata -1`
   - 流级别：`-metadata:s:a:0 language=zho`

6. **常见问题**：
   - 关键帧限制：输入 seek 不精确，用混合方案
   - 容器不兼容：用 MKV 或转换编码
   - 时间戳问题：用 `-fflags +genpts`
   - 音视频不同步：检查 PTS 或重新编码

7. **性能优化**：
   - 流复制比转码快 100+ 倍
   - 批量处理限制并发数（避免 IO 瓶颈）
   - 大文件调整 buffer：`-max_muxing_queue_size 1024`

8. **适用场景**：
   - ✅ 格式转换、裁剪、合并、提取流
   - ❌ 改分辨率、改码率、加水印、加滤镜

## 关键术语速查表

| 术语 | 英文 | 解释 |
|------|------|------|
| 转封装 | Remux | 只改变容器格式，不改变编码数据 |
| 流复制 | Stream Copy | 不解码不编码，直接复制数据包（`-c copy`） |
| 容器兼容性 | Container Compatibility | 容器支持哪些编码格式 |
| 元数据 | Metadata | 标题、作者、日期等描述信息 |
| 关键帧 | Keyframe / I-frame | 独立编码的完整帧，不依赖其他帧 |
| GOP | Group of Pictures | 一组帧，从一个关键帧到下一个关键帧 |
| PTS | Presentation Time Stamp | 播放时间戳，决定帧何时显示 |
| DTS | Decode Time Stamp | 解码时间戳，决定帧何时解码 |
| 数据包 | Packet | 压缩后的数据单元（解封装后、解码前） |
| 万能容器 | Universal Container | MKV，支持几乎所有编解码格式 |
