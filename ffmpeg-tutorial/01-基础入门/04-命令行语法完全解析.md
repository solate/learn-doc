## FFmpeg 命令基本结构

### 完整语法模板

```
ffmpeg [全局选项] [输入1选项] -i 输入1 [输入2选项] -i 输入2 ... [输出1选项] 输出1 [输出2选项] 输出2 ...
```

### 最简单的命令

```bash
ffmpeg -i input.mp4 output.mp4
```

**这个命令做了什么？**
1. 读取 `input.mp4`
2. 自动检测编码格式
3. 自动选择"最佳"视频流和音频流
4. 使用默认编码器重新编码
5. 输出到 `output.mp4`

**问题**：这种"自动"行为可能不是你想要的！

---

## 核心规则：参数顺序决定作用对象

### 规则 1：`-i` 前的参数作用于输入

```bash
ffmpeg -ss 10 -t 30 -i input.mp4 output.mp4
```

**解释**：
- `-ss 10`：从输入文件的第 10 秒开始读取（快速，但可能不精确）
- `-t 30`：只读取 30 秒
- **这两个参数作用于 `input.mp4`**

---

### 规则 2：`-i` 后的参数作用于输出

```bash
ffmpeg -i input.mp4 -ss 10 -t 30 output.mp4
```

**解释**：
- `-ss 10`：从输出的第 10 秒开始（精确，但慢，需要先解码）
- `-t 30`：输出 30 秒
- **这两个参数作用于 `output.mp4`**

---

### 对比：输入 seek vs 输出 seek

```bash
# 方案 1：输入 seek（快速但不精确）
ffmpeg -ss 00:01:00 -i input.mp4 -c copy output.mp4
# 速度：几秒
# 问题：可能从非关键帧开始，导致前几秒画面花屏

# 方案 2：输出 seek（精确但慢）
ffmpeg -i input.mp4 -ss 00:01:00 -c copy output.mp4
# 速度：较慢（需要解码到 1 分钟）
# 优点：精确从关键帧开始

# 方案 3：混合方案（推荐）
ffmpeg -ss 00:00:55 -i input.mp4 -ss 5 -t 10 -c copy output.mp4
# 速度：快
# 精度：高
# 原理：先快速跳到 55 秒（接近目标），再精确裁剪 5-15 秒
```

## 全局选项

### `-y` / `-n`（覆盖输出文件）

```bash
# 自动覆盖输出文件，不询问
ffmpeg -y -i input.mp4 output.mp4

# 不覆盖输出文件，文件存在则报错退出
ffmpeg -n -i input.mp4 output.mp4
```

**生产环境建议**：明确指定 `-y` 或 `-n`，避免交互式询问阻塞脚本

---

### `-v` / `-loglevel`（日志级别）

```bash
# 安静模式（只输出错误）
ffmpeg -v error -i input.mp4 output.mp4

# 正常模式（默认）
ffmpeg -v info -i input.mp4 output.mp4

# 详细模式（调试用）
ffmpeg -v debug -i input.mp4 output.mp4
```

**日志级别**：
- `quiet`：完全静默
- `panic`：只输出致命错误
- `fatal`：致命错误
- `error`：错误信息
- `warning`：警告信息
- `info`：信息（默认）
- `verbose`：详细信息
- `debug`：调试信息
- `trace`：跟踪信息（最详细）

**推荐**：
- 生产环境：`-v warning`（只看警告和错误）
- 调试问题：`-v debug`
- 脚本解析：`-v error`（避免干扰输出）

---

### `-threads`（线程数）

```bash
# 自动检测 CPU 核心数（推荐）
ffmpeg -threads 0 -i input.mp4 output.mp4

# 手动指定 4 线程
ffmpeg -threads 4 -i input.mp4 output.mp4
```

**注意**：
- `-threads 0` 表示自动检测（不是单线程）
- 编码器线程数 ≠ 进程线程数
- 某些编码器（如 libx264）有自己的线程参数

---

### `-progress`（进度输出）

```bash
# 输出到文件
ffmpeg -progress progress.txt -i input.mp4 output.mp4

# 输出到标准输出（脚本解析用）
ffmpeg -progress /dev/stdout -i input.mp4 output.mp4
```

**输出格式**（键值对）：
```
frame=123
fps=30.00
stream_0_0_q=28.0
total_size=1048576
out_time_us=4000000
out_time_ms=4000000
out_time=00:00:04.000000
dup_frames=0
drop_frames=0
speed=1.5x
progress=continue
```

**解析进度百分比**：

## 输入选项

### `-f`（强制输入格式）

```bash
# 从 RTSP 摄像头读取
ffmpeg -f rtsp -i rtsp://192.168.1.100/stream output.mp4

# 从屏幕录制（macOS）
ffmpeg -f avfoundation -i "1:0" screen.mp4

# 从原始 YUV 文件读取
ffmpeg -f rawvideo -pixel_format yuv420p -video_size 1920x1080 -i input.yuv output.mp4
```

---

### `-ss`（输入 seek）

```bash
# 从第 10 秒开始读取
ffmpeg -ss 10 -i input.mp4 -c copy output.mp4

# 时间格式支持多种
ffmpeg -ss 00:01:30 -i input.mp4 -c copy output.mp4  # 1分30秒
ffmpeg -ss 90 -i input.mp4 -c copy output.mp4        # 90秒
```

---

### `-t` / `-to`（输入时长）

```bash
# 只读取 30 秒
ffmpeg -i input.mp4 -t 30 -c copy output.mp4

# 读取到第 60 秒结束
ffmpeg -i input.mp4 -to 60 -c copy output.mp4

# 组合：从第 10 秒读取 30 秒
ffmpeg -ss 10 -i input.mp4 -t 30 -c copy output.mp4
```

---

### `-r`（强制输入帧率）

```bash
# 强制以 30fps 读取（忽略容器声明的帧率）
ffmpeg -r 30 -i input.mp4 output.mp4
```

**用途**：修复帧率错误的视频

---

### `-rtsp_transport`（RTSP 传输方式）

```bash
# TCP 传输（穿透 NAT，稳定）
ffmpeg -rtsp_transport tcp -i rtsp://cam/stream output.mp4

# UDP 传输（低延迟，可能丢包）
ffmpeg -rtsp_transport udp -i rtsp://cam/stream output.mp4
```

## 输出选项

### `-c` / `-codec`（编码器选择）

```bash
# 视频用 H.264，音频用 AAC
ffmpeg -i input.mp4 -c:v libx264 -c:a aac output.mp4

# 流复制（不重编码）
ffmpeg -i input.mp4 -c copy output.mp4

# 只重编码视频，音频流复制
ffmpeg -i input.mp4 -c:v libx264 -c:a copy output.mp4
```

**缩写对比**：
- `-c:v` = `-vcodec` = `-codec:v`（视频编码器）
- `-c:a` = `-acodec` = `-codec:a`（音频编码器）
- `-c:s` = `-scodec` = `-codec:s`（字幕编码器）

---

### `-b:v` / `-b:a`（码率）

```bash
# 视频 5Mbps，音频 128kbps
ffmpeg -i input.mp4 -b:v 5M -b:a 128k output.mp4
```

---

### `-crf`（恒定质量模式）

```bash
# H.264 CRF 23（默认质量）
ffmpeg -i input.mp4 -c:v libx264 -crf 23 output.mp4

# H.265 CRF 28（等效质量）
ffmpeg -i input.mp4 -c:v libx265 -crf 28 output.mp4
```

**注意**：`-crf` 和 `-b:v` 不要同时使用（质量模式 vs 码率模式）

---

### `-preset`（编码速度）

```bash
# 快速编码（体积大）
ffmpeg -i input.mp4 -c:v libx264 -preset ultrafast output.mp4

# 慢速编码（体积小，质量好）
ffmpeg -i input.mp4 -c:v libx264 -preset slow output.mp4
```

**可选值**：ultrafast, superfast, veryfast, faster, fast, medium, slow, slower, veryslow

---

### `-s`（输出分辨率）

```bash
# 缩放到 1280x720
ffmpeg -i input.mp4 -s 1280x720 output.mp4

# 等价于（推荐用滤镜，更灵活）
ffmpeg -i input.mp4 -vf scale=1280:720 output.mp4
```

---

### `-r`（输出帧率）

```bash
# 输出 30fps
ffmpeg -i input.mp4 -r 30 output.mp4
```

---

### `-an` / `-vn` / `-sn`（禁用流）

```bash
# 只保留视频，去掉音频
ffmpeg -i input.mp4 -an output.mp4

# 只保留音频，去掉视频
ffmpeg -i input.mp4 -vn output.aac

# 去掉字幕
ffmpeg -i input.mkv -sn output.mkv
```

## 流选择详解（-map）

### 为什么需要 -map？

**默认行为（不加 -map）**：
- FFmpeg 自动选择"最佳"视频流、音频流、字幕流
- 问题：多音轨视频会丢失其他音轨

**用 -map 手动控制**：
- 精确指定要保留哪些流
- 实现多音轨、多字幕的完整保留

---

### -map 语法

```
-map [输入编号]:[流类型]:[流编号]
```

**示例**：
- `-map 0:v:0`：第 0 个输入的第 0 条视频流
- `-map 0:a:1`：第 0 个输入的第 1 条音频流
- `-map 1:a:0`：第 1 个输入的第 0 条音频流

---

### 实例 1：保留所有流

```bash
# 默认行为（只保留"最佳"流）
ffmpeg -i input.mkv -c copy output.mkv

# 保留所有视频流、音频流、字幕流
ffmpeg -i input.mkv -map 0 -c copy output.mkv
```

---

### 实例 2：提取特定音轨

```bash
# 只保留第二音轨（索引从 0 开始）
ffmpeg -i input.mkv -map 0:v:0 -map 0:a:1 -c copy output.mkv
```

---

### 实例 3：排除某些流

```bash
# 排除所有字幕流
ffmpeg -i input.mkv -map 0 -map -0:s -c copy output.mkv

# 排除第二音轨
ffmpeg -i input.mkv -map 0 -map -0:a:1 -c copy output.mkv
```

**规则**：`-map -0:x` 表示排除

---

### 实例 4：合并不同文件的流

```bash
# 视频来自 video.mp4，音频来自 audio.aac
ffmpeg -i video.mp4 -i audio.aac \
  -map 0:v:0 -map 1:a:0 \
  -c copy output.mp4
```

---

### 实例 5：多输入合并多音轨

```bash
# 合并中文、英文音轨
ffmpeg -i video.mp4 -i audio_cn.aac -i audio_en.aac \
  -map 0:v -map 1:a -map 2:a \
  -c:v copy -c:a copy \
  -metadata:s:a:0 language=zho -metadata:s:a:0 title="中文" \
  -metadata:s:a:1 language=eng -metadata:s:a:1 title="English" \
  output.mkv
```

---

### 实例 6：按语言选择流

```bash
# 只保留英文音轨
ffmpeg -i input.mkv -map 0:v -map 0:a:m:language:eng -c copy output.mkv
```

**`:m:language:eng` 表示匹配语言为 eng 的流**

### 实践 3：解析进度输出（Go 版本）

```go
package main

import (
	"bufio"
	"fmt"
	"os/exec"
	"regexp"
	"strconv"
	"strings"
)

func main() {
	cmd := exec.Command("ffmpeg",
		"-progress", "pipe:1",
		"-i", "test.mp4",
		"-c:v", "libx264", "-crf", "23",
		"-c:a", "aac",
		"output.mp4",
	)

	// 捕获标准输出
	stdout, _ := cmd.StdoutPipe()
	cmd.Start()

	// 获取总时长（实际项目中应该先用 ffprobe 获取）
	totalDuration := 90.0 // 秒

	scanner := bufio.NewScanner(stdout)
	timeRe := regexp.MustCompile(`out_time=(\d+):(\d+):(\d+\.\d+)`)

	for scanner.Scan() {
		line := scanner.Text()

		// 解析时间
		if matches := timeRe.FindStringSubmatch(line); matches != nil {
			hours, _ := strconv.ParseFloat(matches[1], 64)
			minutes, _ := strconv.ParseFloat(matches[2], 64)
			seconds, _ := strconv.ParseFloat(matches[3], 64)

			currentTime := hours*3600 + minutes*60 + seconds
			percentage := (currentTime / totalDuration) * 100

			fmt.Printf("\r进度: %.2f%% (%.2f/%.2f 秒)", percentage, currentTime, totalDuration)
		}
	}

	cmd.Wait()
	fmt.Println("\n转码完成")
}
```

## 本篇小结

1. **命令结构**：`ffmpeg [全局] [输入选项] -i 输入 [输出选项] 输出`

2. **核心规则**：
   - `-i` 前的参数作用于输入
   - `-i` 后的参数作用于输出
   - 参数顺序决定作用对象

3. **全局选项**：
   - `-y`/`-n`：覆盖控制
   - `-v`/`-loglevel`：日志级别
   - `-threads`：线程数（`0` = 自动）
   - `-progress`：进度输出（脚本解析用）

4. **输入选项**：
   - `-ss`：输入 seek（快速，不精确）
   - `-t`/`-to`：时长控制
   - `-f`：强制格式
   - `-rtsp_transport`：RTSP 传输方式

5. **输出选项**：
   - `-c:v`/`-c:a`：编码器选择
   - `-c copy`：流复制（不重编码）
   - `-crf`：质量模式
   - `-b:v`/`-b:a`：码率模式
   - `-preset`：编码速度

6. **流选择（-map）**：
   - 不加 `-map`：自动选择"最佳"流
   - `-map 0`：保留所有流
   - `-map 0:v:0 -map 0:a:1`：精确选择
   - `-map -0:s`：排除字幕流

7. **多输入与多输出**：
   - 多输入：合并不同文件的流
   - 多输出：一次解码，生成多个文件（节省时间）

8. **生产环境建议**：
   - 明确指定 `-y` 或 `-n`
   - 使用 `-v warning` 减少日志
   - 使用 `-hide_banner` 隐藏版权信息
   - 使用 `-progress` 解析进度
