## 1｜从"报时 + 算术"到"管理助手"：先造一个目标

第 7 篇的 agent 只会报时和算术（那两个通用演示工具留在 `agent/` 里继续用）。现在切主场景
——**写作规范锁定：第 8 篇起不再换**——**后台管理助手**：用户一句话"帮我看下张三现在是
什么角色，再给他加上运营"，agent 要自己完成：登录 → 查用户（名字→ID）→ 查角色 → 分配
角色 → 答复。

架构原则一句话：**agent 只通过 HTTP 看后端**——后端用什么语言、什么框架，agent 不关心、
也不碰。这就是"成熟方案三条路线"里路线①（SDK 直连现行 REST）的形态；本系列的学习路径
是先在一条临时 Python 服务上把 agent 侧验证透，真实 Go 后台的落地放 P5·15 / P7。

```text
项目根/
├── agent/            ← 第 7 篇建的 agent（本篇往里加后台工具）
└── target_service/   ← 本篇新建：模拟"现有后台"的临时目标服务

┌──────────────┐   HTTP（就是普通 REST 调用）  ┌──────────────────────┐
│ agent/        │ ───────────────────────────▶ │ target_service/       │
│ 直连版 agent  │ ◀─────────────────────────── │ FastAPI 模拟"现有后台" │
└──────────────┘                              └──────────────────────┘
     AI 侧（我们写的）                            "现有系统"侧（临时的替身）
```

**为什么用临时服务，而不是直接接你的 Go 后台？** 三个理由：

1. **学 agent 不该被后端环境卡住**——5 个接口百来行内存实现就能造出来，先把 agent 侧
   （工具设计、闭环）验证透；"真实后台要不要为 agent 改造"是后面 P5/P7 的话题；
2. **可复现**——每个人本地跑的是同一个目标服务，教程的"预期输出"才有意义；
3. **边界感**——这个服务故意"只有接口、没有业务"，它是一面镜子，照出 agent 侧的工具
   有没有设计对。

## 2｜最小目标服务：约 110 行 FastAPI 模拟后台

5 个端点，正好对应闭环的每一步：

| 端点 | 作用 | 闭环中哪一步 |
|---|---|---|
| `POST /api/v1/login` | 登录发 JWT（JSON Web Token，有效期 1 小时）| 第 1 步：拿 token |
| `GET /api/v1/users?keyword=` | 按用户名/姓名查用户（分页）| 人名 → user_id |
| `GET /api/v1/roles` | 角色目录 | 角色名 → role_id |
| `GET /api/v1/users/{user_id}/roles` | 查某用户已有角色 | 汇报"现在是什么角色" |
| `POST /api/v1/users/{user_id}/roles` | 分配角色（幂等 idempotent）| 写操作 |

**为什么比"四个接口"多了一个 `GET /roles`**：M2 闭环要求"给他加上运营"能执行——模型
只知道"运营"这个名字，写操作要的是 `role_id`（"2002"）；**能把名字翻译成 ID 的只有
后台**，所以必须有角色目录接口。这预演了真实世界工具设计的第一条经验：**闭环缺数据时，
别让模型猜，给它一个查询工具**。

完整代码 `target_service/main.py`：

```python
"""target_service/main.py — 最小目标服务（模拟"现有后台"，临时验证用）。

5 个端点（对应 M2 闭环的每一步）：
  POST /api/v1/login                   登录，发 JWT
  GET  /api/v1/users?keyword=&page=    按用户名/姓名查用户（分页）
  GET  /api/v1/roles                   角色目录（把"运营"翻译成 role_id 用）
  GET  /api/v1/users/{user_id}/roles   查某用户的角色
  POST /api/v1/users/{user_id}/roles   给用户分配角色（幂等）

数据全在内存（重启归零）；JWT 用 HS256 自签。
它只是"验证 agent 用的临时目标"——成熟方案里 agent 只通过 HTTP 看后端，
后端语言与 agent 解耦；真实 Go 后台的落地在 P5·15 / P7 做。

运行：uvicorn main:app --port 8000
"""
import time
from typing import Optional

import jwt
from fastapi import FastAPI, Header, HTTPException
from pydantic import BaseModel

SECRET = "dev-secret-do-not-use-in-prod"   # 仅本地教学；真实系统绝不硬编码密钥
ADMIN = {"username": "admin", "password": "admin123"}
TOKEN_TTL = 3600                            # 秒

app = FastAPI(title="target-service")

# ---- 内存数据（教学示例，重启归零）----
USERS = {
    "1001": {"user_id": "1001", "username": "zhangsan", "display_name": "张三", "status": 1},
    "1002": {"user_id": "1002", "username": "lisi", "display_name": "李四", "status": 1},
    "1003": {"user_id": "1003", "username": "wangwu", "display_name": "王五", "status": 0},
}
ROLES = {
    "2001": {"role_id": "2001", "role_code": "admin", "role_name": "管理员"},
    "2002": {"role_id": "2002", "role_code": "ops", "role_name": "运营"},
    "2003": {"role_id": "2003", "role_code": "readonly", "role_name": "只读"},
}
USER_ROLES = {"1001": ["2001"], "1002": ["2002"], "1003": []}   # user_id -> [role_id]


class LoginBody(BaseModel):
    username: str
    password: str


class AssignRoleBody(BaseModel):
    role_id: str


def require_auth(authorization: Optional[str] = Header(default=None)) -> str:
    """校验 Bearer token，返回用户名；失败一律 401。"""
    if not authorization or not authorization.startswith("Bearer "):
        raise HTTPException(status_code=401, detail="缺少 Bearer token")
    try:
        payload = jwt.decode(authorization[7:], SECRET, algorithms=["HS256"])
    except jwt.PyJWTError:
        raise HTTPException(status_code=401, detail="token 无效或已过期")
    return payload["sub"]


@app.post("/api/v1/login")
def login(body: LoginBody):
    if body.username != ADMIN["username"] or body.password != ADMIN["password"]:
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    payload = {"sub": body.username, "exp": int(time.time()) + TOKEN_TTL}
    token = jwt.encode(payload, SECRET, algorithm="HS256")
    return {"code": 0, "data": {"token": token, "expires_in": TOKEN_TTL}}


@app.get("/api/v1/users")
def list_users(keyword: str = "", page: int = 1, page_size: int = 10,
               authorization: Optional[str] = Header(default=None)):
    require_auth(authorization)
    matched = [u for u in USERS.values()
               if not keyword or keyword in u["username"] or keyword in u["display_name"]]
    start = (page - 1) * page_size
    return {"code": 0,
            "data": {"total": len(matched), "list": matched[start:start + page_size]}}


@app.get("/api/v1/roles")
def list_roles(authorization: Optional[str] = Header(default=None)):
    require_auth(authorization)
    return {"code": 0, "data": {"list": list(ROLES.values())}}


@app.get("/api/v1/users/{user_id}/roles")
def get_user_roles(user_id: str, authorization: Optional[str] = Header(default=None)):
    require_auth(authorization)
    if user_id not in USERS:
        raise HTTPException(status_code=404, detail="用户不存在")
    return {"code": 0,
            "data": {"list": [ROLES[rid] for rid in USER_ROLES.get(user_id, [])]}}


@app.post("/api/v1/users/{user_id}/roles")
def assign_role(user_id: str, body: AssignRoleBody,
                authorization: Optional[str] = Header(default=None)):
    require_auth(authorization)
    if user_id not in USERS:
        raise HTTPException(status_code=404, detail="用户不存在")
    if body.role_id not in ROLES:
        raise HTTPException(status_code=400, detail="角色不存在")
    role_ids = USER_ROLES.setdefault(user_id, [])
    if body.role_id not in role_ids:          # 幂等：已有则不变
        role_ids.append(body.role_id)
    return {"code": 0, "data": {"user_id": user_id, "role_ids": role_ids}}
```

> 本篇的**服务端与 agent 侧工具层均已在编写环境实测**：5 端点 + 401/404/幂等共 13 条
> 用例全过（实测记录见 §4）。运行依赖版本（2026-10-16 PyPI 实测）：fastapi 0.143.2 /
> uvicorn 0.54.0 / pyjwt 2.15.1 / requests 2.34.2；接口行为以
> [FastAPI 官方文档](https://fastapi.tiangolo.com/) 与 [PyJWT 文档](https://pyjwt.readthedocs.io/) 为准。

## 3｜把 API 变成工具：一个端点 → 一个工具

映射规则先摆出来（工具设计的"翻译规则"，B1 的核心）：

| 后台端点 | agent 工具 | description 的关键句 |
|---|---|---|
| POST /login | `login(username, password)` | "调用任何其他后台工具前必须先登录" |
| GET /users | `list_users(keyword)` | "把用户名字转换成 user_id" |
| GET /roles | `list_roles()` | "把角色名转换成 role_id" |
| GET /users/{id}/roles | `get_user_roles(user_id)` | "必须先登录" |
| POST /users/{id}/roles | `assign_role(user_id, role_id)` | "写操作；幂等；必须先登录" |

**三个设计要点**，都在下面的 tools.py 增量里：

1. **登录当工具，不写死在代码里**——如果登录是"代码启动时自动做"，模型就永远学不会
   "凭证错了换一次再试"；登录也是 agent 的"行动"之一，失败信息可以喂回（第 7 篇的兜底
   机制直接复用）。
2. **token 在进程内存持有，不进对话历史**——`_token = None` 模块级变量，登录成功后写它；
   `login` 工具对模型只回"登录成功"，**模型从头到尾看不到 token 原文**——这是"敏感信息
   不进模型上下文"的第一课（P3·10 会正名）。
3. **业务工具自动注入 `Authorization`**——统一走 `_auth_headers()` 一处，5 个工具都不需要
   模型提供 token；模型只需要知道"先登录"这条规则，而不是"Bearer 怎么拼"。

### tools.py 增量（追加到第 7 篇的文件末尾）

先把文件顶部 import 区补两行（第 7 篇的 tools.py 还没有它们）：

```python
import json          # 回给模型的工具结果统一 json.dumps（第 7 篇只有 main.py 用了 json）
```

然后追加：

```python
# ============ 后台管理工具（第 8 篇新增）============
API_BASE = "http://127.0.0.1:8000/api/v1"
_TIMEOUT = 10            # 秒；网络调用永远设超时
_token = None            # 登录 token 存进程内存，不进对话历史（模型看不到它）


def login(username, password):
    """后台登录；成功后 token 存入本进程内存。"""
    global _token
    resp = requests.post(f"{API_BASE}/login",
                         json={"username": username, "password": password},
                         timeout=_TIMEOUT)
    if resp.status_code != 200:
        return f"登录失败：HTTP {resp.status_code} {resp.text}"
    _token = resp.json()["data"]["token"]
    return "登录成功，token 已在本进程内存持有（有效期 1 小时）。"


def _auth_headers():
    return {"Authorization": f"Bearer {_token}"}


def list_users(keyword=""):
    """按用户名或姓名查用户（返回 user_id 等）——把名字翻译成 ID 的第一步。"""
    resp = requests.get(f"{API_BASE}/users", params={"keyword": keyword},
                        headers=_auth_headers(), timeout=_TIMEOUT)
    if resp.status_code != 200:
        return f"查询失败：HTTP {resp.status_code} {resp.text}"
    return json.dumps(resp.json()["data"], ensure_ascii=False)


def list_roles():
    """查后台全部角色目录（role_id / role_code / role_name）。"""
    resp = requests.get(f"{API_BASE}/roles",
                        headers=_auth_headers(), timeout=_TIMEOUT)
    if resp.status_code != 200:
        return f"查询失败：HTTP {resp.status_code} {resp.text}"
    return json.dumps(resp.json()["data"], ensure_ascii=False)


def get_user_roles(user_id):
    """查指定用户当前拥有的角色。"""
    resp = requests.get(f"{API_BASE}/users/{user_id}/roles",
                        headers=_auth_headers(), timeout=_TIMEOUT)
    if resp.status_code != 200:
        return f"查询失败：HTTP {resp.status_code} {resp.text}"
    return json.dumps(resp.json()["data"], ensure_ascii=False)


def assign_role(user_id, role_id):
    """给用户分配一个角色（幂等：已有则不变）。"""
    resp = requests.post(f"{API_BASE}/users/{user_id}/roles",
                         json={"role_id": role_id},
                         headers=_auth_headers(), timeout=_TIMEOUT)
    if resp.status_code != 200:
        return f"分配失败：HTTP {resp.status_code} {resp.text}"
    return "分配成功：" + json.dumps(resp.json()["data"], ensure_ascii=False)


# ---- 注册进第 7 篇的注册表与工具清单：agent 循环一行都不用改 ----
registry.update({
    "login": login,
    "list_users": list_users,
    "list_roles": list_roles,
    "get_user_roles": get_user_roles,
    "assign_role": assign_role,
})

TOOLS_SCHEMA += [
    {"type": "function", "function": {
        "name": "login",
        "description": "登录后台管理系统。调用任何其他后台工具前必须先登录。",
        "parameters": {"type": "object",
                       "properties": {"username": {"type": "string", "description": "用户名"},
                                      "password": {"type": "string", "description": "密码"}},
                       "required": ["username", "password"]}}},
    {"type": "function", "function": {
        "name": "list_users",
        "description": "按用户名或姓名查询后台用户，返回 user_id 等信息。用户提到人名时先用本工具把名字转换成 user_id。必须先登录。",
        "parameters": {"type": "object",
                       "properties": {"keyword": {"type": "string",
                                                  "description": "用户名或姓名，可为空字符串"}},
                       "required": []}}},
    {"type": "function", "function": {
        "name": "list_roles",
        "description": "查询后台全部角色目录（role_id/role_code/role_name）。用户提到角色名时先用本工具把角色名转换成 role_id。必须先登录。",
        "parameters": {"type": "object", "properties": {}, "required": []}}},
    {"type": "function", "function": {
        "name": "get_user_roles",
        "description": "查询指定用户当前拥有的角色列表。必须先登录。",
        "parameters": {"type": "object",
                       "properties": {"user_id": {"type": "string",
                                                  "description": "用户 ID，如 1001"}},
                       "required": ["user_id"]}}},
    {"type": "function", "function": {
        "name": "assign_role",
        "description": "给指定用户分配一个角色（写操作，幂等：已有该角色则不变更）。必须先登录；role_id 需先经 list_roles 查得。",
        "parameters": {"type": "object",
                       "properties": {"user_id": {"type": "string", "description": "用户 ID"},
                                      "role_id": {"type": "string", "description": "角色 ID，如 2002"}},
                       "required": ["user_id", "role_id"]}}},
]
```

## 4｜里程碑 M2：一句话闭环

**目标**：终端里一句话，agent 自己完成 登录 → 查用户 → 查角色 → 分配角色 → 答复。

前置：第 2 节的服务在终端 1 跑着；`tools.py` / `main.py` / `.env` 已按第 3 节更新；
agent 侧装依赖：`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple requests`。

**先做零 token 的工具层冒烟**（预算友好：不烧 LLM 调用，先把工具函数直接验一遍）。
新建 `agent/tools_smoke.py`：


## 本篇结论

1. **路线①落地**：agent 只通过 HTTP 看后端（语言/框架解耦）；临时 FastAPI 目标服务让
   闭环可复现（5 端点约 110 行，服务端 + 工具层 13 条用例本环境已实测）。
2. **工具设计三模式**：登录当工具（失败可喂回）；token 在**进程内存**（不进模型上下文）；
   业务工具统一自动注入 `Authorization`，描述写清"必须先登录"。
3. **M2 达成**：一句话闭环 login → list_users → get_user_roles → list_roles → assign_role
   → 答复；401/404/幂等三种边界都已被"喂回模型"兜住。
