## 1｜"想"与"不想"：同一模型的两态

"推理模型"曾经是另一个模型名（`deepseek-reasoner`）；2026 年的形态是**同一模型的
一个模式**：`deepseek-flash` 在回答前可以先生成一段**思维链（chain of thought）**
推演，再给最终答案——默认开启，深度可调。

| | thinking 关（非思考模式） | thinking 开（思考模式） |
|---|---|---|
| 答题方式 | 看到问题**直接顺着生成** | 回答前先内部**长思维链**推演一遍 |
| 时延 | 快 | 慢（思考要花时间） |
| 成本 | 便宜 | 更贵（思维链按输出 token 计费） |
| 擅长 | 日常对话、单步工具调用、信息提取、改写 | 多步逻辑、数学、规划、"要自查的"复杂任务 |
| 短板 | 复杂任务容易"想快了答错了"（跳步/幻觉） | 简单任务杀鸡用牛刀、更慢更贵，偶尔过度复杂化 |

**"想很久"对应什么**：思考模式是在"真正回答"之前，先产出大量中间推理（响应里的
`reasoning_content` 字段）——相当于把第 2 篇 goal-based 的"规划"也放进模型内部做预演。
对需要严格步骤的任务（数学、多跳逻辑、条件多的规划），这一步很值；对"给我摘句重点"
这种任务，就是纯浪费。

**怎么判该开多深**（决策表；开关与档位的写法见第 2 节）：

| 任务信号 | 建议 | 理由 |
|---|---|---|
| 聊天、闲聊、摘要、信息提取、一步工具能完成 | **关**（`thinking: disabled`） | 快、便宜，"想"是纯浪费 |
| 目标明确的多步任务、常规闭环 | **默认**（开，`high`） | 少点掉进"想当然" |
| 工具调用链条长、第 n 步的结果会改变第 n+1 步怎么做 | 开，`high` 起步 | 重规划更稳 |
| 复杂诊断 / 跨表排查类（量产级） | 考虑 `deepseek-v4-pro` | 模型更强，第 20 篇路由表 |

> 档位说明：`reasoning_effort` 取 `low / high / max`（thinking 默认开启、默认 `high`；
> 请求值到实际档位还有一层官方映射表，细节以官方 Thinking Mode 页为准）。
>
> 进阶形态（第 20 篇才讲）：**模型路由**——按任务复杂度自动分发到不同档位/模型。
> 本篇只讲"同一任务该开多深"，路由是做出来之后的自动分发。

## 2｜DeepSeek 接入主线（OpenAI 兼容）

本系列默认供应商是 DeepSeek，原因就一句话：**OpenAI 兼容**——同一套 `openai` SDK，
只要改 `base_url` 和模型名就能换任意兼容供应商（通义、智谱、本地 Ollama 都是）。

第 1 篇已把 `.env` 配好，接法：

```python
import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    api_key=os.environ["DEEPSEEK_API_KEY"],
    base_url="https://api.deepseek.com",   # DeepSeek 官方 OpenAI 兼容端点
)

# 默认：thinking 开启（默认档 high）——多步任务用它
resp = client.chat.completions.create(
    model="deepseek-flash",
    messages=[{"role": "user", "content": "6 月 30 日是星期几？逐步推导。"}],
    reasoning_effort="high",
    extra_body={"thinking": {"type": "enabled"}},
)

# 简单任务：关掉 thinking——快且省
resp = client.chat.completions.create(
    model="deepseek-flash",
    messages=[{"role": "user", "content": "把这句话改成更礼貌的说法：今天不行。"}],
    extra_body={"thinking": {"type": "disabled"}},
)
```

> 顺带一句：DeepSeek 还提供 **Anthropic 格式端点**（`base_url` 换
> `https://api.deepseek.com/anthropic`）——同一把 key，`anthropic` SDK 也能直连
> DeepSeek（第 6 篇细讲；以官方 docs 为准）。

**三个工程要点**（第 1 条是 2025 年老教程最容易过时的点，务必看）：

1. **带工具的思维链回传规则**：响应里的 `reasoning_content`（思维链）与 `content`
   （正式回答）同级返回。规则分两态——
   - **请求不带 `tools`**：思维链不需要回传（传了也会被忽略、不拼进上下文）；
   - **请求带 `tools`（我们的 agent 就是！）**：**所有历史轮次的 `reasoning_content`
     必须完整回传**、会被拼进上下文；**不回传正确会直接 400 报错**。
   官方推荐一行搞定：`messages.append(response.choices[0].message)`——整个 message
   对象（含 `content` / `reasoning_content` / `tool_calls`）原样入库，回传天然正确。
   第 7 篇的 loop 正是这么写的（`messages.append(msg)`）。
2. **思考模式下采样参数受限**：`temperature`、`presence_penalty`、`frequency_penalty`
   在思考模式**不生效**（设置了不报错、但无效）；`top_p` 仅在思考模式有效，且有效
   范围 0.95–1.0（低于 0.95 按 0.95 处理），非思考模式固定 1.0。**别照搬"调温"
   老习惯**——先确认模式，再决定这些参数有没有意义（细节以官方 Thinking Mode 页为准）。
3. **思维链计入输出 token**：同样的任务，开 thinking 往往慢几秒、贵几倍（思维链
   按输出 token 计费）。所以简单任务关掉它，只有"需要多想一下"的任务才开。

> 心态提醒：**思考模式不是"更聪明"，是把速度换成思考量**。用对它才划算，
> 用错了就是又慢又贵。这正是本篇动手实验要你亲自量一遍的账。

## 3｜提示策略：让模型先规划、再动手、后反思（为 P4 埋伏笔）

不动开关也能显著改善工具调用质量——在 system prompt 里**显式要求模型展示规划与反思**。
两条最基础、最通用的写法：

```text
【规划前置】
在调用任何工具之前，先用一段文字简述你的执行计划：
步骤顺序是什么、每一步打算用哪个工具、可能出现什么情况要改计划。

【反思收尾】
任务完成后，回顾你的执行过程：
结果是否满足用户的真实意图？有没有绕路/多余操作？如有需要修正，说明理由。
```

为什么这有用（条条都能对应第 2 篇的坐标系）：

- **规划前置** = 逼模型先"走一遍脑子里的路线图"再动手 → 减少瞎调工具、工具顺序颠倒；
  对齐的正是 goal-based（第 2 篇）和 agent loop 里"第 ② 步决策"（第 3 篇）。
- **反思收尾** = 让模型检查自己的产出 → 提前发现"答非所问"，相当于把 utility-based
  的"自查"写进 prompt。

代价要算清（第 12 篇会放大这个账）：

- 这两段文字会让每轮多花 **上百 token**，且模型会真的输出一段计划文本；
- 简单任务（"现在几点"）套上这套 prompt 就是纯浪费——**小任务别穿盔甲**；
- 它的本质是"**提示词级别的隐性规划**"。P4·12 会把它升级成"显式计划数据结构 + 计划校验、
  执行中重规划"——到时候你会看到，显式数据结构能接住"计划被工具结果推翻"的情况，
  光靠 prompt 文字接不住。

## 4｜国内落地选项：在线 / 本地 / 私有化

| 方案 | 形态 | 优点 | 什么时候用 |
|---|---|---|---|
| **DeepSeek**（默认主线）| 云，OpenAI 兼容 | 便宜、快、中文好、一站式 | 学习与日常主线直接用 |
| **通义 Qwen**（阿里云 Model Studio）| 云，OpenAI 兼容 | 通义千问系列，国产云原生 | 已有阿里云账号 / 团队标准时 |
| **智谱 GLM**（开放平台）| 云，OpenAI 兼容 | GLM 系列，开放平台友好 | 想对比国产多厂家时备选 |
| **Ollama**（本地）| 本机跑小模型 | 免费、离线、数据不出本地 | 隐私敏感 / 没网 / 想省 token |
| **vLLM**（私有化）| 自有服务器托管大模型 | 完全自控、可上业务 | 团队级私有化部署时才需要考虑 |
| Claude（有条件选做）| 云 | 模型能力强 | 需要网络环境额外可用时才做对比 |

关键认知：**上面所有这些都走 OpenAI 兼容接口**——换供应商 = 改 `base_url` + key + 模型名，
代码结构一字不用动（本篇动手实验里会看到切换成本有多低）。

本地（Ollama）的取舍要诚实讲：

- 优点：免费、离线、隐私好——**但代价是模型小**（本地能跑的是小参数量蒸馏版，
  质量和云端 DeepSeek 差距明显）；
- 结论：**学习主线用云端 DeepSeek，Ollama 只做"离线对比/隐私场景"备用**；别让
  "本地化"变成"省事却变笨"。

> 出处：DeepSeek 开放平台（[platform.deepseek.com](https://platform.deepseek.com/)）、
> 智谱开放平台（[open.bigmodel.cn](https://open.bigmodel.cn/)）、阿里云 Model Studio、
> [Ollama](https://www.ollama.com/)、[vLLM](https://docs.vllm.ai/)——均见本套教程
> 参考资料汇总。具体模型名 / tag / 价格以各自官方 docs 为准，本篇不写死具体版本号。

## 动手实践：同一任务开 / 关 thinking 各跑一遍（Ollama / Claude 可选），记录质量 / 时延 / 成本

**目标**：亲自量一遍第 1 节的账——同一模型、同一题，**thinking 关 vs 开**（本地 Ollama
与 Claude 是可选项），看**回答质量、耗时、token 消耗**三者怎么差。选一个"不推演就容易
错"的任务（数学/逻辑题最能拉开差距）。

新建 `model_compare.py`：

```python
"""第 4 篇动手实践：同一任务对比 deepseek-flash 的 thinking 关/开，记录质量/时延/token。

<需 DEEPSEEK_API_KEY；本环境未实测，接口与参数以官方 docs 为准>
预算友好：先跑 1 个任务，确认差异后再扩任务集。
"""
import os
import time

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    api_key=os.environ["DEEPSEEK_API_KEY"],
    base_url="https://api.deepseek.com",
)

# 选一个"不推演就容易错"的题：日历推理需要逐步算
TASKS = ["6 月有 30 天。6 月 1 日是星期一，那么 6 月 30 日是星期几？请逐步推导。"]

# 同一模型的两态：(名称, 调用附加参数)
CONFIGS = [
    ("thinking-关", {"extra_body": {"thinking": {"type": "disabled"}}}),
    ("thinking-开(high)", {"reasoning_effort": "high",
                           "extra_body": {"thinking": {"type": "enabled"}}}),
]

# 可选：本地 Ollama（需预先安装并用 `ollama pull` 拉一个 DeepSeek 蒸馏模型）
# client 换成：
#   client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
# CONFIGS 里换成对应本地模型名（tag 以 Ollama 模型库为准）

# 可选：Claude（有条件选做）：用 anthropic 官方 SDK；也可直接试 DeepSeek 的
# Anthropic 兼容端点（base_url = https://api.deepseek.com/anthropic），模型名以官方为准

for task in TASKS:
    for name, extra in CONFIGS:
        print(f"\n===== {name} | 任务：{task[:18]}… =====")
        t0 = time.time()
        resp = client.chat.completions.create(
            model="deepseek-flash",
            messages=[
                {"role": "system", "content": "涉及计算或逻辑时请先简述思路再给结论。"},
                {"role": "user", "content": task},
            ],
            **extra,
        )
        elapsed = time.time() - t0
        msg = resp.choices[0].message
        usage = resp.usage
        cot = getattr(msg, "reasoning_content", None)
        print(f"回答：{msg.content}")
        # 思维链：开 thinking 时才有；展示随意，但我们的 agent（带 tools）必须回传（第 2 节规则 1）
        print(f"思维链：{'有（%d 字）' % len(cot) if cot else '无'}")
        print(f"耗时：{elapsed:.1f} 秒")
        print(f"token：输入 {usage.prompt_tokens} / 输出 {usage.completion_tokens} / 总 {usage.total_tokens}")
```

运行：

```bash
source .venv/bin/activate
python model_compare.py
```

预期输出（节奏如此，具体回答与数值以当次运行与官方 docs 为准）：

```text
===== thinking-关 | 任务：6 月有 30 天。6 月 1 日是星期一…
回答：6 月 30 日是星期二。（跳过大半推导直接给结论，这类题偶尔会算错）
思维链：无
耗时：0.6 秒
token：输入 128 / 输出 45 / 总 173

===== thinking-开(high) | 任务：6 月 1 日是星期一…
回答：6 月 30 日是星期二。推导：……（结论更稳）
思维链：有（约 300 字）
耗时：3.2 秒
token：输入 128 / 输出 345 / 总 473
```

**看完输出的三问自检**：

1. **质量**：开 thinking 是不是给了步骤、答得更稳？（如果关着也答对了，换更绕的题
   再试——对比实验的目的就是找到"在什么任务上它值得多花时间"。）
2. **时延**：开着是不是明显更慢？慢的这么多，换来的稳定性值不值？
3. **成本**：输出 token 差多少倍？把 `usage.total_tokens` 乘单价（价格以 DeepSeek
   定价页为准，此处不写死），一声算清"想很久"的账。

**换供应商实验（10 秒做完）**：把 `base_url` 换成通义/智谱的兼容端点、`model` 换成
对应模型名，跑同一题——**代码结构一行没变**。这就是"OpenAI 兼容"送给你的那份切换自由，
也是第 5 篇选型地图要用的手感。

## 本篇结论

1. **"想"是开关不是模型**：`deepseek-flash` 默认开 thinking、`reasoning_effort` 三档
   （low/high/max）；多步/需要自查的任务才划算，闲聊摘要关掉它。
2. **三件工程事**：① 带 `tools` 时历史 `reasoning_content` 必须完整回传（否则 400；
   官方一行 `messages.append(message)` 解决）；② 思考模式下 `temperature` 等采样参数
   不生效、`top_p` 受限；③ 思维链按输出 token 计费。
3. **提示策略**：system prompt 里的"规划前置 + 反思收尾"是零成本提质的起点，但它是
   prompt 级隐性规划——显式计划数据结构要等 P4·12。
4. **国内落地**：全系列走 OpenAI 兼容，换供应商只改 base_url+key+模型名；云端 DeepSeek
   为主，Ollama 做离线备用，vLLM 留给业务私有化。
