## 1｜经典智能体分类：一台"感知 → 决策 → 行动"机器的五档进化

人工智能经典教材《Artificial Intelligence: A Modern Approach》（Russell & Norvig，
清华大学出版社中译本《人工智能：一种现代的方法》）的开篇，就用一张图把"智能体"拆成
三个动作：

```
智能体（agent）
    感知（percept）────────────────▶  决策（decision）────────────────▶  行动（action）
        ▲                                                                    │
        └──────────────────────────────── 环境产生的反馈 ◀────────────────────┘
```

任何 agent 都在这条线上转：**从环境拿到感知 → 内部决策下一步 → 对环境行动 → 再感知**。
五档分类的区别，只在于"决策"这一个环节里放了多少东西。逐档看（每档给一句话 + 日常类比
+ 判定标准）：

### 第一档：simple reflex（简单反射）——只看眼前，不过脑子

- 一句话：**根据当前感知的直接映射（查表）决定动作，没有任何内部记录。**
- 类比：绿灯行、红灯停——红绿灯切换之间，你没有"我刚才看到了什么"的记忆，只有"现在
  是红是绿"这一个输入。
- 判定标准：你**掐掉它上一步的任何痕迹**（上一步感知、上一步动作、历史），它对当前输入
  的反应**完全不变**。

### 第二档：model-based reflex（基于模型）——心里有张世界地图

- 一句话：内部维护**对世界状态的估计（model）**，每次感知都更新它，动作基于**当前感知 +
  内部状态**；状态对它看不全的世界做补全。
- 类比：你戴着耳机走在路上，前面堵了看不见，但你知道"我 3 分钟前听到喇叭声"——你用一个
  内部"模型"补上了当下的盲区。
- 判定标准：**改一下它过去的经历，它现在会对同一个输入做出不同的动作**——过去的痕迹
  进入了现在的决策。

### 第三档：goal-based（目标导向）——知道要去哪，会想路

- 一句话：除世界模型外，再加一个**目标**；它不再只做"看见什么回什么"，而是搜索一条
  **动作序列**把现状推到目标状态（规划）。
- 类比：你要去机场，不是"见到什么做什么"，而是先想"出门 → 打车 → 上高速"整条路线，
  再一步步走，路上发现封路会换路。
- 判定标准：它在动作之前，会有一个**"为达成某个目标而计划"的显式产物**（路线、步骤、
  方案），而不是条件反射。

### 第四档：utility-based（效用）——多个目标打架时算账

- 一句话：多个目标/选项并存时，给每个候选方案算一个**效用值**，选最大化效用的那个——
  不只是"能不能到目标"，而是"哪个更划算、更安全、更省"。
- 类比：同样能到机场，骑车最便宜但可能下雨、打的快但贵——你按"时间 × 钱 × 状态"
  打分，选总分最高的。没有单一日标能回答这件事，只有效用函数能。
- 判定标准：它面对**互斥选项**会权衡取舍（代价/风险/收益），而不是无脑追求唯一目标。

### 第五档：learning（学习）——从经验里改进自己

- 一句话：agent 里多一个**学习部件**，它能根据"行动的反馈是否达成预期"去调整自己
  未来的决策（参数、规则、策略），越用越好。
- 类比：你第一次开这家餐厅的导航多绕了路，下次出门它记住了这条路——你"学"到了经验，
  不用重头再死记一遍。
- 判定标准：**同样一个问题，多次经历之后它的表现变好了**——存在一个把反馈转化为改进的环节。

五档不是并列的五个物种，而是**叠加**的：simple reflex 是最小底座，model-based 加内部状态，
goal-based 加目标与规划，utility-based 加效用权衡，learning 再加自我改进。用一张从下往上的
叠加表记最牢固：

| 档位 | 在决策里加的东西 | 关键字 |
|---|---|---|
| 1 simple reflex | （无） | 当前感知 → 查表 |
| 2 model-based | 内部状态（世界模型） | 补全盲区、记住过去 |
| 3 goal-based | 目标 + 规划 | 拆步骤、找路线 |
| 4 utility-based | 效用函数 | 权衡、取舍、打分 |
| 5 learning | 学习机制 | 反馈 → 改进 |

> 出处：Russell & Norvig《Artificial Intelligence: A Modern Approach》「Agent」章节（智能体
> 分类的权威出处）；分类表述以该教材为准。

## 2｜映射：经典分类 → 2026 年 LLM agent 的哪个构件

这五档是为"任何智能体"写的，不限于神经网络。把今天的 LLM agent 放进去，一档一档对上：

| 经典分类 | 对应 2026 LLM agent 的构件 | 实感例子 |
|---|---|---|
| **simple reflex** | **无记忆的单个 tool call**：模型只对"当前完整输入"做一次反应，不维护任何跨轮状态 | 第 1 篇的"台阶二"：一次 `tool_calls` 声明，用完即弃 |
| **model-based** | **有状态/有记忆的循环（agent loop）**：对话历史 + 工具结果被当作"内部状态"不断喂回去，环境不再看全也靠着状态补 | 第 1 篇时序图里的 loop——模型"记得"自己刚才调过 `get_weather`，才能说"北京 5℃" |
| **goal-based** | **把目标拆计划的 agent（显式 planning）**：模型不是"见一步走一步"，而是先产出一份计划再执行 | P4·12 的 Plan-and-Execute；第 1 篇的"台阶三"再进一步——多步目标任务 |
| **utility-based** | **多目标权衡 / 守卫 / 评测打分**：预算上限、危险操作拒绝、`verifier` 独立检查、eval 打分，都是"算账" | P7·18 评测的 LLM judge；P7·19 写操作确认；P4·12 的 verifier |
| **learning** | **eval 闭环与自改进**：把失败样本吸进测试集 → 改 prompt / 选模型 → 回归验证表现变好 | P7·18"自主学习边界"；第 1 篇自测法"里程碑=考题" |

一个关键的"实感"：**主流 LLM agent 是混合体，不是单一档位**。

- 只发一次请求的"单轮工具调用"≈ simple reflex（最基本，但不是 agent）；
- 我们的 agent loop 一跑起来 ≈ **model-based**（上下文就是它的内部状态）＋ 一部分
  **goal-based**（目标写在 system prompt 里，模型在推理下一步）；
- 加了显式规划 ≈ **goal-based** 升满；
- 加了预算/守卫/verifier ≈ **utility-based** 的零件；
- 上了 eval 回归 ≈ **learning** 的雏形。

所以第 1 篇那张"三台阶表"可以用这五档重新读一遍：**台阶二是 reflex，台阶三的循环是
model-based，会拆计划的循环是 goal-based**——这套旧理论不是考古，是用了几十年的"
智能体要有哪些部件"清单，今天一条都没过时。

用判据自检是不是"真变成高一档"：如果"砍掉历史上下文，模型就不一样了"，你已经踩进
model-based 的地界；如果"没有显式计划产物，就会选错路线"，你在 goal-based 的地界缺了
规划零件（这正是 P4·12 要补的）。

## 3｜PMTA 四要素坐标系（全系列的地图坐标）

PPT 里讲架构、描述别人 agent、复盘自己 demo，都需要一句"它有什么、缺什么"。本系列统一用
**PMTA 四个要素**当坐标系——学术来源是 CoALA（Cognitive Architectures for Language Agents，
arXiv 2309.02427）为代表的语言 agent 架构框架，本质是把第一、二节讲的东西固定成一张
"零件清单"：

| PMTA 要素 | 一句话定义 | 对应经典分类的 | 本系列在哪篇深讲 |
|---|---|---|---|
| **Planning 规划** | 决定"怎么从现状到目标"的动作序列与重规划 | goal-based | P4·12（显式规划/反思/verifier）；P6·17（planner-executor 模式） |
| **Memory 记忆** | 让 past 影响 present 的信息仓库：in-context / session / 长期 | model-based（内部状态）、learning（经验）| P2·3（上下文管理）、P4·11（三层记忆/压缩/存储） |
| **Tool use 工具** | 让 agent 影响环境的**外部能力接口**（API/代码/文件/DB） | 行动机制的延伸 | P2·7（手写工具）、P3·8-10（直连后台）、P5·13-15（MCP）|
| **Action 行动** | 真正产生副作用的执行（工具执行、文本输出、终止） | reflex/utility 的出口 | P2·3（loop 骨架）、P5·15（MCP 执行） |

**这块词怎么用（贯穿全系列的操作法）**：描述任何一个 agent，从四个角度各问一句——

1. **Planning**：它会不会为多步目标先出计划？计划崩了会不会重规划？
2. **Memory**：它记住什么？（用完即弃 = 没记忆 / 有对话历史 = in-context / 能跨会话 =
   长期记忆？）
3. **Tool use**：它接住了哪些外部能力？工具描述写得清不清楚？
4. **Action**：它的执行有没有副作用、有没有人能拦下来（权限/确认）？

缺哪块，就往哪块补——第 1 篇"怎么自测"里让你"用 PMTA 复盘每个成品"，用的就是这张表。
后面每一篇的标题括号里的【A0/A1/…】知识地图标签，就是告诉你"这篇在喂 PMTA 的哪块"
（B1 工具系统、B2 记忆设计、B3 规划能力…，见 README 结构速览）。

> 出处：CoALA 论文（[arXiv 2309.02427](https://arxiv.org/abs/2309.02427)）提出的
> 语言 agent 认知架构——行动空间 / 记忆 / 决策程序——是 PMTA 坐标系的理论来源；
> 本系列的"Planning / Memory / Tool use / Action"四要素是对该框架的教学化提炼。

## 4｜为什么 2026 年讲 agent 还要回到这套老模型？

**这些分类回答的是"智能体要有哪些部件、按什么逻辑闭环"，而不是"要用什么技术栈"。**
技术会换代（符号逻辑 → 神经网络 → LLM），部件清单不会。三个理由：

1. **通用语言**：`simple reflex` / `goal-based` 是教科书名词，任何人（不管用 LangGraph 还是
   MCP）都听得懂。你说"我这个 agent 是 model-based + 目标写在 system prompt"，比说"我用了
   XX 框架"更能让对方在一分钟内理解架构。
2. **照出短板**：PMTA 四个问题一问，缺什么一目了然。比如第 1 篇的三台阶 agent——
   问 Planning 发现"没有规划"、问 Memory 发现"只有当前这轮上下文"，自然知道该去 P4 补。
   这是防止"能力听起来很全、实际缺零件"的最好自检。
3. **防过度设计**：经典框架只看 get 上限 stretch 是 UTILITY/LEARNING；**不代表每个 agent
   都要上到最高档**。多数内部工具型 agent 到 model-based + 轻度 goal-based 就够用；一上来
   就上 learning（微调）往往是浪费（P7·18 会细说"新手别微调"）。知道"边界在哪"，才不会
   过度设计。

**局限也要诚实说**：这套理论定义的是**部件**，不回答 2026 年最要命的工程细节——上下文
窗口怎么算、token 成本怎么控、模型幻觉怎么防、MCP 怎么接。那些是本系列后文（P2-P7）的活。
理论给你地图，工程给你路。

## 动脑练习：用 PMTA 指认一个真实的 agent（Claude Code）

不写代码也不配环境——你已经跑着的 Claude Code 就是最现成的标本。**练习目标**：
把第 3 节的四个问题，真的指认到一个软件上。

**任务**：对照下面的"指认表"，在你用 Claude Code 的过程中（或回想它最近帮你做的某件事）
把每一格填上"它==有什么==、==在哪=="：

| PMTA 要素 | 去 Claude Code 里找什么 |
|---|---|
| Planning | 它会不会先读相关文件、列出计划再动手？（它有一个"计划模式"专门干这个——先征得你同意再执行） |
| Memory | 它的"上下文"是什么？会话中途 `/compact` 压缩了什么？多会话之间它从哪恢复？（checkpoint / 会话历史） |
| Tool use | Read / Edit / Write / Bash / 网页抓取——它用哪些"外部能力"接触你的系统？ |
| Action | 它编辑文件、跑命令，是真的有**副作用**的——哪些操作它会停下来问你？为什么？ |

**做完你会得出三个"原来如此"**：

1. **Claude Code 是 model-based 的**：它靠"上下文（内部状态）+ 工具结果"记住刚才改到哪了——
   删掉上下文它马上"失忆"，正是第二档的判据；
2. **它的 Action 有守卫**：危险/花钱/破坏性操作要你确认——这就是 utility-based 里"权衡"
   的工程化落地；
3. **PMTA 不是空话**：每个要素都能在真实产品里找到实体（工具 = Read/Bash，记忆 =
   上下文/checkpoint，规划 = 计划模式）。你以后描述任何 agent，就都有了这张指认表。

> Claude Code 的具体功能（计划模式、/compact、checkpoint 是否存在与形态）以官方文档为准
> [Claude Code overview](https://docs.anthropic.com/en/docs/claude-code/overview)。

## 本篇结论

1. 五档经典分类是按"决策环节里加了什么"**叠加**起来的：reflex（查表）→ model-based（内部
   状态）→ goal-based（目标+规划）→ utility-based（权衡）→ learning（自我改进）。
2. 映射到手：无记忆 tool call≈reflex、loop 上下文≈model-based、显式规划≈goal-based、
   守卫/评测≈utility-based、eval 闭环≈learning——主流 agent 是它们的混合体。
3. **PMTA 四要素（规划/记忆/工具/行动）就是全系列的地图坐标**：描述任何 agent 问四句，
   缺什么补什么。
