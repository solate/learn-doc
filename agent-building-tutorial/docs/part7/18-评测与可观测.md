## 1｜开发方法：五步环与 trace 驱动调试

### 1.1 和"写函数"的根本区别

传统开发里，"正确"由代码逻辑保证；agent 的行为是**非确定**的（模型、上下文、
工具结果都在变），"正确"只能用**用例集**逼近。所以开发范式整体平移：

| | 写函数 | 写 agent |
|---|---|---|
| 行为定义 | 代码逻辑 | 提示词 + 工具 + 循环（行为契约） |
| 正确性 | 单元测试断言 | **用例集 + 打分**（统计意义上的"对"） |
| 回归风险 | 改坏逻辑 | 改坏 **prompt / 工具描述 / 上下文组装**——diff 看不出对错 |
| 调试入口 | 断点 / 日志 | **trace**（模型想什么、调了什么、结果如何） |

### 1.2 五步环

```
① 需求 ──▶ ② 拆成"可验证子任务" ──▶ ③ 工具/prompt 最小草稿
   ▲                                      │
   │                                      ▼
⑤ 失败驱动迭代 ◀── ④ 先建 3-5 条最小用例集，跑起来看
```

每一步的"完成定义"：

- **② 拆解**：每条子任务先回答"**什么算对**"（能写成断言吗？）——写不出断言
  的需求，先别进开发队列；
- **③ 草稿**：工具 + prompt 的最小版，故意简陋——它存在的意义是被用例打脸；
- **④ 用例**：**先于迭代**存在（Anthropic 原话："start with small-scale testing
  right away with a few examples"——别等几百条用例的"完美评测"）；
- **⑤ 迭代**：一次只改一个变量（prompt / 工具描述 / 循环结构），改完**全量重跑**。

### 1.3 调试 = trace 驱动

agent 出错的现场永远有"三重黑盒"：模型想了什么、调了什么、拿回了什么。
trace 就是把三层都摊开的那份记录——第 2 篇 b-8 的 `log_step`（单行 JSON 迭代
日志）是它的幼年形态，本篇 §5.1 正式化它。

顺带把两份日志的分工钉死（第 3 篇埋的）：

| | audit.jsonl（P3·9） | trace.jsonl（本篇） |
|---|---|---|
| 读者 | 事后的人（合规 / 审计） | 开发的人（调试 / 评测 / 成本） |
| 关心 | 谁在什么时候做了什么决定 | 每一步花了多少时间 / token、调用链长什么样 |
| 保留 | 长期 | 开发期可滚动清理 |

反模式三连（都反着做就对了）：凭手感改 prompt、一次改三个变量、没有回归集
就重构。

## 2｜评测最小可行版：10-20 条黄金用例 + 自动对拍

### 2.1 用例从哪来

两个来源，都要：**真实需求样本**（用户真的会问什么——从 audit.jsonl 里捞）、
**已出过的 bug**（每修一个，就把那个输入固化成用例——**这就是"回归"的本体**：
bug 不再复发不是因为记得，是因为每次全量重跑都替你记得）。

### 2.2 用例结构与判定三档

一条黄金用例 = `输入 + 期望判定`。判定按"能多确定就多确定"分三档：

| 档 | 判定方式 | 适合 | 例（本篇 cases.json 的真实用例句） |
|---|---|---|---|
| 1 精确/包含 | 字符串包含、正则、结构校验 | 有固定要点的回答 | `"contains": ["查不到"]` |
| 2 工具断言 | **检查调没调某工具** | agent 评测特有——答对了但没调工具 = 错 | `"tools": ["get_user_roles"]` |
| 3 行为规则 | 禁止/必须行为 | 安全与边界 | `"no_tools": ["delete_user"]` |

**第 2 档是 agent 评测独有的、也最容易漏**："张三的角色是 admin"这句话可能是
查出来的，也可能是编的——只有"必须调过 `get_user_roles`"才能区分。

### 2.3 打分器分工：规则 judge vs LLM judge

| | 规则 judge | LLM judge |
|---|---|---|
| 成本/速度 | 便宜、快 | 每次评分开一次模型调用 |
| 确定性 | 100% | 有波动、有偏差 |
| 适合 | 包含/工具/结构等可枚举判定 | 开放输出的"答得好不好" |
| 用法 | **先写满**——能规则判的绝不交给 LLM | 补规则判不了的那部分 |

LLM judge 的三条纪律：**别让裁判用和选手一样的提示词**（防同款偏差）；评分
prompt 本身就是资产，要进版本；**关键用例人抽检**——Anthropic 的原话是
"scales **when done well**"，做得糙的 judge 比没有更危险（错误的安心感）。

### 2.4 报告：通过率 + 逐条 + 历史

跑完出三样：**通过率**（10 条里过几条）、**逐条结果**（哪条失败、为什么）、
**历史对比**（上次多少——通过率下降 = 回归警报）。评审的节奏也就定了：
改什么东西之前先跑一遍，改完再跑一遍，用报告说话。

## 3｜可观测：自建 JSONL trace（+ 现成方案指针）

### 3.1 trace 记什么

事件表（本篇实现的最小集，字段都是自解释的）：

| 事件 | 何时 | 关键字段 |
|---|---|---|
| `turn_start` | 收到用户输入 | user_input |
| `llm_call` | 每次模型调用后 | msgs（条数）、ms（耗时） |
| `llm_usage` | 每次模型调用后 | in_tok / out_tok / total_tok、tool_calls |
| `tool_call` | 每次工具调用前 | tool、args（截断）、ms（耗时） |
| `tool_done` | 每次工具调用后 | tool、ok、result_len |
| `subagent_*` | 17 篇的 scout 事件 | question / steps（并入同一流） |
| `turn_end` | 回合结束 | steps、total_tok、total_ms |

为什么还是 **JSONL**：追加写不重写、一行一个事实、`grep`/`jq` 直接查、**坏一行
不坏整个文件**——和第 16 篇 checkpoint 选原子写是同一个工程直觉。

### 3.2 trace 的三种复用

1. **评测的数据源**：§5 的评测就靠 trace 里的 `tool_call` 事件做"工具断言"；
2. **成本报表**：第 17 篇的 `TOKENS["n"]` 只是计数器，trace 是它带时间戳、
   带归因（哪一步、哪个 subagent）的完整版；
3. **失败诊断**：用户报"它昨天答错了"，拿 trace 回放那一次的三层现场。

### 3.3 不想自建：两个指针

| 方案 | 是什么 | 什么时候上 |
|---|---|---|
| **Langfuse**（35,903 ★） | 开源 agent 评测与可观测平台：Trace / evaluate / improve 一体，可自托管 | 团队协作、要看板、不想维护存储时 |
| **OTel GenAI SemConv** | 厂商中立的**字段标准**（spans / metrics / events；含 MCP 与各家 provider 约定） | 要跨系统/跨厂商对齐、或公司已铺 OpenTelemetry 时 |

关系想清楚：**JSONL trace 学的是"记什么"（字段设计），现成方案买的是"存哪里、
怎么看"**。先把本篇的 8 个字段玩明白，迁到 Langfuse 只是换个写入端；OTel 则是
把字段名标准化——它 2026 年还在搬家（独立仓库、活跃演进），所以本系列的立场是：
**字段设计握手自建，别等标准冻结**。<以官方 docs 为准>

## 4｜自改进边界：从失败案例到微调的五级阶梯

"让 agent 自己变好"有一串流行词（reflection、自我改进、自动 prompt 优化）。
把它们排成阶梯，**收益递减、风险递增**——每一步都问"上一级榨干了吗"：

| 级 | 动作 | 收益 | 成本/风险 |
|---|---|---|---|
| ① | 失败案例 → 测试集 | 立竿见影（回归护住） | 几乎为零——**永远先做这个** |
| ② | 改 prompt / 工具描述 | 解决大多数行为问题 | 需评测验证（§2 就是验证器） |
| ③ | 改工具/循环结构（加校验、加 subagent） | 解决"提示词救不了"的结构问题 | 改动面大，回归风险高 |
| ④ | reflection：让模型自动改写自己的 prompt | 省人工调参 | 可能过拟合评测集；**必须过评测量才准上线** |
| ⑤ | 微调（fine-tune） | 风格/格式显著固化、可蒸馏小模型省成本 | 要数据、要评测、要版本回滚——**新手别碰** |

**微调三问**（三个都"Yes"才值得考虑）：

1. 有**足够量**的同质请求数据吗（至少上千条真实样本，不是几十条）？
2. 有能**证明收益**的评测集吗（微调前 X%，微调后 Y%——没有评测就没有改进，
   只有"我们改了"）？
3. 有**版本与回滚**机制吗（微调后的模型也要能灰度、能回退）？

三个 No 的时候微调 = 花大钱引入一个难维护的行为黑盒。而①→③的收益，多半
还没榨干。

一条红线，和第 16 篇"policy enforced by code"同源：**任何自动改动（包括 ④）
必须全量过评测集才能上线**——评测集就是 agent 自改进的护栏。

## 5｜动手实践：trace + 黄金用例 + 看回归护住

### 5.1 trace.py：把 b-8 的单行日志正式化

```python
# -*- coding: utf-8 -*-
"""trace.py —— 正式版"单行 JSON"日志：一条 JSONL = 一次可计量的动作。

（第 2 篇 b-8 的 log_step 是它的幼年形态；演进关系见第 18 篇 §5.1。）
"""
import json
import time

TRACE_FILE = "trace.jsonl"
_T0 = time.time()


def trace(event, **fields):
    line = {"ts": round(time.time() - _T0, 3), "event": event}
    line.update(fields)
    with open(TRACE_FILE, "a", encoding="utf-8") as f:
        f.write(json.dumps(line, ensure_ascii=False) + "\n")


class Span(object):
    """给一次动作计时：with Span("llm_call", msgs=len(messages)): ...

    退出时自动落一条带 ms 的事件——耗时不需要手写。"""

    def __init__(self, event, **fields):
        self.event = event
        self.fields = fields
        self.t0 = time.time()

    def __enter__(self):
        return self

    def __exit__(self, *exc):
        fields = dict(self.fields)
        fields["ms"] = round((time.time() - self.t0) * 1000)
        trace(self.event, **fields)
```

接进你的 agent 只需四处（都是小改）：`chat()` 里包 `Span("llm_call")` + 落
`llm_usage`；`run_tool` 前后落 `tool_call` / `tool_done`；回合首尾落
`turn_start` / `turn_end`；scout 里沿用第 17 篇的 `subagent_*` 事件。

本机跑出的真实 trace 片段（`python3` 演示 5 个事件）：

```text
{"ts": 0.0, "event": "turn_start", "user_input": "张三的角色是什么？"}
{"ts": 0.015, "event": "llm_call", "msgs": 2, "ms": 15}
{"ts": 0.015, "event": "llm_usage", "in_tok": 86, "out_tok": 31, "total_tok": 117, "tool_calls": true}
{"ts": 0.025, "event": "tool_call", "tool": "get_user_roles", "args": "{\"user_id\": \"1001\"}", "ms": 10}
```

一眼能读出来：这一回合第 2 条消息就调了工具、耗时 10ms、总用了 117 token。

### 5.3 evals.py：runner + 规则 judge（全文）

```python
# -*- coding: utf-8 -*-
"""evals.py —— 评测最小可行版：黄金用例 + 规则 judge + 报告落盘。

本机演示：python3 run_demo.py
接真 agent：见文章 5.5（把 run_agent 换成你的 agent_loop）
"""
import json


def judge(case, answer, called_tools):
    """规则 judge：按用例声明的规则打分（快 / 便宜 / 确定性）。"""
    e = case["expect"]
    if "contains" in e:
        for s in e["contains"]:
            if s not in answer:
                return False, "回答缺少：%s" % s
    if "not_contains" in e:
        for s in e["not_contains"]:
            if s in answer:
                return False, "出现了不该有的：%s" % s
    if "tools" in e:
        for t in e["tools"]:
            if t not in called_tools:
                return False, "没调用必须的工具：%s" % t
    if "no_tools" in e:
        for t in e["no_tools"]:
            if t in called_tools:
                return False, "调用了禁止的工具：%s" % t
    return True, ""


def run_evals(run_agent, tag=""):
    cases = json.load(open("cases.json", encoding="utf-8"))
    results = []
    for c in cases:
        answer, called = run_agent(c["input"])
        ok, why = judge(c, answer, called)
        results.append({"id": c["id"], "input": c["input"], "ok": ok, "why": why})
        print("%s  #%-2d %s%s" % ("PASS" if ok else "FAIL", c["id"], c["input"][:30],
                                  "" if ok else "   ← " + why))
    n_ok = sum(1 for r in results if r["ok"])
    print("[%s] 通过率：%d/%d = %.0f%%" % (tag, n_ok, len(results), 100.0 * n_ok / len(results)))
    with open("eval_report.json", "w", encoding="utf-8") as f:
        json.dump({"tag": tag, "pass": n_ok, "total": len(results), "results": results},
                  f, ensure_ascii=False, indent=2)
    if n_ok < len(results):
        print("失败用例（回归清单）：", [r["id"] for r in results if not r["ok"]])
    print()
    return n_ok, len(results)
```

import json
from evals import run_evals
from main import agent_loop, TOKENS          # 你的 agent（第 17 篇形态）
from trace import TRACE_FILE

def tools_since(offset):
    """从 trace.jsonl 的第 offset 行往后收集 tool_call 事件（工具断言的取数处）"""
    called = []
    with open(TRACE_FILE, encoding="utf-8") as f:
        for i, line in enumerate(f):
            if i >= offset and json.loads(line)["event"] == "tool_call":
                called.append(json.loads(line)["tool"])
    return called

def run_agent(user_input):
    with open(TRACE_FILE, encoding="utf-8") as f:
        offset = sum(1 for _ in f)           # 记住本回合前的行数
    TOKENS["n"] = 0
    answer = agent_loop(user_input)
    return answer, tools_since(offset)

if __name__ == "__main__":
    run_evals(run_agent, "真 agent × 10 条黄金用例")
    print("本回合 token：", TOKENS["n"])    # 对照 trace 的 llm_usage 核算成本

### 5.6 五条自检

1. `trace.jsonl` 里一次任务的事件顺序正确：turn_start → (llm_call/llm_usage/

1. **开发方法换了底座**：行为正确性从"代码逻辑"移到"用例集 + 打分"——先用例、
