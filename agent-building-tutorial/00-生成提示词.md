## 使用说明

将下方提示词发给 AI，让它按阶段逐篇生成学习文档。每生成完一篇回复"继续"即可生成下一篇。

**结构**：共 21 篇，按学习曲线分成 **8 个 Part（第二层包）**。每个 Part 有明确目标，
并以一个**里程碑**（看得见的成品）收口；学到哪、离毕业还多远一眼可辨。后续生成与
复习都按 Part 走。

**学习主线**：先做出一个"能干活但有缺憾"的后台管理助手（P3 里程碑），再用
记忆/规划升级它（P4），再标准化为 MCP（P5）、多智能体化（P6）、工程化上生产（P7），
最后用 Agentic OS 视角看规模化（P8 毕业收口）。

**本提示词的产出**：一套**教学型学习文档**（先教会原理），配套**可复现的 Python 代码**。
真正的生产实现（落地到现有 Go 后台）在学完之后另开设计文档（phased design doc）进行。

**读者视角的定位**：学完整套 = 掌握实现一个可上线的 agent 所需的全部分支。
每篇开头标了它对应【知识地图】的哪个分支，方便按需跳读。

## 核心原则

1. **先概念后代码**：每个新名词先一句话大白话 + ASCII 图，再给准确定义和官方出处。
2. **每步可运行**：完整文件 + 运行命令 + 预期输出；不给"只贴关键片段"。
3. **对比优先**：直连 vs MCP、手写 vs SDK、各框架、通用 vs 推理模型、单 vs 多 agent、
   记忆方案、规划 vs 不规划，都给场景化对比表和选型建议，且给"什么时候不选它"。
4. **"直连→MCP"是学习路径**：先直连是为概念密度低、最快建立心智模型；MCP 补
   "标准化"拼图。第 15 篇必须给生产最终选型建议。
5. **设计要有"为什么"**：记忆、规划、工具、交互（打断/介入）必须从"它解决什么
   问题 / 不解决会出什么事故"讲起。
6. **工程化是分水岭**：评测、可观测、可靠性、安全、成本，每件给能落地的极简做法
   + 生产级工具指针，不许只讲理念。
7. **国内可落地**：模型层给国产替代（DeepSeek/通义/智谱 OpenAI 兼容）、私有化
   （Ollama/vLLM）、国内镜像源安装注意事项。
8. **引用权威**：MCP 官方 spec、SDK 官方文档、经典教材（Russell & Norvig）、
   CoALA 论文、Anthropic/OpenAI 官方 agent 指南；标注版本号。
9. **不堆术语**：新概念先讲"为什么需要它"，再讲它是什么。
10. **Part 内收口**：里程碑（**加粗标注**）落在 Part 内最自然的一篇；Part 的最后一篇负责收口——复验里程碑吸收本 Part 后续增量后仍可跑通，Part 与 Part 之间讲一句"下一 Part 会暴露什么问题"。

## 技术约束（2026 现状，已在线核验）

- **MCP（Model Context Protocol）**：开放协议，2025-2026 事实标准，官方规范最新
  tag `2026-07-28`。核心：tools、transport（stdio / Streamable HTTP / SSE）、
  server/client、配额与授权。
- **MCP Python SDK（MCPServer，v1 名 FastMCP）**：pip `mcp`，@mcp.tool() 声明式定义 server（v2 起 FastMCP 更名 MCPServer，旧导入路径直接 ModuleNotFoundError；2026-10-16 官方 migration 文档核验）。
- **MCP Go SDK**：官方 `github.com/modelcontextprotocol/go-sdk`
  （单一主包 `mcp`；另有 `jsonrpc` / `auth` / `oauthex`；v1.7.0+ 支持规范 2026-07-28，最新 v1.8.0——2026-10-16 官方 README 核验）。本项目目标后台是 Go，桥接用它。
- **Agent 框架（Python 生态，2026-10 实盘盘点）**：
  ① `langchain` 1.4.x——star 最多（14.8w）但是**库大 ≠ 用它直接构建 agent**：链式
  API（LCEL）在 2026 已基本退出"直接构建 agent"的路径，官方自身也转向 langgraph，
  本系列不教用它的链式抽象；② `langgraph` 1.2.x——多 agent 图编排/循环控制复杂
  场景才上；③ 厂商 SDK：`openai-agents` 0.24.x（OpenAI 兼容供应商一行切换，内置
  MCP/guardrails/handoffs）、`claude-agent-sdk` 0.2.x（内置 Claude Code 级 harness，
  但其模型绑定 Claude）；④ `pydantic-ai-slim` 2.5x——类型安全、轻、可当默认封装；
  ⑤ 会撞见的两个（不展开，一句话定位）：`LlamaIndex`（RAG/数据检索平台，Python，
     star 5.3w / PyPI 0.14.25）— 主场是"把文档变成可检索知识"，与 agent 主线弱相关，
     第 11 篇提一句；`Semantic Kernel`（微软系，.NET/C# 优先、有 Python 版，
     star 2.9w / PyPI 1.45.0）— 企业微软栈相关，与本主线弱相关；均为 2026-10-15 curl 核验。
  **本系列默认主线 = DeepSeek（OpenAI 兼容）+ 从零手写 loop（学习）→ 需要封装时
  优先 pydantic-ai / openai-agents**；langgraph 只在多智能体对比篇出现；
  claude-agent-sdk 在 P6 拆解 Claude Code 时讲其 harness 概念。
- **模型层（2026，默认供应商 = DeepSeek）**：**`deepseek-flash`（V4.1-Flash）一个模型、
  两种模式**——thinking 关（快/便宜，日常工具调用）vs thinking 开（`reasoning_effort`
  low/high/max，复杂多步/规划类任务更稳；**默认开启、默认 high**）。三条必讲的工程
  规则：带 `tools` 时历史 `reasoning_content` 必须完整回传（否则 400）、思考模式下
  `temperature` 等采样参数不生效、`top_p` 仅在思考模式生效（钳在 0.95–1.0）。OpenAI
  兼容（base_url `https://api.deepseek.com`；另有 Anthropic 格式端点 `/anthropic`，
  P2·6 提一句）。全部可运行示例默认用它，一键切换供应商只需改 base_url + key；私有化
  选 Ollama / vLLM。重型档 `deepseek-v4-pro` 仅第 20 篇路由表引入。（2026-10-16 勘误：
  旧名 `deepseek-chat` / `deepseek-reasoner` 官方已于 2026-07-24 停用，全系列已统一迁移。）
- **成熟方案是怎么做的（行业 2026 现状，全系列对照基线）**：企业把"agent + 现有
  系统"集成只有三条通用路线——① SDK 直连现有 REST：工具层包一层 HTTP client，不动
  老系统（OpenAI/Anthropic 官方指南推荐的最简做法，最快可验证）；② MCP Server 包装：
  一个 server 服务所有 agent/IDE（Claude Code / Cursor / 自研 agent），包内部服务时
  server 语言随系统语言走，本项目 Go 后台用官方 go-sdk（P5·15、P7）；③ 企业 Agent
  平台/编排层：身份/权限/成本/审计平台化，规模化后再上。教程凡涉"成熟实践"都以这三
  条为基准，第 21 篇毕业项目选型在这三条之间做最终决定（含理由）。
- **经典 AI 智能体理论（解释框架，不讲算法实现）**：simple reflex / model-based
  reflex / goal-based / utility-based / learning，映射见第 2 篇。
- **PMTA 四要素**（Planning / Memory / Tool use / Action 坐标系）：出自 CoALA
  （arXiv 2309.02427）等研究的公共框架，第 2 篇定义、全系列引用。
- **评测/可观测**：deepeval、promptfoo 可评测 agent；Langfuse / OpenTelemetry

- **harness（agent loop / agent core）**：驱动"感知→思考→行动→观察"循环的工程化

- **现有后台系统**：Go + Gin，仅健康检查，业务 REST（/api/v1，JWT，用户/角色/

## 系列结构（共 21 篇 · 8 个 Part，每篇标注覆盖分支与里程碑）

### Part 1 打开黑盒：Agent 到底是什么（第 1-2 篇，概念与理论为主；第 1 篇含一段最小验证脚本）

**目标**：让读者建立"Agent 是一套系统、不是玄学"的心智，拿到全系列的坐标系。

#### 第 1 篇：全景与学习路线地图【A1/A3/C1 + 全图导航】
- 分界线：普通聊天 → function calling/tool use → 自主 agent（什么叫"自主"）
- 一次 tool call 全流程拆解（ASCII 时序图）
- 为什么需要 agent：模型不会发起 HTTP，代码不会决定下一步——agent 是编排层
- 学习路线图：8 个 Part × 里程碑（学完能看到什么成品）、必修/选学、怎么自测
- 核心词表：LLM / Prompt / Function Calling / Tool Use / Workflow vs Agent / Harness
- 动手实践：一行 Python 触发一次 tool_use 返回，亲眼看结构化参数

#### 第 2 篇：经典智能体理论 → 现代 LLM Agent 映射【A0/PMTA 坐标系】⭐ 理论地基
- 经典分类逐个讲（一句话 + 日常类比 + 判定标准）：simple reflex（纯刺激-反应）/
  model-based reflex（有内部状态）/ goal-based（目标导向，会规划）/ utility-based
  （效用权衡）/ learning（从经验改进）
- 核心映射：reflex≈无记忆 tool call；model-based≈有状态/有记忆的循环；
  goal-based≈把目标拆计划的 agent；utility-based≈多目标权衡/守卫/评测打分；
  learning≈eval 闭环与自改进（P7·18 落实践）

### Part 4 让它更聪明：记忆与规划（第 11-12 篇，能力设计）

**目标**：给 M2 的助手升级。先用它现在"每次都忘"的痛点引出，再设计与落地。

#### 第 11 篇：记忆设计 — 三层记忆、压缩整理与存储后端【B2】⭐ 设计深度
- 从 M2 的痛点切入：助手"记不住上一轮" → 三层记忆模型：上下文字符串
  （in-context）/ 工作记忆（session）/ 长期记忆（persist）；每层的 token/成本/时效；
  多轮对话记忆的实战问题：什么该记、什么该忘、"串话"与语义漂移、回忆失败的
  业务后果
- 记忆的读写策略：写（何时把信息固化进记忆槽）、读（哪些记忆进上下文）——
  记忆设计超出"把对话塞回去"的关键
- **压缩与整理**（"为什么会忘、怎么不丢"）：近 N 轮 + 摘要的裁剪策略（单层 vs
  层级 hierarchical 摘要）；定时离线压缩任务；遗忘策略（TTL 过期 / LRU 淘汰 /
  语义去重，把"该忘的"忘掉，控制存储成本）
- **存储后端选型**（教学最小版 → 生产成熟版渐进）：短期/会话状态 → **Redis**
  （TTL 过期、并发锁、token/工具结果缓存）或 RDBMS 会话表；长期记忆 → **RDBMS
  结构化记忆表**（本项目已是 Postgres，直接复用）+ **向量库（pgvector 优先**——
  Postgres 原生扩展，与本项目同栈；Qdrant / Milvus 是独立向量库，规模化再考虑）；
  给一张"记忆类型 × 存哪 × 何时用"的选型对比表
- 最小实现链条：SQLite/JSONL（教学，重启能引用）→ Redis + Postgres/pgvector
  （本项目落地）；embedding + 向量检索最小实现（fastembed/chroma / 纯 numpy demo）
- RAG 分界线：什么时候真需要知识检索、什么时候只是记忆；典型坑（检索跑偏、
  上下文爆炸、时效）
- 动手实践：① 在最小 agent 上加"近 N 轮 + 摘要"裁剪策略，验证旧信息不丢、
  token 不涨；② 把记忆从 SQLite 换成 Redis（会话）+ Postgres/pgvector（长期），
  重启后仍能引用用户偏好，附一键起 Redis/Postgres 的方式（docker compose）

#### 第 12 篇：规划能力设计 — 复杂任务怎么被拆开、反思怎么纠正【B3/A3】⭐ 设计深度
- 从 M2 的第二个痛点切入：助手只会"一步干到底" → Planning 在 PMTA 的位置：

  计划再逐步执行）；计划的表示（怎么让模型输出"能执行"而不是"像话"）
- 计划的生命周期：计划校验、执行中重规划（工具结果推翻了计划）、回退与回滚
- 反思与验证：self-correct（结果被质疑的两种写法）、verifier（独立检查步骤）；

### Part 7 支撑上线的工程底子（第 18-20 篇，工程质量与实战）

#### 第 18 篇：开发方法、评测、可观测与自改进边界【D1/D2/D3】

- 自主学习边界：reflection → 把失败案例沉淀成测试集 → 改进 prompt → 选择性微调；

- 动手实践：配 trace 输出 + 最小评测集，跑一次 eval 出报告；把失败案例吸收进

#### 第 19 篇：多轮对话、中断与人工介入 — 工程实战问题集【C3/D5/D4】⭐ 实战汇
- 多轮对话被"打断"：用户在执行到一半插话 / 喊停 / 改需求——取消语义
  （cancellation token、中断检查点）、暂停-恢复、执行进度可见
- 人工何时介入：必须确认的操作（写/删/付费/出站/敏感数据）按风险分级表；
  介入三种方式（确认后继续 / 修正指令 / 彻底中止）
- 介入时机设计：什么时候该"停下来问"而不是闷头干错（确定性低、破坏性高、
  信息不足、多选浮现）
- 长任务问题：跑很久怎么报进度、断点续跑、超时兜底
- 其他常见问题：模型输出不稳定（参数幻觉/乱调/编结果）兜底链、上下文漂移、
  并发与限流（多用户同用）、tool 结果过大、答非所问回环检测
- 与权限系统的搭配（交互侧）：权限提示粒度与频次、放行一次 vs 永久白名单、审计对齐；身份选型（用户 token vs 专用 service account）与 RBAC 架构侧见第 20 篇
- 动手实践：实现"跑批前打断 + 写操作确认 + 中途改需求"三个场景，验证体验与日志

#### 第 20 篇：生产化、安全与既有系统治理 — 落地清单【D4/E3/E4/E5/F1】
- 可靠性：重试 / 超时 / 幂等 / 熔断 / 降级在 agent 里的对应物
- 成本控制：prompt caching、模型路由（简单任务用便宜模型）、并发与预算
- 部署形态：CLI vs Web（FastAPI+SSE 流式）vs 嵌入既有系统；各给最小骨架
- 安全专项：prompt injection（含工具返回内容注入的反制/隔离）、沙箱、密钥管理、
  数据脱敏、内容合规（对齐国内要求）
- 既有系统治理（本项目核心 F1）：agent 以什么身份访问后台；如何遵守 RBAC、
  多租户隔离（绝不跨租户，参考本项目后台 `.Where(tenant_id)` 惯例）、**会话/记忆/

  落到本项目时直接套这条）、审计留痕、操作限额
- 里程碑 M6 动手实践：套上"只读模式开关 + 租户参数注入 + 审计日志"三层壳，

## 写作规范

1. **按知识点切篇、完整性优先（最高优先）**：目标 = 把这块知识**完整弄懂**，不是
   卡在"一篇多长"。**篇幅以知识点为单位，不设每篇字数线**：
   - 复杂知识点（如记忆设计、MCP）一时讲不透 → **拆成多篇**，每篇变小、聚焦、好消化，知识点拆几篇都行；
   - 紧凑连贯、拆开会断气的知识点（如一次完整闭环演练）→ 合在一篇，篇幅偏长也没关系。
   **唯一红线：不得为凑篇幅裁剪知识点，也不得用废话凑数。**
   交稿前自查：本篇清单里每个问题都有实质内容吗？若某问题被篇幅挤掉了，正确动作是**拆篇**，不是删内容。
2. **脚手架从简（装饰性内容总占比 ≤10%）**：不要堆目录树、关键术语速查表、
   大量分隔线、重复小结等空壳。篇头给一张"本篇覆盖 N 个问题"清单（3-5 行），
   正文按问题逐个讲透；篇尾至多 3 行本篇结论。每章开头一句话说明"读完你能理解
   什么"。
3. **动手实践按需添加（只加有实质学习价值的）**：判断标准 ="不亲手做就学不会 /
   做了能验证某个设计决策"，不是篇幅配平工具。加的例子：NL2SQL 类真实任务
   （agent 自己查库完成查询）、闭环验收（跑通"一句话分配角色"）、对照实验（开/关

   图）。凡加的动手实践必须可运行、给预期输出；不加的不许硬凑。
4. **语言**：中文。术语首次出现标注英文原文，大小写与官方一致
   （MCP / MCPServer / FastMCP / agent / subagent / harness / tool use / reflex / PMTA）。
5. **代码可运行优先**：所有代码是**能直接跑的最小完整实现**，不是示意伪代码——
   文件路径、完整 import、依赖安装命令、运行命令、预期输出都齐全；代码组织成

   `<未实测，以官方文档为准>`，禁止把"想当然"描述得像跑过一样。
